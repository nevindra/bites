# Request input

**How an Input is filled from the request: wire names, presence, text decoding, the JSON codec, the body types and validation.**

**Guide:** [requests](../guide/requests.md) · **Reference:** [input](../reference/input.md)

## Overview

An Input is decoded from the request by plans built at Registration. Each field has a wire name, a kind and an offset, and every mistake of the client is collected as a located error and answered together ([errors](errors.md)). The type of a field says what is possible: a plain field is required, `Opt[T]` may be absent, a plain field named by its Section's `Defaults` method is optional on the wire and never absent in the handler (the text is decoded by the field's own decoder, at Registration to check it and again on each request that omits it), `Null[T]` may be null, and a constraint type states a bound that decoding checks and the API description repeats.

```text
Path / Query / Header / Cookie   text, decoded by the field's type          (0042)
Body                             decided by its type                         (0044)
    struct, slice, map  -> JSON via the codec on jsontext                    (0015)
    Raw[T]              -> JSON, exact bytes kept for signatures
    []byte              -> the bytes as sent
    Form[T]             -> urlencoded fields, decoded like the query
    Upload              -> multipart parts read by the handler
    BodyReader          -> the bytes as sent, read by the handler as an io.Reader
every field's name: the one naming policy                                    (0011)
absent / null: Opt[T], Null[T], never a pointer                              (0041)
after all sections decode: Validate() on the Input                           (0021)
```

All text read from the request is copied into one slab allocated for the request, and the strings of the Input point into it ([ADR 0008](../adr/0008-no-pooled-object-reaches-the-user.md)), which is how a typed JSON request stays at the allocations of [ADR 0003](../adr/0003-the-trade-budget.md).

## Rules

1. **One application-wide naming policy maps Go field names to wire names, for path, query, cookie and body alike.** It is snake_case unless the app sets another, splits a run of capitals as one word (`ItemID` is `item_id`, `UserIDs` is `user_ids`), canonicalises header fields to kebab form (a leading `X` before a capital is a word of its own, so `XAPIKey` is `X-Api-Key`, and a header's error is located by that canonical name), and refuses two fields of one struct that produce the same wire name. Names no rule produces come from a `WireNames() map[string]string` method, checked at Registration; a `json` tag wins over the policy in a body, and one on a text Section's field that names it otherwise is refused; one app has one policy. `App.WriteWireTable` prints every route's wire names from the compiled plans, for a policy only the application knows. [ADR 0011](../adr/0011-one-naming-policy-for-wire-names.md)

2. **Each Input and Output type is compiled at Registration into a plan, and JSON is read and written by a codec of our own on `encoding/json/jsontext`.** It gives wire names without tags, every error and not only the first, strings that point into the slab, and an Input that stays on the stack, none of which `encoding/json/v2` can; a type with its own JSON or text methods is delegated to v2 for that value. Only a syntax error ends decoding, nesting beyond 64 levels is refused, and the codec is fuzzed differentially against v2. A flat body (scalars only) is read first by a scanner of a strict subset, which gives up to the tokenizer on anything else, fuzzed to agree with it. [ADR 0015](../adr/0015-json-is-our-own-codec-on-jsontext.md) A type that writes its own JSON (a decimal, a database timestamp) is delegated to for that value, and is refused at Registration unless `WithJSONSchema` says what it is in the document, because it would be `{}` there otherwise; `json.RawMessage` is free-form by name. [0076](../adr/0076-a-type-that-writes-its-own-json-is-described-by-a-registration-or-refused.md)
3. **Whether a field may be absent or null is said by its type, in every section.** A plain field is required (400 `required`), `Opt[T]` may be absent, `Null[T]` may be null, `Opt[Null[T]]` is the PATCH field, and a pointer in an Input is refused at Registration because it cannot say which `nil` meant (`Opt.Ptr` and `OptOf` convert at the boundary to a service that speaks `*T`). `Opt` is a field type only, and `json:",omitempty"` does not make a request field optional. [ADR 0041](../adr/0041-presence-is-a-type.md)

4. **Text in the path, query, headers and cookies is decoded by the field's type.** Strings, bools, integers, floats, `time.Time` (RFC 3339), `uuid.UUID`, `Date`, a `TextUnmarshaler` (a type from another module is registered with `WithTextFormat`) and slices of these are allowed and anything else is refused; a slice is filled from repeated keys and never split on a comma, unless the field is a `CSV[T]`, the opt-in list in one comma-separated value for a Query or a Header; a repeated key for a non-slice field is a 400; an enum is a string type with `Values()`; `Null[T]` is refused in a text section. A `TextUnmarshaler`'s error never reaches the client as written. An unknown query key is ignored unless a route, a group or the app refuses it. An enum on output is declared in the API description and not enforced. [ADR 0042](../adr/0042-text-values-are-decoded-by-type.md)
5. **The type of `Body` decides how a body is read.** A `Submitted[T]` is a `Form[T]` whose mistakes the handler shows again as a `Page` [0078](../adr/0078-a-page-for-a-browser-is-a-page-and-a-form-it-shows-again-is-a-submitted-body.md). A struct, slice or map is JSON, and an `Opt` of one is JSON that may be absent; `Raw[T]` is JSON that keeps its bytes for signatures; `[]byte` is the bytes as sent; `Form[T]` is `application/x-www-form-urlencoded` decoded like a query, but an unknown field is a 400 because a body is the contract of a write; `Multipart[T]` is a `multipart/form-data` body decoded into a struct before the handler runs, its files in memory up to a small bound and in an unlinked temporary file beyond it, each valid only while the handler runs (a `Submitted[T]` whose `T` has a file field is read the same way); `Upload` is a multipart body read part by part by the handler. A content type the route does not accept is a 415. [ADR 0044](../adr/0044-the-body-type-decides-how-a-body-is-read.md)

6. **Memory is held for the bytes a client has sent, never for the length it declared.** The slab holds the body only when it arrived whole with the head, and otherwise the body gets a region that starts small and doubles as bytes arrive, so many connections that declare a large body and go quiet cannot multiply the allocation. [ADR 0044](../adr/0044-the-body-type-decides-how-a-body-is-read.md)
7. **A `FormFile` is valid only while the handler runs, and a `Multipart[T]` route must state `MaxBody`.** After the handler returns `Open` and every reader return `ErrUploadClosed`, in memory or on disk; a file lives in memory up to 256 KiB a request and 32 MiB for the app (judgements, not measurements) and in an unlinked temporary file past that, closed when the request ends. The other sections are decoded first and refuse before a byte of the body is read; the body is then read whole and its mistakes are one 400 located under `body.`. [ADR 0044](../adr/0044-the-body-type-decides-how-a-body-is-read.md)
7. **An `Upload` (or a `BodyReader`) and every `Part` are valid only while the handler runs, and the route must state `MaxBody`.** A late read returns `ErrUploadClosed` or `ErrPartClosed`, never another request's data; the parser is our own with limits on parts, part headers and the boundary; `FileName` is data the client sent and is never opened by the framework. [ADR 0044](../adr/0044-the-body-type-decides-how-a-body-is-read.md)

8. **Validation beyond types is a method: on a type for one value, on the Input across fields.** A named type carries its own rule: `Length() (min, max int)` on a string type, `Range() (min, max int64)` on an `int` or `int64` type and `Range() (min, max float64)` on a `float32` or `float64` type, `Items() (min, max int)` on a slice type (checked as the list is decoded, so it is also a limit), `Members() (min, max int)` on a map type (counted as the object is decoded, so it is a limit too), `Unique() bool` on a slice of strings, booleans, numbers or UUIDs (pairwise up to 16 items, a set beyond), `MultipleOf()` on an integer or float type (a float with a tolerance) and `ExclusiveMin() float64` and `ExclusiveMax() float64` on a float type (a side is stated once, by `Range` or by one of these), `Pattern() string` on a string type (a regular expression, refused at Registration if RE2 and ECMA-262 would read it differently, so the document states it as `pattern`), read once at Registration, with `Format() string` on a string type naming the document's `format` and, for `email`, `uri`, `hostname`, `ipv4`, `ipv6`, `date`, `date-time` and `uuid`, checking it (any other name stays an annotation; a rule the document states and the server does not keep is a false promise), and `Check() error` on any type, run on each decoded value with its location filled in; a method of one of those names that is not that rule is refused. `NonEmpty`, `PositiveInt` and `PositiveInt64` name the commonest bounds. All decode wherever their base type does, a bound gives a fixed sentence that never quotes the client's value, and bounds are carried into the API description for a request. `Validate` is on the Input by value, runs once after every section decoded without an error, reports `Invalid` located errors in the same 400, and is refused on a section or with a pointer receiver. Tags with a validator library were rejected as a language in a string no compiler checks, and `Bounded[R]` as two declarations for one bound; a tag another framework reads for a rule or a place (`validate`, `binding`, `query`, `minLength`, `required` and the rest) is refused at Registration rather than ignored, except a `validate` or `binding` on an Input whose `Validate` can run a validator. [ADR 0021](../adr/0021-validation-is-a-method-and-a-few-constraint-types.md)

## Decisions

| ADR | What it decides |
|---|---|
| [0011](../adr/0011-one-naming-policy-for-wire-names.md) | one naming policy per app, `WireNames` for the names it cannot produce |
| [0015](../adr/0015-json-is-our-own-codec-on-jsontext.md) | JSON is our own codec, built per type at Registration, on `jsontext` |
| [0021](../adr/0021-validation-is-a-method-and-a-few-constraint-types.md) | `Length`, `Range` (integer and float), `ExclusiveMin`, `ExclusiveMax`, `MultipleOf`, `Items`, `Unique`, `Members`, `Pattern`, `Format` (eight formats checked) and `Check` on a type, three constraint types, `Validate` on the Input |
| [0041](../adr/0041-presence-is-a-type.md) | `Opt` and `Null` say absent and null; pointers are refused |
| [0042](../adr/0042-text-values-are-decoded-by-type.md) | text sections are decoded by the field's type |
| [0044](../adr/0044-the-body-type-decides-how-a-body-is-read.md) | the body type decides how it is read: JSON, `Raw`, bytes, `Form`, `Submitted`, `Multipart`, `Upload` |
| [0078](../adr/0078-a-page-for-a-browser-is-a-page-and-a-form-it-shows-again-is-a-submitted-body.md) | a `Page` is HTML for a browser with 200 or a 4xx, and a `Submitted[T]` form hands its mistakes to the handler that shows it again |
| [0076](../adr/0076-a-type-that-writes-its-own-json-is-described-by-a-registration-or-refused.md) | a type that writes its own JSON is described by `WithJSONSchema` or refused |

## Open questions

- **`WireNames` and `Validate` locations are strings nothing checks** once a policy or tag renames a field ([ADR 0011](../adr/0011-one-naming-policy-for-wire-names.md), [ADR 0021](../adr/0021-validation-is-a-method-and-a-few-constraint-types.md)).
- **The codec is a correctness burden for the life of the project**, held by differential fuzzing; the largest single piece of milestone 1 ([ADR 0015](../adr/0015-json-is-our-own-codec-on-jsontext.md)).
- **Rules are limited where the API description is concerned.** A pattern is limited to the subset RE2 and ECMA-262 read alike (a pattern outside it is a `Check` the description cannot state), a bound costs a declared type, a float `MultipleOf` is a tolerance and not an exact test, `Unique` does not compare structs or fold case, a `Check`'s message is the application's and may quote the client's value, and nothing checks a value a handler returns ([ADR 0021](../adr/0021-validation-is-a-method-and-a-few-constraint-types.md)).
- **A model type full of pointers cannot be an Input**, so the request type is separated from the table's ([ADR 0041](../adr/0041-presence-is-a-type.md)).
- **An enum on output is advisory**, so a client generated from the description may reject a value it does not know; a `bitetest` check is a claim, not built ([ADR 0042](../adr/0042-text-values-are-decoded-by-type.md)).
- **`MaxFields` is app-wide, not per route**, and its default is low for a form with a long list ([ADR 0044](../adr/0044-the-body-type-decides-how-a-body-is-read.md)).
- **Uploads:** the rate floor of 128 KiB/s is a judgement, one deadline covers the whole body, a chunked upload is refused for size only after `MaxBody` bytes were read, and throughput and p99 of an upload are not claimed ([ADR 0044](../adr/0044-the-body-type-decides-how-a-body-is-read.md), [roadmap](../roadmap.md#nice-to-have-what-few-applications-need)).
