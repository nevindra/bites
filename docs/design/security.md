# Security

**How bites protects an API and a web application: the client's address behind proxies, security headers, auth Providers that parse and leave the verdict to the application, a token bucket per key in bounded memory, sessions sealed in cookies and changed through the return value, and CSRF that trusts the browser's word about the origin.**

**Guide:** [security](../guide/security.md), [deploying](../guide/deploying.md#behind-a-load-balancer) · **Reference:** [security](../reference/security.md), [`jwt`](../reference/jwt.md), [`WithTrustedProxies`](../reference/app.md#withtrustedproxies), [`Request.ClientAddr`](../reference/middleware.md#requestclientaddr), [`Request.PublicURL`](../reference/middleware.md#requestpublicurl)

## Overview

Every piece is a first-party middleware or Provider in the root package, built on the two mechanisms of [Middleware and Providers](./middleware-and-providers.md) and on the rules every other part keeps: nothing pooled reaches the application, the answer is the return value, a configuration that cannot work is refused when it is made, and every refusal of a request is problem+json.

```text
app.Use(RequestID, CORS, SecurityHeaders, limiter.Middleware(), CSRF)
  route matched
group Use                         a page group's own SecurityHeaders, a stricter limiter
    Providers                     BearerAuth / BasicAuth / APIKeyAuth -> User
                                  Sessions.Load -> Session[T]
                                  User's Provider calls perUser.Allow(ctx, user.ID)
      handler                     returns OK{Body, Cookies: session.Save(...)}

read by all of them:  Request.ClientAddr  Request.Scheme   (trusted proxies only)
to build links:       Request.PublicHost  Request.PublicPrefix  Request.PublicURL
                      (X-Forwarded-Host and -Prefix only from a trusted proxy the app says writes them)
```

What a client can say about itself is believed only when the app was told to believe it: a forwarding header from a listed proxy, a `Sec-Fetch-Site` or `Origin` that only a browser sets, a credential the application's own function verifies, a cookie sealed with the application's key.

## Rules

1. **No proxy is trusted unless named, and the client address is read from the right.** `WithTrustedProxies` lists networks; `Request.ClientAddr` is the peer unless the peer is listed, and then the rightmost element of `X-Forwarded-For` that is not a listed proxy. `Request.Scheme` is `https` on TLS the engine terminated or from a listed proxy that says so. Both allocate nothing. `Request.PublicHost` and `Request.PublicPrefix` read `X-Forwarded-Host` and `X-Forwarded-Prefix` only from a trusted proxy and only when `ForwardedHost` and `ForwardedPrefix` say the proxies write them, take the element the nearest proxy wrote, and answer `Host` and `""` for a value that is not a host or a clean absolute path; `PublicURL` joins them with the scheme. `Forwarded` is not read, and never mixed with `X-Forwarded-*`. A Unix socket's peer is trusted only with `UnixSockets`, and a listener with `ProxyProtocol()` takes the client from a PROXY header of a listed proxy and closes any other peer at accept. [ADR 0025](../adr/0025-no-proxy-is-trusted-by-default.md), [ADR 0058](../adr/0058-the-proxy-protocol-is-turned-on-per-listener-and-accepted-only-from-a-trusted-proxy.md)
2. **Security headers are safe for a JSON API by default, and the frame policy has one source.** `SecurityHeaders` sends a CSP that lets nothing load, `nosniff`, `no-referrer`, a `Permissions-Policy` that denies geolocation, camera and microphone, `Cross-Origin-Resource-Policy: same-site`, the frame header derived from the CSP's `frame-ancestors`, and HSTS only when the scheme is `https`; the opener and embedder policies, which break popups and cross-origin embeds, are sent only when asked for. A CSP without `frame-ancestors` is refused. [ADR 0053](../adr/0053-security-headers-are-one-middleware-with-safe-defaults.md)
3. **An auth Provider parses the credential and the application verifies it.** `BearerAuth`, `BasicAuth` and `APIKeyAuth` take the verification function and return a Provider of the application's type; missing is 401 with the scheme's challenge, malformed is 400, `ErrInvalidCredentials` is 401, any other error a 500. A JWT verifier is a verification function. No credential is logged or written in an answer. `AnyAuth` is one Provider of several credentials, the first one sent deciding and a bad one never falling through to the next; an `Opt[User]` field makes the credential optional, absent when none is sent and still a 401 for one that is not good; `CustomAuth` gives a Provider the application wrote the scheme it reads. [ADR 0054](../adr/0054-auth-providers-parse-the-credential-and-the-application-verifies-it.md), [ADR 0069](../adr/0069-the-api-document-states-what-a-routes-providers-and-middleware-ask-and-answer-and-a-route-can-be-left-out.md)
4. **A Provider's error can carry headers.** `StatusError.WithHeader` is how a 401 carries its challenge and a 429 its `Retry-After`, from a Provider that answers only with an error. [ADR 0049](../adr/0049-errors-are-found-with-errors-as-and-timeouts-wait.md)
5. **Rate limiting is a token bucket per key, in bounded memory, and per user from the user's Provider.** The default key is `ClientAddr`, an IPv6 client by its /64; the in-memory store holds at most `MaxKeys` and drops first the keys whose bucket is full again; a shared store is one method, and the Postgres one is the module `pgratelimit`, one statement a Take over one row of GCRA on the application's clock; a 429 carries `Retry-After` and the `RateLimit` headers. Middleware runs before Providers, so a limit per user is `Allow` called in the user's Provider. [ADR 0055](../adr/0055-rate-limiting-is-a-token-bucket-per-key-with-a-bounded-store.md), [ADR 0085](../adr/0085-a-postgres-rate-limit-store-is-a-module.md)
6. **A `Session` is sealed with AES-256-GCM and changed by returning the cookie `Save` gives, and a type with a `SessionOwner` method over an `OwnerSessionStore` can be revoked by owner.** `Sessions.Load` is its Provider; `Save`, `Renew` and `Clear` return a `Cookie` for the answer's `Cookies`, so nothing is written behind the handler. Keys rotate as a list, the expiry is sealed, the cookie is `__Host-`, `HttpOnly`, `Secure` and `Lax`, and a server-side store keeps a sealed id; the Postgres one is the module `pgsession`, an `OwnerSessionStore` that keeps only a hash of each id. [ADR 0056](../adr/0056-a-session-is-sealed-in-a-cookie-and-changed-by-returning-its-cookie.md), [ADR 0082](../adr/0082-a-postgres-session-store-is-a-module.md)
6a. **The origins of the app's pages are written once.** `CSRFOptions.Origins` left empty is the list of `WithAllowOrigins`, which the WebSocket routes use too; it is read when a request arrives, a list of its own is not compared with the app's, and the mistakes are refused when the middleware is given to the app. `CORS` never takes it, since it lets another origin read ([ADR 0057](../adr/0057-csrf-trusts-the-browsers-origin-and-falls-back-to-a-double-submit-token.md)).

7. **CSRF trusts `Sec-Fetch-Site` and `Origin`, and falls back to a double-submit token.** Safe methods and requests with no cookie and no Basic credentials pass, except a form posted from an unlisted origin, which is login CSRF; origins are a list compared with `Origin`, never with `Host`; a client that sends neither header must echo the token cookie in a header. [ADR 0057](../adr/0057-csrf-trusts-the-browsers-origin-and-falls-back-to-a-double-submit-token.md)
8. **A JWT is verified by a module whose key fixes the algorithm.** `modules/jwt` gives `BearerAuth` its verification function: the token's `alg` must equal the key's, so `none` and key confusion cannot pass; `exp` is required and `exp`, `nbf`, `iat` are checked on the app's clock with a 30-second leeway; keys rotate by `kid`, from a fixed set or a JWKS fetched at most once a `MinRefresh`; every failure wraps `ErrInvalidCredentials` except a key source that could not look, which is a 500. Standard library crypto only; JWKS uses `net/http` inside the module. [ADR 0062](../adr/0062-jwt-verification-is-a-module-whose-key-fixes-the-algorithm.md)
9. **The API document says what each route asks for and can refuse.** The schemes of the auth Providers a route runs are its `security`, with a 401, an `AnyAuth`'s as alternatives and an optional one with the empty requirement `{}`; a `RateLimiter`'s middleware adds a 429 and `CSRF` a 403 to state-changing methods; a Provider is recognised by its code and never called unless the framework made it. `Undocumented()` leaves a route out of the document, which hides it from the document and not from a client. [ADR 0069](../adr/0069-the-api-document-states-what-a-routes-providers-and-middleware-ask-and-answer-and-a-route-can-be-left-out.md)
10. **None of it costs the typed request an allocation.** The whole stack (request id, headers with HSTS, an address limit, CSRF and a Bearer Provider behind trusted proxies) keeps the typed POST at 2; a route with a `Session` costs 6 to read and 18 to save, named in [ADR 0003](../adr/0003-the-trade-budget.md). [ADR 0055](../adr/0055-rate-limiting-is-a-token-bucket-per-key-with-a-bounded-store.md), [ADR 0056](../adr/0056-a-session-is-sealed-in-a-cookie-and-changed-by-returning-its-cookie.md)

| [0025](../adr/0025-no-proxy-is-trusted-by-default.md) | trusted proxies by network, the client address read from the right, the scheme, the public host and prefix read only when the app says its proxies write them |
| [0058](../adr/0058-the-proxy-protocol-is-turned-on-per-listener-and-accepted-only-from-a-trusted-proxy.md) | the PROXY protocol from a listed proxy only, per listener; a Unix peer trusted only when named |
| [0049](../adr/0049-errors-are-found-with-errors-as-and-timeouts-wait.md) | a status error can carry response headers (`WithHeader`) |
| [0053](../adr/0053-security-headers-are-one-middleware-with-safe-defaults.md) | `SecurityHeaders`: safe defaults for an API, `frame-ancestors` as the one frame policy, HSTS only over HTTPS |
| [0054](../adr/0054-auth-providers-parse-the-credential-and-the-application-verifies-it.md) | `BearerAuth`, `BasicAuth`, `APIKeyAuth`: the framework parses, the application verifies, an outage is a 500; `AnyAuth` and an `Opt` field for several credentials and an optional one |
| [0055](../adr/0055-rate-limiting-is-a-token-bucket-per-key-with-a-bounded-store.md) | `RateLimiter`: GCRA per key, a bounded in-memory store, a shared store, limits per user from a Provider |
| [0056](../adr/0056-a-session-is-sealed-in-a-cookie-and-changed-by-returning-its-cookie.md) | `Session[T]`: AES-256-GCM, key rotation, sealed expiry, changed through the returned cookie, server-side stores, revoking every session of an owner |
| [0082](../adr/0082-a-postgres-session-store-is-a-module.md) | server-side sessions in Postgres as the module `pgsession`, an `OwnerSessionStore` that judges expiry on the app's clock and joins the application's transaction with `WithTx` |
| [0085](../adr/0085-a-postgres-rate-limit-store-is-a-module.md) | a rate limit store in Postgres as the module `pgratelimit`: GCRA in one upsert, the application's clock, hashed keys, an unlogged table |
| [0057](../adr/0057-csrf-trusts-the-browsers-origin-and-falls-back-to-a-double-submit-token.md) | `CSRF`: `Sec-Fetch-Site` and `Origin` first, a double-submit token for clients that send neither |
| [0062](../adr/0062-jwt-verification-is-a-module-whose-key-fixes-the-algorithm.md) | `modules/jwt`: HS256, RS256 and ES256 with the standard library, the algorithm fixed by the key, claims on the app's clock, JWKS with a refetch floor |
| [0069](../adr/0069-the-api-document-states-what-a-routes-providers-and-middleware-ask-and-answer-and-a-route-can-be-left-out.md) | the API document's `securitySchemes`, `security` and the 401, 403 and 429 found from what a route runs; `CustomAuth`, `AnyAuth` and the optional credential; `Undocumented` |

## Open questions

- **Throughput and p99** of every piece are not measured yet; they wait for the serial run of wave 2. The allocation rows are exact in `security_budget_test.go`.
- **The API document sees what the framework made and what the application said**: a Provider the application wrote is described only through `CustomAuth`, whose scheme nothing checks, and cannot have dependencies there; a `RateLimiter.Allow` inside a Provider and a verifier's 403 for a missing scope are not described; OAuth 2 flows and scopes are not a `SecurityScheme` type ([ADR 0069](../adr/0069-the-api-document-states-what-a-routes-providers-and-middleware-ask-and-answer-and-a-route-can-be-left-out.md)).
- **`AnyAuth` chooses by order, not by which credential is good**, and its alternatives provide one type; a request with none gets the first alternative's 401, with the challenges of the others the framework knows ([ADR 0069](../adr/0069-the-api-document-states-what-a-routes-providers-and-middleware-ask-and-answer-and-a-route-can-be-left-out.md)).
- **A session without a store cannot be revoked** before it expires (a session type that states an owner is refused without one, and with an `OwnerSessionStore` `RevokeOwner` ends every session of a User and `RevokeOthers` every one but the session in hand; a request already running can still save its session back, which the User Provider must refuse), and a handler that forgets to return the cookie `Save` gave changes nothing; both are stated, not solved ([ADR 0056](../adr/0056-a-session-is-sealed-in-a-cookie-and-changed-by-returning-its-cookie.md)).
- **The rate-limit headers follow an IETF draft** whose field names have changed between versions, and under a flood of new keys the random part of eviction can reset a key that was still limited ([ADR 0055](../adr/0055-rate-limiting-is-a-token-bucket-per-key-with-a-bounded-store.md)).
- **`Cross-Origin-Resource-Policy: same-site` is the default and was reasoned from the specifications, not run in a browser**; whether it surprises an app that serves public images to other sites is for a deployment to say ([ADR 0053](../adr/0053-security-headers-are-one-middleware-with-safe-defaults.md)).
- **A Unix socket peer is trusted as a whole or not at all** (`UnixSockets`): the socket's permission bits are the only list ([ADR 0058](../adr/0058-the-proxy-protocol-is-turned-on-per-listener-and-accepted-only-from-a-trusted-proxy.md)). A PROXY header that keeps the balancer as the peer (`LOCAL`, `UNKNOWN`) lets `X-Forwarded-For` be read from it.
- **The public host is the operator's word** (`ForwardedHost`): nothing checks that the proxy replaces `X-Forwarded-Host`, and an allow-list of public hosts, which would bound what a passed-through value could name, is not built. A WebSocket's same-origin check believes it too: `Origin` is compared with `Host` and with the forwarded host ([ADR 0046](../adr/0046-websocket-origins-and-inbound-limits.md)). The allow-list waits for a deployment that cannot vouch for its proxy, `X-Forwarded-Proto` is read from any trusted peer because it can only say `http` or `https`, and `Forwarded` (RFC 7239) is not read until a deployment's proxy writes it ([ADR 0025](../adr/0025-no-proxy-is-trusted-by-default.md)).
- **The JWT module** verifies HS256, RS256 and ES256 only, re-verifies every token (no cache), and checks no revocation before `exp`; whether a cache or more algorithms are needed waits for a deployment that asks ([ADR 0062](../adr/0062-jwt-verification-is-a-module-whose-key-fixes-the-algorithm.md)).
