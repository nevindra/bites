# The engine

**The HTTP/1.1 engine under the router: a goroutine per connection that is parked when idle, cancellation on disconnect, TLS and mTLS, certificate reload, several listeners and Unix sockets, panics, shutdown and readiness, strict parsing, trusted proxies and the PROXY protocol.**

**Guide:** [deploying](../guide/deploying.md) · **Reference:** [app](../reference/app.md)

## Overview

The engine is the part that accepts connections, reads requests and writes responses; everything below the router. It is written in this repository (`internal/engine`, with the parser in `internal/h1`), not borrowed from net/http, because net/http's server spends about 13 allocations a request and about 20 KB on every idle connection in its own buffers ([ADR 0005](../adr/0005-our-own-http1-engine-with-a-goroutine-per-connection.md)).

```text
accept --> goroutine per connection
              |
              |-- busy: read head -> route -> handler -> write         (buffer from a pool, returned before the wait)
              |
              |-- idle 100 ms: wait on a fresh goroutine (small stack)
              |
              `-- idle longer: parked on the poller, no goroutine
                                 bytes | hangup | idle timeout | Shutdown | Close  --> wake: one goroutine again

disconnect watcher (epoll, armed lazily) --> cancels the handler's context with ErrClientGone
```

A request, a handler and a WebSocket message always run on a goroutine of their own connection, so a handler that blocks on a database call costs a goroutine and no worker pool. What a handler sees never depends on the protocol, so HTTP/2 in milestone 4 changes no user code ([ADR 0017](../adr/0017-tls-now-http2-later.md)).

## Rules

1. **The engine is our own HTTP/1.1 server with one goroutine per connection while the connection has something to do.** For the first 100 ms of an idle wait it keeps the last request's read buffer and reads the next request straight into it, one read and one deadline change a keep-alive request, blocked under a frame of padding sized so that the collector does not halve the stack its requests grew; after that it gives the buffer back and blocks on a one-byte read, holding nothing, taking a buffer from a pool only when bytes arrive. An event loop was rejected: it is smaller per idle connection, but a handler that blocks grows its worker pool to a goroutine per blocked handler, and every event-loop library measured reuses request objects, which [ADR 0008](../adr/0008-no-pooled-object-reaches-the-user.md) refuses. [ADR 0005](../adr/0005-our-own-http1-engine-with-a-goroutine-per-connection.md)

2. **A connection idle for 100 ms is parked on the engine's poller and holds no goroutine.** Bytes, a hangup, the idle timeout, Shutdown, Close or the end of a WebSocket wake it, and exactly one goroutine owns the connection at any time. Parking is on by default on Linux for TCP and Unix socket connections ([ADR 0068](../adr/0068-one-app-serves-several-listeners-and-a-unix-socket-is-a-socket-like-tcp.md)), and `WithoutParking()` keeps every idle connection on a goroutine. Its cost is a wake for a request that finds the connection parked, accepted for the memory axis. [ADR 0005](../adr/0005-our-own-http1-engine-with-a-goroutine-per-connection.md)
3. **A handler's context is cancelled when the client goes away and when the handler returns, and its cause is `ErrClientGone`.** One watcher goroutine per engine holds an epoll instance and the descriptor is added only when someone first calls `Done()` or `AfterFunc`, so a handler that never looks pays nothing. The cause is read with the context's own `Cause()` method, because `context.Cause` cannot see it; `bites.Cause(ctx)` reads it through any derived context and compares with `bites.ErrClientGone`. When the client left and the handler set no answer or panicked, nothing is written and the connection closes ([ADR 0049](../adr/0049-errors-are-found-with-errors-as-and-timeouts-wait.md)). The context's parent is never cancellable. Off Linux the watch is a goroutine that reads one byte, and it never reads while the request's body is read from the socket: the body's own read sees the client leave, and the watch starts when the body is over. [ADR 0016](../adr/0016-the-handler-context-is-cancelled-on-disconnect.md)

4. **TLS is `crypto/tls` inside the engine and only HTTP/1.1 is negotiated for traffic.** `App.ListenTLS` and `App.ServeTLS` take a `*tls.Config`; one whose `NextProtos` holds anything but `http/1.1` and `acme-tls/1` is refused with a panic, a tls-alpn-01 challenge on `acme-tls/1` is answered by the handshake and closed quietly (with a `GetCertificate` to answer it, or it is refused), the handshake runs under its own timeout and counts against `MaxConns` from accept, and a failed handshake is a Warn only when the client rejected the operator's certificate. An idle TLS connection costs more than a plain one because of `crypto/tls`'s own state. HTTP/2 is milestone 4. [ADR 0017](../adr/0017-tls-now-http2-later.md)
5. **Client certificates are verified by the app's `tls.Config`, and only the verified chains are offered.** `ClientAuth` and `ClientCAs` decide; `Request.VerifiedChains()` gives a Provider or a middleware the chains `crypto/tls` verified, and nil for a certificate that was asked for and not verified. A config that verifies with no `ClientCAs` (which would trust every public CA) is refused. [ADR 0066](../adr/0066-client-certificates-are-verified-by-the-tls-config-and-read-as-verified-chains.md)

6. **A certificate is replaced without a restart through `Certs`.** Its `GetCertificate` reads the certificate in force with one atomic load; `Reload` and `Set` check the new one first, and a failed reload returns its error and changes nothing. [ADR 0067](../adr/0067-a-certificate-is-reloaded-through-get-certificate-and-a-failed-reload-changes-nothing.md)

7. **One app serves several listeners, and a Unix socket is served like TCP.** Each `Serve`, `ServeTLS`, `Listen`, `ListenTLS` or `ListenUnix` logs its address and feeds the one engine, so `MaxConns`, `Shutdown` and `Close` reach them all; a Unix connection parks, is watched by epoll, and has the zero peer address. [ADR 0068](../adr/0068-one-app-serves-several-listeners-and-a-unix-socket-is-a-socket-like-tcp.md)

8. **A panic in a handler, a Provider or a middleware is always recovered by the engine.** The client gets a 500 with no detail if nothing was written, the connection is closed if a stream had begun, and the panic and its stack are logged with the request. It cannot be turned off; a panic at Registration is a refusal and is not recovered. [ADR 0028](../adr/0028-panics-are-recovered-by-the-engine.md)

9. **Shutdown stops accepting, drains what is running and closes the rest when its context ends.** Idle connections close at once, requests in flight finish with `Connection: close`, every WebSocket gets a Close 1001 after its own random share of a window (1 ms a socket, at most `WithGoAwaySpread`, 3 s by default, and at most half of what is left of the context; the log line says the window used and when the context cut it), and a live stream (`SSE`, or a `Stream` declared `Live`) has its context cancelled with `ErrServerClosed` while a plain `Stream` drains. The framework installs no signal handler. A `Service` registered with `app.Service` starts after the listener is bound and before the first accept, runs `BeforeShutdown` when Shutdown starts and `Stop` after the drain, both in reverse registration order, and `Listen` returns only after the stops; `bites.Worker` and `bites.Every` build a Service for a background goroutine and for a call once per interval on the app's clock ([ADR 0079](../adr/0079-services-start-after-the-app-binds-and-stop-in-reverse-around-shutdown.md)). `WithShutdownDelay(d)` keeps the listener open for `d` with readiness failing before all this, and `WithHealth` answers a liveness and a readiness path before app middleware, readiness checking no dependency; both are built and on the [observability](observability.md) page too. [ADR 0029](../adr/0029-shutdown-drains-and-then-closes.md), [ADR 0052](../adr/0052-health-and-readiness-follow-shutdown.md)
10. **The parser refuses anything two servers could read two ways, and every refusal closes the connection.** Both `Transfer-Encoding` and `Content-Length`, a repeated `Content-Length`, a bare LF, obs-fold, a repeated `Host`, a `%` in a host and an unknown version each have an answer in the table of the ADR; the policy is that table, and the differential fuzzer only finds where net/http disagrees. [ADR 0045](../adr/0045-http1-strictness.md)

11. **No proxy is trusted unless the application names it.** The client address and scheme come from the socket, and `X-Forwarded-For`, `X-Forwarded-Proto`, `X-Real-IP` and `Forwarded` are not read from an address the application did not list. A default that trusts nothing cannot need a security fix after release, as Echo 5.4.0 did. Built in milestone 3 (security track): `WithTrustedProxies` names the networks by CIDR, `Request.ClientAddr()` takes the rightmost untrusted element of `X-Forwarded-For` (or one address from a header such as `CF-Connecting-IP`), `Request.Scheme()` reads `X-Forwarded-Proto`, a `/0` prefix is refused, and a Unix socket's peer is trusted only with `UnixSockets`. Both methods allocate nothing; their users are on the [security](security.md) page. [ADR 0025](../adr/0025-no-proxy-is-trusted-by-default.md)
12. **The PROXY protocol is per listener and only from a trusted proxy.** `ProxyProtocol()` on a serving call makes that listener read a version 1 or 2 header first; a peer outside the trusted list is closed at accept, a trusted one that sends no header or a broken one is closed with nothing written, and the client a header names becomes the peer for `RemoteAddr`, `ClientAddr` and the forwarding walk. The wait for the header is the idle wait, parked; once begun it has `HeadTimeout`, or `HandshakeTimeout` before TLS. A connection keeps its 416-byte size class, and one of such a listener carries an 80-byte wrapper. [ADR 0058](../adr/0058-the-proxy-protocol-is-turned-on-per-listener-and-accepted-only-from-a-trusted-proxy.md)

## Decisions

| ADR | What it decides |
|---|---|
| [0005](../adr/0005-our-own-http1-engine-with-a-goroutine-per-connection.md) | an engine of our own, a goroutine per connection, buffers held only during a request, idle connections parked |
| [0016](../adr/0016-the-handler-context-is-cancelled-on-disconnect.md) | the handler's context is cancelled on disconnect, noticed by one epoll watcher armed lazily |
| [0017](../adr/0017-tls-now-http2-later.md) | TLS now over `crypto/tls`, HTTP/1.1 only and `acme-tls/1` for a challenge, HTTP/2 in milestone 4, nothing protocol-specific reaches the user |
| [0066](../adr/0066-client-certificates-are-verified-by-the-tls-config-and-read-as-verified-chains.md) | mTLS through the app's `tls.Config`, `Request.VerifiedChains` offers only verified chains |
| [0067](../adr/0067-a-certificate-is-reloaded-through-get-certificate-and-a-failed-reload-changes-nothing.md) | `Certs`: a certificate swapped atomically behind `GetCertificate`, a failed reload changes nothing |
| [0068](../adr/0068-one-app-serves-several-listeners-and-a-unix-socket-is-a-socket-like-tcp.md) | several listeners on one app, Unix sockets parked and watched like TCP, no peer address |
| [0025](../adr/0025-no-proxy-is-trusted-by-default.md) | no forwarded header is trusted unless the application names the proxy; the client address is the rightmost untrusted element |
| [0058](../adr/0058-the-proxy-protocol-is-turned-on-per-listener-and-accepted-only-from-a-trusted-proxy.md) | the PROXY protocol per listener, only from a trusted proxy, its client the connection's peer; a Unix peer trusted only with `UnixSockets` |
| [0028](../adr/0028-panics-are-recovered-by-the-engine.md) | a panic is recovered by the engine and cannot be turned off |
| [0029](../adr/0029-shutdown-drains-and-then-closes.md) | Shutdown drains, sends WebSockets a jittered 1001 over a window the app can widen, cancels live streams and closes the rest, after an optional delay |
| [0052](../adr/0052-health-and-readiness-follow-shutdown.md) | liveness and readiness answered by the app, readiness failing when Shutdown starts, no dependency checked |
| [0079](../adr/0079-services-start-after-the-app-binds-and-stop-in-reverse-around-shutdown.md) | a `Service` of functions started after the bind and before the first accept, stopped in reverse after the drain; `Listen` returns after the stops; `Worker` and `Every` are its constructors for a background goroutine and for periodic work on the app's clock |
| [0045](../adr/0045-http1-strictness.md) | the HTTP/1.1 parser refuses what could be read two ways, and closes |

## Open questions

- **A client that only half-closed gets no answer** when the handler set none, where it once got a 500 with no detail ([ADR 0049](../adr/0049-errors-are-found-with-errors-as-and-timeouts-wait.md)).
- **The forwarded host and prefix and RFC 7239 `Forwarded` are not read**, and a trusted range that also holds untrusted clients lets them choose their address, by a forwarding header or a PROXY header alike ([ADR 0025](../adr/0025-no-proxy-is-trusted-by-default.md), [ADR 0058](../adr/0058-the-proxy-protocol-is-turned-on-per-listener-and-accepted-only-from-a-trusted-proxy.md)). The PROXY protocol's TLVs (an NLB's endpoint id, a TLS summary) are skipped, and a port cannot serve proxied and direct clients together.
- **The shutdown delay helps only as far as its length matches the balancer's lag**, which the application must know ([ADR 0052](../adr/0052-health-and-readiness-follow-shutdown.md)).
- **Parking's wake.** A client that sends a request every 150 ms to 1 s pays a wake on every one; a later park threshold is the change if a workload shows it ([ADR 0005](../adr/0005-our-own-http1-engine-with-a-goroutine-per-connection.md)). Shutdown's time with 20,000 parked connections is not measured.
- **TLS in milestone 3.** `acme-tls/1` is built but not yet run against a real CA, and autocert's `GetCertificate` runs under its own 5 minute context rather than the handshake deadline ([ADR 0017](../adr/0017-tls-now-http2-later.md)); client certificates are not checked for revocation and stay a connection's identity for its life ([ADR 0066](../adr/0066-client-certificates-are-verified-by-the-tls-config-and-read-as-verified-chains.md)); a reload happens only when the application calls it ([ADR 0067](../adr/0067-a-certificate-is-reloaded-through-get-certificate-and-a-failed-reload-changes-nothing.md)); TLS throughput is not measured.
- **Unix sockets** offer no peer credentials; a Unix peer is a trusted proxy only with `UnixSockets`, which trusts every peer the socket's permission bits let in, with no finer list ([ADR 0068](../adr/0068-one-app-serves-several-listeners-and-a-unix-socket-is-a-socket-like-tcp.md), [ADR 0058](../adr/0058-the-proxy-protocol-is-turned-on-per-listener-and-accepted-only-from-a-trusted-proxy.md)).
- **Disconnects it cannot catch.** A client that half-closes after sending looks like a disconnect, and behind a load balancer that reuses its connections a leaving client is never seen ([ADR 0016](../adr/0016-the-handler-context-is-cancelled-on-disconnect.md)).
- **A handler that ignores its context** holds its connection until Shutdown's context ends, and the jitter of the 1001 spreads reconnects only as far as clients behave ([ADR 0029](../adr/0029-shutdown-drains-and-then-closes.md)).
- **HTTP/2** as an engine of its own against net/http's server as a second engine is weighed when an application is served to browsers directly, since most sit behind a proxy that speaks HTTP/2 to them ([ADR 0017](../adr/0017-tls-now-http2-later.md), [roadmap](../roadmap.md#nice-to-have-what-few-applications-need)).
