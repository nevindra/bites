# Agent usability test, run 5: event ticketing

I built an in-memory event ticketing service, module `example.com/tickets`, in `docs/research/agent-usability/run-5/app/` (one binary, `cmd/tickets`, with `newApp(Config)` separate from `main`). It has an organiser HTML form with session and CSRF, a public JSON API for events and orders, a signed payment webhook, an NDJSON export, a live seat counter on a WebSocket and on an EventSource with query tickets, `otel` tracing, a hand-written `net/http` `/metrics` handler mounted with `stdhttp`, a `docsui` page, a 2 s timeout, gzip, body limits, health and readiness, and graceful shutdown. It was written by Claude Sonnet 5.5 (`claude-sonnet-5-5`) on 2026-11-04 against nilo-go commit `981ee3e` (clean tree). `go vet ./...`, `go test ./...` and `go test -race ./...` all pass: 52 tests, all with `nilotest`. Files: `go.mod`, `go.sum`, and in `cmd/tickets/`: `app.go`, `api.go`, `pages.go`, `live.go`, `webhook.go`, `metrics.go`, `store.go`, `main.go`, `tickets_test.go`. About 2,100 lines in all. I also started the binary on a real port, checked three requests, and sent SIGTERM; the process exited cleanly.

## What works, what is partial, what was given up

1. Organiser sign-in and event forms: works. `POST /login` (form), a `__Host-session` cookie (HttpOnly, Secure, renewed at login, cleared at logout), CSRF on the login and organiser posts, a wrong password gives the form again with a 401 and an error, and a signed-out organiser is sent to `/login` by a group middleware that calls `sessions.Load`. Create and edit work, with capacity 1 to 50,000 and a price. Partial: field mistakes in the event form are a problem+json 400 and not a re-rendered form (row 6).
2. Events and the public API: works. `GET /api/events` has `from` and `to` (dates) and `venue`, sorts by start time, and pages with `page` and `per_page`. `GET /api/events/{id}` sends an `ETag` and answers `If-None-Match` with a 304; it also accepts a list, a weak tag and `*`. The tag changes when seats are sold.
3. Orders: works. A fresh order gets 201. Sold out gets 409 with `seats_left` and "N seats left" in the detail. The same key and the same request gets the first order again with `Idempotent-Replayed: true` and one reservation. The same key with a different request gets 422. A non-UUID or missing key is a 400 on `header.Idempotency-Key`. A 20-goroutine race on 10 seats sells exactly 10.
4. Webhook: works. The HMAC-SHA256 is checked over `Raw.Bytes()`; a bad or missing signature is 401, a good one marks the order paid, an unknown order is 404, and re-spacing the JSON breaks the signature. Partial: the body is decoded before the signature check (row 9).
5. NDJSON export: works. It needs the session (401 without), streams one order per line as `application/x-ndjson`, and is 404 for an unknown event. Streams are not gzipped.
6. Live seat counter: works. `POST /api/live-tickets` needs the session and CSRF and gives a single-use ticket valid one minute (checked on the app's clock), bound to one event. The WebSocket at `/live/{id}` and the EventSource at `/live/{id}/events` refuse a missing, unknown, used, expired or wrong-event ticket before the upgrade or stream starts (401, or 403 for another event's ticket). Both send the current count and every sale, and nothing about another event. The span for the stream route does not contain the query string, so the ticket is not recorded. Partial: the API document lists the stream route with an `apiKeyAuth.ticket` query scheme but cannot list the WebSocket route; I stated both in `Info.Description` (row 8).
7. Tracing, metrics, docs: works. Spans are named `POST /api/events/{id}/orders` and join a caller's `traceparent`. `/metrics` is a plain `http.Handler` mounted GET-only (POST gives 405). The `docsui` page is served with exactly one CSP header, because I kept `SecurityHeaders` off its route (it sets its own policy).
8. Timeout, gzip, limits: works. The `/api` group has `Timeout(2s)`. gzip applies to a large list answer and not to a small one or without `Accept-Encoding`. A 20 KiB JSON body or a 9 KiB form is 413. A form with an unknown field, a JSON member the type lacks and a body with no `Content-Type` are 400, 400 and 415. The API group sends security headers.
9. Health and shutdown: works. `/livez` and `/readyz` are served; readiness turns 503 during the shutdown delay while liveness stays 200. `main` catches SIGINT and SIGTERM, calls `Shutdown` with a 20 s grace and waits for `Listen` to return.

Given up or left out: a login rate limiter, a real organiser store, and production trace export (`main` uses an SDK provider with no exporter).

## The five changes that would have helped most

1. Give `Bytes` (and `Text`) an optional `Status`, or add an HTML answer type that has one. Re-showing a form with 401 or 422 is the normal case for pages, and today it forces `Stream`, which costs more allocations and is never compressed (row 2).
2. Add a documented way to turn a decode or `Validate` 400 on a `Form[T]` route into a custom answer, for example a route option that receives the located errors and returns a `Response` or a page. Without it a browser user sees raw JSON for a bad field (row 6).
3. State in `security.md` that a plain HTML form (no script) can only pass `CSRF` through `Sec-Fetch-Site` or `Origin`, since it cannot send `X-CSRF-Token`. Show a form route and its `nilotest` request with `Sec-Fetch-Site: same-origin`, because test requests carry no fetch metadata and the first form test returns 403 (row 7).
4. Give WebSocket routes a structured place in the API document, for example a route option that adds an `x-websocket` entry with its security scheme, or a documented convention for the query ticket. A prose sentence in `Info.Description` is easy to forget and cannot be read by a client generator (row 8).
5. Fix the entry points for module docs: say in `guide/README.md` and `reference/otel.md` that `go doc` must run inside the module directory (row 1), and add one sentence to the `Raw` section of `requests.md` that the body is decoded before the handler runs, with a pointer to `Body []byte` for a webhook that must verify first (row 9).

## What worked well

- Refusals say what to do. The empty group prefix refusal in `reference/app.md` names `nilogo.Options`, and `routing.md` even shows my exact `Use(headers, csrf)` bundle. The CSRF 403 says what was missing.
- The 400 for a bad query, header or path names the location (`query.from`, `header.Idempotency-Key`, `path.id`, `body.capacity`, `body.vip`) with no code from me, and it lists every error at once.
- One Input struct gave me the route, the decoding, the UUID header with `format: uuid`, the `Defaults`, and the OpenAPI parameters. The generated document also states the cookie and query-ticket schemes on the right routes, plus 401, 403, 413, 415 and 304 where I would have forgotten them.
- The guide's examples compile as written. `CustomAuth` with `In: "query"`, `OneOf2` with `NotModified`, `Raw` for a webhook, `Events`, and `Topic` were copied and adapted with no surprises.
- `nilotest` covers nearly everything without a port: `Do`, the fake `Clock` for the 2 s timeout, the ticket's minute and the shutdown delay, `DialWS` and `TryDialWS` for a refused upgrade, `OpenEvents`, and `WaitEnded` before reading spans.
- `Sessions`, `CSRF`, `SecurityHeaders`, `Timeout`, `WithGzip`, `WithLimits` and `WithHealth` need one line each, and their defaults were safe: limits on, the strict `__Host-` cookie, CSP `default-src 'none'`.
- The pre-computed `ETag`, 304 and `Created` header shapes, and `With("seats_left", n)` on a `Conflict`, made the 409 problem body trivial.

## Review against the source

Checked by the session that ran the test, on 2026-11-04, at 981ee3e. Row 1: each module under `modules/` has its own `go.mod` (ADR 0070), so `go doc ./modules/otel` from the root fails as quoted; no guide or reference page says where to run it. Row 2: `Bytes` and `Text` have no status (`output.go`), only `Redirect` and `Stream` carry one, and an error status comes only from the returned error, which is always problem+json (ADR 0012, ADR 0013); an HTML page with 401 or 422 is therefore reachable only through `Stream`, so the gap is real and is a design question against ADR 0012. Row 6: `WithErrorMapper` is asked only for an error with no `*StatusError` in its chain (`problem.go`), so the framework's own 400 of a `Form[T]` never reaches it; the gap is real and is the same question as row 2. Row 7: `CSRF` reads its token only from the `Header` (`X-CSRF-Token` by default, `csrf.go`), never from a form field, so a form without script passes only by `Sec-Fetch-Site` or `Origin`, which every current browser sends on a POST; `security.md` does not say so, and a `nilotest` request carries neither, so the doc gap is real. Row 8: WebSocket routes are left out of `paths` by ADR 0020, since OpenAPI 3.1 cannot describe an upgrade; the ticket a query-reading Provider states (ADR 0069, built after run 4) therefore reaches the document only on the event-stream route. Row 9: the body is decoded before the handler, as for any Input, and `requests.md` does not say so next to `Raw`; the decode runs after the Providers, so a Provider that checks the signature would have to read the body, which a Provider cannot. Row 3 is the refusal of run 3 working as intended; rows 4 and 5 are the agent's own. The agent's read of `docs/research/agent-usability/app/go.mod` is noted in its caveats and touched nothing it wrote. The app's 52 tests pass with and without `-race`.
