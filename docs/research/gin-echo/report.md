No release in the ~8 months since, although master was pushed 2026-10-10 ("docs: include HTTP QUERY method", #4879) [gh api]. 19 commits since 2026-07-31, and all 19 PRs merged in that window were merged by one person, appleboy [gh pr list]. Open: 607 issues and 212 PRs [gh issue list / pr list]. #3824 "What's the status of Gin?" **Foundation.** [code] net/http `Engine.ServeHTTP` (gin.go:662). h2c via `UseH2C` flag + `Engine.Handler()` wraps in `h2c.NewHandler` (gin.go:169,243-249). HTTP/3: `RunQUIC` imports quic-go into gin.go itself (gin.go:20,627-639), so every Gin build links quic-go [probe: `go list -deps` of a hello program lists quic-go, 19 packages].
**Handler.** [code] `type HandlerFunc func(*Context)` (gin.go:51), no error return. `*Context` is a concrete struct. Errors are `c.Error(err)` collected in `c.Errors`.
**context.Context.** [code] `*Context` has Deadline/Done/Err/Value, but they delegate to `Request.Context()` only if `Engine.ContextWithFallback` is true (context.go:1434-1438); `New()` does not set it (gin.go:206-232), so the default is false. Without it Deadline returns no-deadline and Value only answers Gin's own keys and `c.Keys` (context.go:1467-1483). Note `Value(string)` looks in `c.Keys` first, a key-space shared with user data.
**Pooling.** [code] `sync.Pool`; `ServeHTTP` does Get, reset, handle, Put (gin.go:667-674). `c.Copy()` exists for goroutines (context.go:122). [probe gin3] Three sequential requests `/p/first|second|third`, each handler spawning a goroutine that sleeps 200ms then reads `c.Param("x")` and `c.Request.URL.Path`: goroutines of "first" and "second" read `Param="third" Path="/p/third"`. Silent cross-request data. `-race` run printed no race report in my run.
**Binding.** [code] `Bind*`/`MustBindWith` call `AbortWithError(400,...)` (context.go:810-825), 413 only for `http.MaxBytesError`; `ShouldBind*` just returns the error. Validator is go-playground/validator via `binding:"..."` tags (binding/default_validator.go). [probe gin/gin2] `ShouldBindUri` into `int` with "abc": handler-chosen body, error text `strconv.ParseInt: parsing "abc": invalid syntax` (no field name). Malformed JSON: `unexpected EOF`; type mismatch: `json: cannot unmarshal string into Go struct field J.age of type int` (this one names field); missing required: `Key: 'J.Name' Error:Field validation for 'Name' failed on the 'required' tag`. All are raw library strings; format is up to the handler.
**Bind fails, then handler calls c.JSON(500, ..)** [probe gin2, real loopback server]: client gets status **400** with the handler's 500-body `{"after":"bind failed"}` and Content-Type `text/plain; charset=utf-8` (header was committed by the abort before the JSON render set it). Log: `[GIN-debug] [WARNING] Headers were already written. Wanted to override status code 400 with 500`, **only in debug mode**; in release mode (gin probe, first run) nothing is logged. `c.Errors` holds the bind error and the Logger middleware prints it [probe].
**Write twice / header late.** [probe gin2] `c.JSON(200,a); c.JSON(201,b)` -> 200, body `{"a":1}{"b":2}` (invalid JSON document), warning only in debug mode. `c.String(200); c.Header("X-Late")` -> header silently dropped, **no log at all**. `c.String(200); c.Status(404)` -> client sees 200, debug warning.
**Abort.** [probe gin] After `c.Abort()` the rest of the handler still ran ("code after Abort() ran", `IsAborted=true`) and its `c.String` wrote; the next handler in the chain did not run. `AbortWithStatus(401)` then `c.String(200,"x")`: status 401, body "x" written anyway.
**Errors.** [probe] `c.Error(boom)` followed by `c.String(200)`: client sees 200 "fine"; the only reader by default is the Logger middleware, which printed `Error #01: boom` (logger.go:302). Without Logger nothing reads `c.Errors`.
**OpenAPI.** [code] No first-party OpenAPI (grep of repo). Common route: swaggo/swag + gin-swagger, which generate Swagger 2.0 from "declarative comments" [docs: swaggo/swag README]; swag last pushed 2026-09-30, gin-swagger 2026-07-10 [gh api]. Comments, not types.
**Global state.** [code] `GIN_MODE` env read in `init()` (mode.go:50-53); `gin.SetMode` is a package global (atomic); default mode is debug, which prints routes and a warning banner [probe output]. Under `go test` it defaults to test mode (mode.go:59-61). Also package vars `DefaultWriter`, `DefaultErrorWriter` (mode.go:42,45), `binding.Validator` (binding.go:72). Debug warnings are the only diagnostics for the double-write cases, so release mode hides them.

## Mistakes a new framework should not repeat
1. Handlers without an error return plus ambient `c.Error` (Gin): the error is read by whoever happens to install Logger [probe]. Echo's returned error is better, but returning nil after a failed write gives an empty 200 [#3025].
2. Writing twice is permitted, produces invalid bodies (`{"a":1}{"b":2}`) and Gin reports it only in debug mode [probe]. Single write from the returned value removes this class. Late headers/status are silently dropped in both [probe].
3. `Bind*` that commits a 400 itself, then lets the handler keep writing: client got 400 with a 500-shaped body and wrong content type [probe gin2].
4. Pooled Context visible to goroutines: both silently serve another request's data [probe]; Gin's fix is a manual `Copy()`; Echo has none. Hand the handler values, not a recycled object. BodyDump bug #3173 shows pooling leaking through middleware too.
5. Context that half-implements context.Context: Gin's `ContextWithFallback` is off by default so Done/Deadline do nothing [code]; Echo drops the interface entirely [code]. Cancellation must just work.
6. Binding errors as raw library strings: Gin gives `strconv.ParseInt...` with no field name; Echo's default hides detail to a bare "Bad Request" [probe]. Neither names the field uniformly. nilo's field-naming 400 is an advantage.
7. Package-level mutable mode/env (`GIN_MODE`, `SetMode`, `binding.Validator`, `DefaultWriter`) and debug-vs-release behaviour differences [code].
8. Pulling every codec into the default build (Gin links quic-go, mongo-driver, protobuf, toml, yaml, ugorji for hello world [probe]).
9. Single-maintainer risk and stalled releases (Gin #3824, one merger, no release in 8 months; Echo largely one author).
10. Breaking major plus rapid security churn: Echo v5 asked users to wait 2.5 months for stabilisation and 5.4.0 changed forwarded-header trust [release notes]. Defaults on proxy headers are a security surface.
11. OpenAPI left to comment annotations (swaggo) that drift from types [docs]; Echo's generics-based helpers (`PathParam[T]`) are only partial type-driven input.

## Things worth copying
- Echo: returned `error` plus one central `HTTPErrorHandler`; unknown errors become a generic 500 without leaking message by default [probe]; opt-in `exposeError` [code echo.go:463].
- Echo: `Committed` flag on the response and a log line when written twice, in all modes [code response.go:51].
- Echo: per-instance logger on `slog`, almost no global state, 2 real dependencies [code].
- Echo: `QueryParam[T]` generic typed extraction [code binder_generic.go]; #3066 shows demand for methods.
- Gin: `http.MaxBytesError` -> 413 distinction in binding [code context.go:810-825]; `UseH2C` as opt-in; explicit trusted-proxy config.
- Both: plain net/http `Handler`, so httptest works with no ceremony [probe].
