# bites v0.1.0

**The first release of bites: what it holds, what it does not promise, and the runs behind its numbers.** Its numbers are the runs already written down; the release run on the bench machine waits for a later release (see [The numbers](#the-numbers)).

## What v0.1.0 is

The first tagged release, prepared as [the roadmap](../roadmap.md#the-first-tag) orders it: what a team needs to put bites in front of real users without a second framework beside it. It is a v0.x release under [ADR 0034](../adr/0034-versioning-before-1-0.md): before 1.0 the Go API and the wire behaviour may change in any release, and each release after this one lists such changes on its page with what to change.

## What it holds

These are not promises of stability; they are what the release is tested to do, each held by a test or a refusal ([ADR 0033](../adr/0033-the-rules-are-build-steps.md)).

- **Mistakes in a handler's types are refused at Registration**, before the first request, each with an exact message naming the route, the field and where it was registered ([ADR 0007](../adr/0007-mistakes-are-refused-at-registration.md)).
- **A typed JSON request costs 2 allocations**, 3 when its context's done channel is used ([ADR 0003](../adr/0003-the-trade-budget.md)).
- **Nothing pooled reaches user code** ([ADR 0008](../adr/0008-no-pooled-object-reaches-the-user.md)), and the response comes only from the handler's return value ([ADR 0009](../adr/0009-the-response-comes-only-from-the-return-value.md)).
- **Every error answer is problem+json** with wire names ([ADR 0012](../adr/0012-client-errors-are-400-problem-json.md)).
- **The core imports the standard library only**; the optional features are modules with their own `go.mod` ([ADR 0006](../adr/0006-no-third-party-dependency-in-the-core.md), [ADR 0070](../adr/0070-optional-features-are-modules-under-modules-each-with-its-own-go-mod.md)).

## What is in it

Milestones 1 to 3 as the [README](../../README.md) and the [roadmap](../roadmap.md) list them: the HTTP/1.1 engine with idle connections parked on epoll, typed routes and the JSON codec, problem+json, responses by return type, files with conditional and Range requests and static serving, streaming and server-sent events, groups, middleware and Providers, the first-party middleware, Observers with the access log, Prometheus metrics, W3C trace context and OpenTelemetry, health and readiness, WebSockets, the OpenAPI 3.1 document with an `operationId` for every operation and the security schemes of every auth Provider (including one the application wrote, several credentials on one route, and an optional one), TLS with mTLS, certificate reload and `acme-tls/1`, Unix sockets and several listeners, trusted proxies with the public host and prefix they forward, and the PROXY protocol, sessions, CSRF, rate limiting, security headers with `Permissions-Policy` and the cross-origin policies, the auth Providers and JWT, compression with gzip in the core and zstd and brotli as modules, `bitetest`, `stdhttp`, the API documentation UI, `bites-doc` and `bites-site`.

The modules are tagged after the core, each with its own version, as [ADR 0070](../adr/0070-optional-features-are-modules-under-modules-each-with-its-own-go-mod.md) says: `modules/jwt`, `modules/otel`, `modules/zstd`, `modules/brotli` and `modules/docsui`.

## What it does not promise

- **No stability of the Go API or of the wire** before 1.0 ([ADR 0034](../adr/0034-versioning-before-1-0.md)).
- **No HTTP/2**: bites speaks HTTP/1.1, and is meant to sit behind a proxy that speaks HTTP/2 to clients until milestone 4 ([ADR 0017](../adr/0017-tls-now-http2-later.md)).
- **No WebSocket compression** (permessage-deflate), milestone 4 ([ADR 0040](../adr/0040-no-permessage-deflate-for-now.md)).
- **No multipart/byteranges**: a request for several ranges of a file is answered whole ([ADR 0064](../adr/0064-a-file-answers-its-own-conditional-and-range-requests.md)).
- **No OAuth 2 flows or scopes in the API document**: an access token is described as a Bearer token ([ADR 0069](../adr/0069-the-api-document-states-what-a-routes-providers-and-middleware-ask-and-answer-and-a-route-can-be-left-out.md)).
- **Not built yet, waiting for a deployment that asks:** a cache of verified JWTs and the PS256 and EdDSA algorithms, an allow-list of public hosts and the `Forwarded` header ([ADR 0025](../adr/0025-no-proxy-is-trusted-by-default.md)), OpenTelemetry HTTP metrics beside the Prometheus Observer, an Observer of WebSockets, and restarting a trace at an internet-facing edge.
- **The engine's own optimisations after step 17** (fewer deadline arms, one read a request fewer, a smaller idle connection) are left for a later release, with the evidence in [`docs/research/hotpath-mac`](../research/hotpath-mac/report.md) and [`docs/research/profile-fib`](../research/profile-fib/report.md).
- **No Autobahn conformance run**: the WebSocket framing, close and UTF-8 rules are tested by the repository's own tests and fuzzed, but the Autobahn suite echoes arbitrary text, which a typed socket does not send ([roadmap](../roadmap.md), milestone 2, step 12).
- **The documentation site is not published**: the documentation is read as Markdown in the repository, and `bites-site` renders it for anyone who wants it as HTML.

## The numbers

The release run on the bench machine (`bench/release.sh`) was not made for v0.1.0: the machine was out of reach, and the release does not wait for it (decided 2026-11-02). So this release states no new figure over a real socket, and every number it can point to is a run already written down, with its machine and commit:

- **Allocations a request** are held by tests rather than quoted: 2 for a typed JSON request, 3 when its context's done channel is used, asserted over the in-memory connections on every `go test` run (`budget_test.go`, `security_budget_test.go`).
- **Throughput, CPU a request, latency and memory per idle connection** are milestone 1's run beside net/http, Huma and nilo ([`bench/result/milestone1.md`](../../bench/result/milestone1.md)) and the run beside fib ([`bench/result/fib.md`](../../bench/result/fib.md)), both on the Ryzen 7 9700X before milestones 2 and 3. They say what the engine was then, not what this release is.
- **Step 17's pass** is 18.6% less time at the geometric mean of the hot paths, over memory on a Mac at one P, against `b2b8576` ([`docs/research/hotpath-mac`](../research/hotpath-mac/report.md)); what it is worth over TCP is not measured.

The release run is ready for the next release with the machine: one command, `cd bench && ulimit -n 524288 && ./release.sh` ([`bench/README.md`](../../bench/README.md#the-release-run)).
