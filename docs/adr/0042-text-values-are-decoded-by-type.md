# Text in the path, query, headers and cookies is decoded by the field's type

A field in `Path`, `Query`, `Header` or `Cookie` may be: a string; a bool; a signed or unsigned integer; a float; a `time.Time`, read as RFC 3339 with its offset; a `uuid.UUID` from the standard library (the Go 1.27 package `uuid`, imported as `"uuid"`; a uuid type from a module is a registered text type, below); a `Date`; any type implementing `encoding.TextUnmarshaler`; or a slice of one of these. Anything else is refused at Registration, including nested structs and maps in a query.

- **A slice is filled from repeated keys**, `?tag=a&tag=b`. A comma is not a separator, because values contain commas.
- **`CSV[T]` is the opt-in comma-separated list**, for an API that already sends `?stage=won,lost` (OpenAPI `style: form`, `explode: false`). It is `type CSV[T any] []T`, a plain slice to the handler (range, `len`, index, and a conversion to `[]T`), and it is read in `Query` and `Header` only. One value is split at its commas, and each element is decoded with `T`'s own text decoding and rules (`Length`, `Range`, `Pattern`, `Values`, `Check`, `uuid.UUID`, an integer). `?stage=` is an empty list; an absent key is a 400 `required` unless the field is `Opt[CSV[T]]`; an empty element (`a,,b`, a trailing comma) is decoded as the empty string, so a `NonEmpty` element refuses it with its own message and nothing is dropped. There is one wire form per field: `?stage=won&stage=lost` is a 400 `sent more than once`, as for any field that is not a repeated-key slice. A bad element is located as `query.stage[1]` with its rule. There is no escaping, so **an element cannot contain a comma**; that is the price of choosing `CSV` over a repeated key, and the reason it is a type to choose and not the default. In a `Header` the elements are trimmed of spaces around the commas, as HTTP's list syntax allows; a repeated header line is the same 400, not a concatenation, because the header code does not join lines. Since `Header` does not split on commas by itself, `CSV` there is not redundant: a plain `[]T` reads one element per header line. The API description states `type: array` with the element's schema, and for a query `style: form`, `explode: false`; for a header `style: simple`.
- **A bound on a `CSV` is an `Items` method on a named type that says it is a `CSV` again**: `type Stages bites.CSV[Stage]` does not inherit `CommaSeparated`, so it declares `func (Stages) CommaSeparated() {}` beside `Items() (min, max int)`. The commas are counted before the list is allocated, and a failure is the `items` rule at the field. Without the marker the named type is a plain slice, filled from repeated keys, which is what a named slice type was before `CSV`.
- **`CSV` is refused where a comma list means nothing**, at Registration: in `Path`, `Cookie` and `Form` (a Form field is a repeated key), and in a JSON `Body`, where a list is an array and the message says `use []T`. A `CSV` of `Opt` is refused as a list of `Opt` is, and a `CSV` of a slice as a slice of a slice is.
- **A repeated key for a field that is not a slice is a 400**, never first-wins or last-wins: an ambiguous request is refused, which also closes HTTP parameter pollution. The same holds for a repeated header.
- **An enum** is a named string type with a `Values()` method; Registration calls it once, decoding refuses anything not listed, and the API description lists the values. The same device, a method on the field's own named type read at Registration, carries a length (`Length`), an integer range (`Range`) and a per-value check (`Check`) since 2026-11-02 ([ADR 0021](0021-validation-is-a-method-and-a-few-constraint-types.md)).
- **A bool** is `true`, `false`, `1` or `0`. An empty value for a number (`?page=`) is a 400, not zero.
- **A date with no time or offset** (`2026-01-01`) is a 400 for a `time.Time`; a civil date is a `Date`.
- **`Date` is the calendar date**, a built-in type read from `YYYY-MM-DD` in every section and in a JSON body, written the same way, and described as `type: string, format: date`. Anything else is the one sentence `expected a date as YYYY-MM-DD`, with the rule `type`: a timestamp, a day that does not exist (`2026-02-30`), a year outside 1 to 9999, a missing zero. The sentence never contains the client's value. A `Date` is an integer (the days since 0001-01-01, so the zero `Date` is that day, as the zero `time.Time` is), decoded where it lies, and costs no allocation in any section (`TestATypedJSONPOSTWithADateInPathQueryBodyAndAnswerStillAllocatesTwice`). **It has no `Time` method**, because a date has no instant: turning one into a `time.Time` means choosing a zone, and UTC midnight against local midnight differs by a day across zones, so the choice is written at the call, `d.In(loc)`. **Arithmetic is in days only** (decided 2026-11-03): `AddDays(n)` and `Sub(u)` are integer operations on the stored count and cost nothing, and they are what a due date needs (thirty days of terms, how many days late). `AddDays` returns `ErrInvalidDate` for a result outside 1 to 9999 rather than panicking, because `n` may come from a client, and rather than wrapping, because a date `YYYY-MM-DD` cannot write would fail only when it is encoded. `AddMonths` and `AddYears` are left out on purpose: the 31st of January plus a month has no single answer, so that arithmetic goes through `In` and `time.Time.AddDate`, where the normalisation is visible. It offers `Year`, `Month`, `Day`, `AddDays`, `Sub`, `Before`, `After`, `Equal`, `Compare`, `IsZero`, `String`, `MarshalText`, `UnmarshalText`, and the constructors `NewDate` (which refuses a day that does not exist and normalises nothing), `DateOf` (the calendar day of a `time.Time` in its own location) and `ParseDate`. Its errors are one value, `ErrInvalidDate`, with fixed text, so a `Check` may send it to a client.
- **`WithTextFormat[T](format)` registers a type from another module as text.** The core imports the standard library only ([ADR 0006](0006-no-third-party-dependency-in-the-core.md)), so `github.com/google/uuid`'s type cannot be named here, and a `Format` method (the way a type of the application's own gets a format, [ADR 0021](0021-validation-is-a-method-and-a-few-constraint-types.md)) cannot be added to it. The option is the app's statement that `T` has a text form: `*T` must implement `UnmarshalText` and `T` or `*T` `MarshalText`, or `New` panics naming the line. A registered type is then read from every text section and from a JSON body with its own `UnmarshalText`, written with its own `MarshalText`, and described as `type: string` with the format given. A value that does not decode is told the format's sentence: `expected a UUID` for `uuid`, `expected a date as YYYY-MM-DD` for `date`, `expected a valid <format>` for any other, where an unregistered `TextUnmarshaler` still says `expected a valid value`. A type the core already knows (`time.Time`, `uuid.UUID`, `Date`) cannot be registered, and one type cannot have two formats. It costs what a `TextUnmarshaler` costs, two allocations in a text section, and one more reflected value in a JSON body, which is why it is the way for a type the core cannot name and not the way to spell a `uuid`. **An unregistered uuid of another package is named at start** (decided 2026-11-04, from an application whose `github.com/google/uuid` path parameter answered `expected a valid value` and was a plain string in its document, which it learned from the docs alone): a text field whose type is named `UUID` in a package whose path holds `uuid`, and that has no registration, is logged once per type at Info with the first field that has it and the `WithTextFormat` call written out. A log line and not a refusal, because the type works and an application may want the plain sentence; not a format guessed from the name, because a guess is the framework doing what the code did not say.
- **An unknown query key is ignored by default, and a route, a group or the app may refuse it.** A misspelled filter (`?knid=government`) otherwise returns every row and looks exactly like a filter that worked. `RejectUnknownQueryKeys()` (a route option, so also on a `Group`), `AcceptUnknownQueryKeys()` (its undoing, innermost wins) and `WithRejectUnknownQueryKeys()` (the app's default) make each such key a 400 at `query.<key>` with the sentence `unknown query parameter`, listed with the other errors, once however many times the key is repeated. The sentence goes on to say what the route accepts, in the message and not in a new member of the entry (a client that shows `message` shows it, and the entry keeps the shape of every other error, ADR 0012): `; did you mean "user_access_id"?` when a declared key is near, then `; this route takes a, b, c` listing the declared keys in field order (the first eight, then `, and N more`), or `; this route takes no query parameters` for a route with no `Query` section. A key is near when it differs from a declared one only in case, `_` and `-` (userAccessId, user-access-id), or by an edit distance of one (two for a name of eight bytes or more, three for sixteen or more) with a swap of two neighbours counting as one, so `knid` names `kind` and `account_id` names nothing and the list is what helps. Without it, a client that sends `account_id` to a route that wants `user_access_id` has to read the document to find out. The names written are the route's own declared names, and the route's `Use` middleware has run before the query is decoded, so a client that sign-in refuses (a 401) never sees them; a route with no sign-in publishes the same names in its API document. The distance is computed on the error path only and the check itself is unchanged, a failed lookup that allocates nothing. Only the key's name is echoed, cut to 64 bytes as an unknown `Form` field's is ([ADR 0012](0012-client-errors-are-400-problem-json.md)); the value never is. A route with no `Query` section takes no query when the switch is on. `Header` and `Cookie` are not covered: a request carries headers and cookies nobody on the route chose. The default stays lenient because a proxy, a link shortener or an analytics tag adds parameters to URLs the API did not ask for, and a framework that refuses them by default breaks working clients. The check is a failed lookup in the section's names and costs no allocation (`TestATypedJSONPOSTOnARouteThatRejectsUnknownQueryKeysStillAllocatesTwice`).

`+` in a query means a space, as form encoding says; in a path it is a plus sign.

- **`Null[T]` in a text section is refused at Registration**: text has no null, so the type would promise a state no request can produce. `Opt[T]` is the way to say a text value may be missing.
- **`uuid.UUID` accepts what the standard library's `UnmarshalText` accepts**: the hyphenated form, 32 hex digits, braces and the `urn:uuid:` prefix. It is always written hyphenated.
- **A `time.Time` keeps the offset it was sent with.**
- **A `TextUnmarshaler` costs two allocations**: its argument is a `[]byte` the method may keep or modify, so the slab's bytes are copied for it, and the method runs on a fresh value that is then copied over the field, because the Input lives on a stack the compiler was told nothing escapes from, and a method that kept its receiver would point into it. The built-in types above cost none.
- **A `TextUnmarshaler` error never reaches the client as written**: it may quote the input, so the client gets "expected a valid value", or the sentence of the format when the type is registered with `WithTextFormat`.
- **What was rejected for `?ids=1,2,3`: a type of its own with `UnmarshalText`.** It was the advice until 2026-11-02. It fails an existing client twice: its error is only "expected a valid value", with no element and no rule, and the API description says `string`, not an array. `CSV[T]` replaces it; the default of a plain slice does not change, because a comma in a value is common and a split that cannot be escaped must be chosen, field by field.
- **`CSV` costs what a repeated-key list costs.** The commas are counted, the backing array is made once, and the elements are cut from the request's text without a `[]string`: a `CSV[int]` of 3 elements allocates 3 a request (the slab, the context, the array), as three repeated keys do, and an empty one allocates 2 (`TestACSVOfThreeElementsCostsWhatThreeRepeatedKeysCost`).

- **What was rejected: a civil date left to the application, and the advice to write a `Date` type of your own.** That was the rule until 2026-11-03. Every application wrote the same nine-line type (`UnmarshalText`, `MarshalText`, a `Format` method), and one that swallows the parse error turns a mistyped date into the zero date; `format: date` is in nearly every API, so the type is built in and its error is fixed.
- **What was rejected: a `uuid.UUID` from a third-party module as a first-class type.** It was a `TextUnmarshaler`, which decoded but said `expected a valid value` in a path and was described as a bare `string`, with nothing at Registration saying so. The core cannot import the module (ADR 0006) and cannot guess which uuid package the application means, so the registration is the application's.

**An enum on output is declared, not enforced.** The API description lists the `Values()` of an enum in a response, and the encoder does not check that the value written is one of them. Decoding refuses an unlisted value because the client sent it; encoding does not, because a database row can hold a value the Go type does not list (an old row after a deploy, a migration in progress), and a check would turn that drift into a 500 for the whole response, for a field the client may not even use. The cost of checking was not the reason: on top of the 5.3 ns `AppendQuote` of a string, a linear scan costs +2.7 ns for 3 values, +5.6 ns for 8 and +6.9 ns for 32, a map +3.9 ns at 32, with no allocation; 20 enum fields pay 50 to 140 ns, about 1 to 3% of a request's CPU (claim for the share). A `bitetest` helper that checks a response value against `Values()` is the middle path (claim, not built). Evidence: [`docs/research/decisions-bodies/`](../research/decisions-bodies/report.md), section "Enum on output". **What it fails at:** a client generated from the description that rejects a value it does not know, the usual open-enum hazard.
