# Static files are a route with precompressed twins, a cache rule by name, and a fallback that never hides an API 404

`App.Static(prefix, Static{...})` and `Group.Static` register one route, `GET prefix/{path...}` (and its HEAD), that answers the files of an `os.Root`, an `fs.FS` or an `embed.FS` as `File` answers them ([ADR 0043](0043-cookies-and-bodies-other-than-json.md), [ADR 0064](0064-a-file-answers-its-own-conditional-and-range-requests.md)): `Content-Length`, the validators, 304, 412, one `Range`. Built 2026-11-01, milestone 3, track C, in `static.go`.

**It is a route.** A more specific route of the app wins over it by the router's rules ([ADR 0018](0018-the-router-follows-servemux-rules.md)), it runs the app's middleware and those of its group and its own `Use` ([ADR 0048](0048-groups-and-the-order-things-run-in.md)), and two statics on one prefix, or a static over a route's pattern, conflict at Registration. It is left out of the API document: OpenAPI has no good way to say "any file under here", and an operation per file would describe the build, not the API. `Summary`, `Description` and `Returns` on it are refused; `Tag` is accepted and ignored, as on a WebSocket route.

**Names.** The rest of the path is percent-decoded into the request's slab ([ADR 0008](0008-no-pooled-object-reaches-the-user.md)) and checked with `fs.ValidPath`; the router has already refused `..`, `.` and `//` as raw segments with 400 ([ADR 0018](0018-the-router-follows-servemux-rules.md)), so `%2e%2e/` decoded is the only way to spell them here, and it fails `fs.ValidPath`. An `os.Root` refuses a symbolic link out in the call itself. A name that is missing, not a regular file, invalid or refused is the same 404 problem+json as `File`'s. A path that ends in a slash, the bare prefix included, is answered with `Index` (`index.html` by default, a plain name); a directory named without its slash is a 404, never a redirect (ADR 0018 has no automatic redirects). No directory is ever listed.

**Precompressed twins.** For `app.js`, an `app.js.br`, `app.js.zst` or `app.js.gz` beside it is answered instead, with `Content-Encoding` and the type of `app.js`, when the client's `Accept-Encoding` accepts it. The choice reads RFC 9110 weights to the thousandth: the highest weight among the twins that exist wins, br then zstd then gzip on a tie; a coding not listed takes the weight of `*`; a client that lists `identity` above every coding gets the file itself; no `Accept-Encoding` at all gets the file itself. Twins are looked for only for a type that compresses (the engine's list of [ADR 0031](0031-gzip-only-and-off-by-default.md): not an image, a video, a font or an archive), and every answer of such a type says `Vary: Accept-Encoding`, whether or not a twin was found, so a cache never hands the identity body it stored to a client that could have had br, or the reverse. A twin is its own representation: its own `ETag`, its own bytes for a `Range`. The core makes no compressed file; a build step does (Vite, esbuild and `brotli`/`zstd` on the command line), and the zstd and brotli modules of milestone 3 are about compressing answers on the fly, not this.

**Where the facts come from.** An `embed.FS` cannot change while the program runs, so it is read once at Registration: every file is hashed with SHA-256 into a strong `ETag` (the first 16 bytes, base64url), since embedded files have no modification time and would otherwise have no validator, and its twins are known; a request then makes no stat. So is any `fs.FS` whose first regular file has no modification time, which is what `fs.Sub` of an `embed.FS` (the usual way to drop a `dist/` prefix) gives: a source without times has no way to say it changed, so it is taken not to change. Any other source, an `os.Root` above all, is looked at on each request and sees files as they are now, a file added while serving included. Which twins a file of such a source has is remembered per version of the file (its size and modification time), so a file with no twin does not cost three failed stats a request; the entry is made only for a file that exists and was asked for with an `Accept-Encoding`, so a client inventing names cannot grow it, and a twin that disappears is forgotten at the next request.

**Cache-Control, by name.** A name that holds a content hash is `max-age=31536000, immutable`: it can never change, because a new build gives a new name. `Index` and `Fallback` are always `no-cache`: they name the hashed files, so a stale one points at files the next deploy removed. Every other name is `no-cache` by default, or `max-age=N` with `Static.MaxAge` (whole seconds). `no-cache` is not "do not store": the browser keeps the file and asks with its `ETag` each time, which costs a 304 and no body. A `public` is never added, so a shared cache does not store a static answer to a request that carried `Authorization` behind an auth middleware. The default rule for "holds a content hash", `Static.Immutable` when nil: one part of the base name, between dots or dashes, of 8 to 64 characters, either lower-case hex with a digit and a letter (webpack's `[contenthash]`) or letters, digits and `_` with an upper-case letter and a digit (Vite's and esbuild's `[hash]`): `app-3f2a1b9c.js`, `index-BxR3k9aQ.js`, `chunk-ABCD1234.js`, `main.3f2a1b9c.chunk.css`. An application with another scheme gives its own `Immutable`.

**The single-page-app fallback.** `Static.Fallback` (`index.html` for most) is answered, `no-cache`, for a path that names no file only when the request is a browser loading a page: a GET or HEAD whose `Accept` lists `text/html` with a weight above 0, whose last segment has no extension, and whose first segment under the prefix is not the first segment of any other route of the app. The last test is what keeps an API's 404 a 404: with `GET /api/users/{id}` registered, `GET /api/nothing` is the problem+json 404 even from a browser, and so is anything under `/healthz/`. The set of first segments is read from the route table once, when the app starts serving (`Router.Each`). A fetch or an XHR (`Accept: application/json` or `*/*`) never gets the page; a missing `app.js` never gets HTML with a 200, which a browser would try to run. The fallback file must exist at Registration.

**What it costs** (the allocation axis of [ADR 0003](0003-the-trade-budget.md); idle memory: none; throughput and p99: not measured yet, waits for the serial run of wave 2). Measured on the AMD Ryzen 7 9700X on 2026-11-01 over the in-memory connection (`TestAStaticAnswerCostsWhatTheFileAnswerCostsAndATwinLookupItsStats`, three runs, no spread): from an `os.Root`, **13 allocations** a request without `Accept-Encoding` and **13** from a browser for a file with no twin (the twins remembered; before they were, it measured 28, three failed stats of five allocations each), **18** for the br twin (the twin's name and its stat); from an `embed.FS`, **5** for a file with no twin and **7** for the br twin, because nothing is stat-ed. The `os.Root` rows are ceilings in the test, as `File`'s is. Registration of an `embed.FS` reads and hashes every file once.

**Refusals** (rows of `refusal_test.go`): both or neither of `Root` and `FS`; a prefix that is not `/` and does not start with a slash, ends with one or has a wildcard (on the app and on a group); an `Index` with a slash; a `Fallback` that is not a valid name or is not a regular file in the directory; a negative `MaxAge`, or one under a second; `Summary` (and `Description`, `Returns`) on a static route; a static route that conflicts with another route.

**Scenarios it was put against.**

- _The reference workload_ ([ADR 0002](0002-the-reference-workload.md)) serving a Vite build from an `embed.FS` at `/` beside `/api/...`: hashed assets cached for a year, `index.html` revalidated with a 304, every client-side route of the app a navigation that gets `index.html`, every unknown `/api/...` path the API's own 404.
- _A hostile client walking out of the directory_: `/static/..%2fsecret.txt`, `%2e%2e/`, `%2fetc%2fpasswd`, `a.css%00`, a bad escape and a symbolic link out are each the same 404 (`TestAStaticOsRootServesFilesAsTheyAreNowAndEveryForbiddenNameIsTheSame404`); `../` and `//` are 400 at the router.
- _A client inventing names to grow memory_: no entry is made for a name that does not exist.
- _A deploy that replaces files under a running process_ (an `os.Root`): the next request sees the new file, its new tag and its new twins.
- _A CDN in front_: `Vary: Accept-Encoding` keeps br and identity apart; `immutable` lets it keep hashed files for a year.

**What it fails at.** The fallback's rule for an API is "another route owns the first segment": an application whose pages and API share a first segment (`/users/7` a page, `/users/{id}` an endpoint) gets the endpoint, and a route whose first segment is a wildcard turns the fallback off entirely. A POST to any path under a static prefix is a 405 with `Allow: GET, HEAD`, not a 404, which is the router's rule for a path one method knows (ADR 0018). A twin added beside a file that has not changed is not seen until the file changes or the process restarts. The hash rule is a guess about names: a name like `jQueryUI2.js` passes it and is cached for a year, and a hash with a dash in it (some base64url alphabets) is missed and costs a revalidation; `Immutable` replaces it. An `fs.FS` without modification times that does change while serving (an `fstest.MapFS` a test edits) is served as Registration saw it. No `public`, no `stale-while-revalidate` and no per-file `Cache-Control` are offered.

**What was rejected.** Redirecting `/docs` to `/docs/` (ADR 0018). A fallback for every 404 under the prefix, the usual default: it answers `/api/nothing` with a 200 and HTML, which a client reads as a success and fails to parse. A fallback decided by an `Exclude` list of prefixes: the route table already knows them, and a list must be kept in step by hand. A short `max-age` for unhashed names by default: it serves a stale file for that long after a deploy, and `no-cache` with a 304 costs one round trip. Compressing files on the fly for a static route: the CPU of every request for what a build step does once. Listing a directory: an index that says which files exist, which `File`'s 404 rule refuses to say.
