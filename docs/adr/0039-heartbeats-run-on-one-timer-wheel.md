# Heartbeats are pings every 30 seconds, on one timer wheel for the whole app

The server pings each WebSocket every 30 seconds and closes one that misses two pongs in a row; both are configurable. Every socket's deadlines are driven by one timer wheel per app rather than a `time.Timer` each, because a timer per socket adds its memory to every idle connection, the axis [ADR 0003](0003-the-trade-budget.md) holds hard. What the wheel costs a socket is measured when it is built and added here.

**A pong never touches the wheel.** A received pong, solicited or not, sets a flag on the socket that the next heartbeat tick reads. Re-arming the node on each pong would take the wheel's global lock, and a flood from one socket would contend with every other socket's heartbeat; pongs also count in the same bucket as pings ([ADR 0046](0046-websocket-origins-and-inbound-limits.md)). Evidence: [`docs/research/decisions-websocket/`](../research/decisions-websocket/report.md), "ADR 0046 gaps".

**Built.** The wheel ticks once a second, so a heartbeat interval is rounded to the tick; every socket has one node, embedded in its engine state (no timer and no allocation), armed before the 101 is written so that a client that sees the 101 cannot get ahead of it. A tick pings a socket whose interval has run out and counts a ping unanswered if no pong set the flag since the last one; at `MissedPongs` the socket is closed with 1008, which is about 90 s with the defaults. The same node carries the close timeout, 5 s from the moment the server's close frame is queued, armed under the socket's lock so that a flusher cannot write the frame before the node is armed. A wheel callback takes the socket's lock and queues; it never writes, because the wheel's goroutine must not block. The wheel is the app's clock's, so every test runs it on the fake clock.

**The idle gate, built.** An idle WebSocket costs 3,944 B of heap plus stack marginal from 10,000 to 20,000 sockets through the whole app (spread 3,942 to 3,947 over three runs, one message exchanged on each socket), and 4,911 B of RSS (4,840 to 5,047); 3,841 B and 4,628 B with no message. The runs used the server on cores 2, 3, 10 and 11 and the client on 4 to 7 and 12 to 15, sources 127.0.0.2 to 127.0.0.5, at commit 6b086e4 with the step's changes, in [`docs/research/ws-gate/`](../research/ws-gate/report.md). The gate is `TestTheMarginalHeapAndStackOfAnIdleWebSocketStaysUnderItsCeiling`, 4,700 B of heap plus stack from 1,200 to 2,200 sockets (3.4 to 3.8 KB measured there), 20% over the 10k to 20k number as the TLS gate is over its own ([ADR 0017](0017-tls-now-http2-later.md)). What the wheel and the rest of the socket's state add to the prototype's 2,947 B is about 1 KB; the stack is 2,055 B of the whole and is the goroutine's minimum.

**Parked, the gate is lower (step 16).** An idle WebSocket now parks after 100 ms ([ADR 0005](0005-our-own-http1-engine-with-a-goroutine-per-connection.md)): its goroutine ends and its socket waits on the engine's poller, so it holds **1,642 B of heap plus stack** (1,632 to 1,661, marginal from 10,000 to 20,000 sockets, one message exchanged on each, three interleaved runs) and 4.7 KB of RSS from 0 to 20,000 sockets, against 3,966 B and 5.9 KB `WithoutParking` in the same runs ([`docs/research/parking/`](../research/parking/report.md)). Nothing in this ADR needed the reading goroutine: a tick runs on the wheel's goroutine and its ping leaves through the flusher, so a parked socket is pinged on time; the pong it answers wakes it, it reads the pong, and it parks again 100 ms later. The close deadline is the same node, and when it fires on a parked socket the socket is closed and woken so its own goroutine runs `OnClose`. A socket assembling a message does not park, so `MessageTimeout` stays the deadline of a read. The wheel also carries the idle timeout of a parked HTTP connection now, one more node in a `parkState` the connection makes the first time it parks, so that timeout is rounded up to the one-second tick. The gate is `TestTheMarginalHeapAndStackOfAnIdleWebSocketStaysUnderItsCeiling`: 1,800 B parked (20% over the 1,466 B it measured, from 1,200 to 2,200 sockets) and the 4,700 B above `WithoutParking`. What it costs: at the default 30 s interval each idle socket is woken once a heartbeat, about 670 wakes a second at 20,000 sockets, each holding a goroutine for 100 ms.
