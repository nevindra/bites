# A message sent to many sockets is framed once, and every queue shares that frame

A broadcast frames its message once into an immutable frame, and each socket's queue holds a reference to it, counted inside the engine and never visible to the user. Measured with a hand-written server, pushing one message a second to 20,000 sockets raised RSS by about 3% and returned every pooled buffer ([`docs/research/ws-idle/`](../research/ws-idle/report.md)). The idea is fib's `PreparedMessage`. A shared frame belongs to no request, so [ADR 0008](0008-no-pooled-object-reaches-the-user.md) is not touched: the user never holds it.

**Built.** A frame is one `[]byte` made by the first subscriber's encoder: ten bytes are reserved in front of the payload, the payload is encoded after them, and the header is written right before the payload, so the frame is one allocation and is not copied again. There is no reference count: the queues hold the slice and the collector frees it when the last queue has written it. Up to 64 subscribers the sockets are written on the publisher's goroutine; beyond that the list is split over up to four workers (`min(GOMAXPROCS, 4)`) that write inline where they can. The list of subscribers is a snapshot taken under the Topic's lock and pooled by the Topic, so a publish allocates the frame and, past 64 subscribers, the workers' closures: [ADR 0003](0003-the-trade-budget.md). All subscribers of a Topic must be sockets of the same app, because the first one's encoder frames for all.
