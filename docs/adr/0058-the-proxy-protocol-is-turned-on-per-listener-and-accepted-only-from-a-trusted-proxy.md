# The PROXY protocol is turned on per listener and accepted only from a trusted proxy

A listener given `ProxyProtocol()` reads the PROXY protocol, version 1 (text) or version 2 (binary), at the start of every connection: the header a TCP balancer (AWS NLB, HAProxy, a Kubernetes ingress in TCP mode, nginx's `proxy_protocol on`) sends to say who its client is. The client it names becomes the connection's peer, so `Request.RemoteAddr`, `Request.ClientAddr` and the forwarding walk of [ADR 0025](0025-no-proxy-is-trusted-by-default.md) start from it. Decided and built on 2026-11-01, milestone 3, wave 2, track E (`internal/proxyproto`, `internal/engine/proxy.go`, `proxies.go`).

```go
app := bites.New(bites.WithTrustedProxies(bites.TrustedProxies{
	Prefixes: []netip.Prefix{netip.MustParsePrefix("10.0.0.0/16")}, // the NLB's subnets
}))
go app.Listen(":8443", bites.ProxyProtocol()) // the balancer's port
go app.Listen(":8080")                         // the kubelet's probes, no header
```

## The rule

1. **Per listener.** `ProxyProtocol()` is a `ListenOption`, given after the other arguments of `Listen`, `ListenTLS`, `ListenUnix`, `Serve` or `ServeTLS`. A balancer speaks the protocol on the port it was configured for and not on the others: the health checks of an orchestrator go to the pod directly and send no header, and an app on several listeners ([ADR 0068](0068-one-app-serves-several-listeners-and-a-unix-socket-is-a-socket-like-tcp.md)) has one for each. The start-up line of each listener says `proxy_protocol=true` or `false`.
2. **One list of trust.** The peers that may send a header are the trusted proxies of `WithTrustedProxies`: a TCP peer inside `Prefixes`, a Unix socket's peer when `UnixSockets` is set. Rules 3 and 4 make a header from anyone else impossible to act on.
3. **A peer outside the list is closed as it is accepted**, before a byte is read, and gives its `MaxConns` place back at once. The port belongs to the balancer; a client that reached it directly is either a network mistake or a probe, and serving it plainly would make the port answer two protocols.
4. **A trusted peer must send the header.** A connection whose first bytes are not one (plain HTTP, a ClientHello), or whose header breaks a rule of the specification, is closed with nothing written: the peer is a balancer speaking a protocol wrongly, and a problem+json body would go to the balancer, not to a person. A trusted peer that sent no header at all is logged at Warn, at most once a minute with the ones skipped counted, because it is almost always a balancer not configured to send one, which closes every connection; a peer refused at accept is logged the same way, because a stale `Prefixes` closes every connection too. A malformed or slow header is a Debug line.
5. **The deadline.** On a plain listener the header is read as the first bytes of the first request: the wait for its first byte is the connection's idle wait, parked like any other ([ADR 0005](0005-our-own-http1-engine-with-a-goroutine-per-connection.md)) and ended by `IdleTimeout`, because some balancers send the header only with the client's first bytes; once its first byte has arrived, the whole header must arrive within `HeadTimeout`, as a head must ([ADR 0024](0024-limits-are-on-by-default.md)). On a TLS listener the header comes before the handshake and is read within the `HandshakeTimeout` that runs from accept ([ADR 0017](0017-tls-now-http2-later.md)). Either way the connection counts against `MaxConns` from accept, as every connection does.
6. **What the header says.** Version 1 `TCP4` and `TCP6`, and version 2 `PROXY` over `AF_INET` or `AF_INET6` with `STREAM`, name a client: its address and port become the peer. Version 2 `LOCAL` (the balancer's own health check), version 1 `UNKNOWN`, and version 2 `PROXY` with `AF_UNSPEC` or `AF_UNIX` keep the connection's real peer, as the specification says. Version 2 TLVs are skipped unread. Refused as malformed: a version 1 line longer than the 107 bytes the specification allows, a bare LF, a byte that is not printable ASCII, fields not separated by exactly one space, an address of the other family or with a zone, a port past 65535 or with a leading zero; a version 2 header with a version other than 2, a command other than `LOCAL` and `PROXY`, an unknown family or transport, a `DGRAM` source under `PROXY` (this stream cannot be a datagram's), an address block shorter than its family needs (refused at the header's 16th byte, before the rest is waited for), or a length past 4 KiB.
7. **A Unix socket's peer is trusted only when named.** `TrustedProxies.UnixSockets` trusts the peer of every Unix socket the app listens on, for forwarding headers and for the PROXY protocol: the socket file's permission bits (`ListenUnix`'s `perm`) decide who may connect, so they are the list a CIDR is for TCP. It is false by default, and `Prefixes` may be empty when it is set. A Unix peer has no address; with it trusted, `ClientAddr` reads `X-Forwarded-For` from the right as for any trusted proxy, and without, it is the zero `Addr` and no header is read. After a PROXY header that named a client, the peer is that client, a TCP address, trusted only if it is in `Prefixes`.

## What it costs

**Memory per idle connection: unchanged for a connection of a listener without the protocol, 72 bytes more (an 80-byte object) for one with it.** The connection struct stays at 416 bytes, its size class: the state (`px`, one byte) took two bytes of padding after `moved`, held by `TestTheConnectionStructKeepsItsSizeClassWithThePROXYProtocolState`. The client a header named lives in a `proxyConn` wrapper the accept loop puts around a trusted peer's connection, so that `c.nc` is the same value for the connection's whole life (Shutdown and a WebSocket's flusher read it from other goroutines); it holds the named address and, over TLS, the bytes read past the header until crypto/tls has read them. Measured, heap plus stack marginal from 1,200 to 2,200 parked loopback connections, each test in a process of its own, interleaved three times: plain 1,191, 1,153 and 1,180 B; with a version 1 header 1,264, 1,177 and 1,292 B (`TestTheMarginalHeapAndStackOfAnIdlePROXYProtocolConnectionStaysUnderItsCeiling`, under the 1,400 B gate of a parked connection). Two tests in one process read the second one low, because it reuses the runtime's descriptors the first one freed; that is why the runs were separate.

**Allocations per request: none.** A typed POST behind a middleware that reads `ClientAddr` and `Scheme`, on a connection that began with a header, is 2 allocations, exact (`TestATypedRequestOverAPROXYProtocolConnectionStillAllocatesTwice`). `Exchange.RemoteAddrPort` returns the named address from the wrapper without building a `net.TCPAddr`; `RemoteAddr()`, which the log lines use, builds one. A connection pays the wrapper, and over TLS a copy of the bytes read past the header, once. The request path of a listener without the protocol gained one byte comparison per request (`c.px == pxDue` in the serve loop) and two type assertions in `RemoteAddrPort`.

**Throughput and p99: not measured yet; they wait for the serial run.** The header is parsed once a connection, in the pooled read buffer, with no syscall of its own when it arrives with the first request.

## Refusals

Rows of `refusal_test.go`, each a panic at the serving call naming its file and line: `ProxyProtocol` on an app with no `WithTrustedProxies` ("no peer could send the header"); on a Unix socket (`ListenUnix`, or `Serve` or `ServeTLS` of a Unix listener) when `UnixSockets` is false; on a TCP listener when `Prefixes` is empty (only Unix peers are trusted); a nil `ListenOption`. `WithTrustedProxies` with an empty `Prefixes` is refused only when `UnixSockets` is false too; its row's message says so.

What cannot be caught before the first connection: a balancer that is not configured to send the header, or sends it from an address outside `Prefixes`. Both close every connection, and both are the rate-limited Warn of rule 4, so the log says which it is.

## Scenarios it was put against

- _The reference workload_ ([ADR 0002](0002-the-reference-workload.md)) behind an AWS NLB with proxy protocol v2 on its target group: `Prefixes` lists the NLB's subnets, the app listens on the target port with `ProxyProtocol()` and on a second plain port for the kubelet. `ClientAddr` is the client's address, and a rate limit by address ([ADR 0055](0055-rate-limiting-is-a-token-bucket-per-key-with-a-bounded-store.md)) keys on the client, not on the NLB's private address.
- _A hostile client that reaches the port directly_ and sends `PROXY TCP4 10.0.0.1 ...` to claim an internal address: its peer is not in `Prefixes`, so it is closed before its bytes are read (`TestAPeerThatIsNotATrustedProxyIsClosedAtAcceptAndGivesItsPlaceBack`).
- _A hostile client behind the balancer_ that sends `X-Forwarded-For: 10.9.9.9` through an L4 balancer that forwards its bytes untouched: the peer is the client the header named, which is not a trusted proxy, so the header is not read (`TestBehindAPROXYProtocolBalancerTheClientItNamesIsThePeerAndItsOwnForwardingHeadersAreNotBelieved`).
- _A slow or truncated header_ from a trusted peer: closed at `HeadTimeout` after its first byte, or at `HandshakeTimeout` from accept over TLS (`TestAPROXYHeaderThatStallsAfterItsFirstByteIsClosedAtTheHeadTimeout`, `TestOverTLSAPROXYHeaderThatNeverComesIsClosedAtTheHandshakeTimeout`). Only a trusted peer can hold a connection open waiting, and it holds it as an idle connection: parked, no goroutine (`TestAConnectionWaitingForItsPROXYHeaderParksAndIsServedWhenItComes`).
- _HAProxy_, which writes the header the moment it connects and the request later: the header is read alone, the scratch buffer goes back to the pool, and the connection waits idle for its request (`TestAHeaderSentAloneIsFollowedByAnIdleWaitForTheFirstRequest`).
- _TLS terminated by the app behind an NLB_: the header, then the ClientHello, often in one read; the bytes past the header reach crypto/tls first (`TestOverTLSThePROXYHeaderComesBeforeTheHandshakeAndTheBytesReadPastItReachCryptoTLS`), and the connection parks after it as any TLS connection does.
- _nginx on the same host over a Unix socket_, with `proxy_protocol on` toward the app: `ListenUnix(path, 0o660, ProxyProtocol())` and `UnixSockets: true` (`TestAPROXYHeaderOnATrustedUnixSocketNamesTheClient`).
- _A misconfigured balancer_ that does not send the header: every connection is closed and the log has one Warn a minute naming the peer (`TestATrustedPeerThatSendsNoPROXYHeaderIsClosedWithNothingWrittenAndAWarn`).
- _Shutdown_ while a connection waits for its header: it is idle, so it is closed at once ([ADR 0029](0029-shutdown-drains-and-then-closes.md), `TestShutdownClosesAConnectionStillWaitingForItsPROXYHeader`).

The parser was fuzzed for 120 s, 46,508,071 executions with 18 inputs found beyond the 12 seeds, and no failure; the property checked is that two parses agree, an error returns nothing else, a header's length is within the input and 4 KiB, `Named` holds exactly when the source is valid, and bytes after a header never change what it says. The seeds are kept as `TestTheFuzzSeedsParseTheSameWayEveryTime` (`internal/proxyproto`).

## What it fails at

A trusted peer can name any client; the protocol has no signature, so the trust is only as good as `Prefixes` (a pod network that also holds untrusted pods trusts them all, as for [ADR 0025](0025-no-proxy-is-trusted-by-default.md)). A header that keeps the real peer (`LOCAL`, `UNKNOWN`, `AF_UNSPEC`, `AF_UNIX`) leaves the balancer as the peer, which is trusted, so `X-Forwarded-For` is then read; an L4 balancer that relayed a client of a family it cannot express would let that client name its address. The TLVs are not read, so an NLB's VPC endpoint id or a TLS summary a balancer sends is not offered to the request. A port cannot serve both proxied and direct clients: the guide says to give each its own listener. Version 2's CRC32c TLV is not checked. A client that a balancer connects and leaves silent keeps the connection open for `IdleTimeout`, parked, as any idle connection.

## What was rejected

- **One switch for the whole app** (`WithProxyProtocol()` beside `WithTrustedProxies`): the balancer speaks it on one port and the orchestrator's probes reach another without it, and one switch would close every probe.
- **A field of `TrustedProxies`** turning it on: the list says who may speak, not which ports speak it, and the same list serves forwarding headers on plain listeners.
- **A listener wrapper** (`bites.ProxyListener(ln)`): it would not work with `Listen`, `ListenTLS` and `ListenUnix`, which make their own listener, and a wrapper that reads the header in `Accept` would read it on the accept loop's goroutine, where one slow balancer stalls every connection behind it.
- **Serving an untrusted peer plainly on a PROXY port**, refusing only a header from it: the port would answer two protocols, a direct client's `PROXY` request line (a valid extension method) would have to be told from a header by sniffing, and a stale `Prefixes` would quietly serve every client with the balancer as its address instead of failing loudly.
- **Accepting a trusted peer that sends no header** (HAProxy's optional mode): a balancer misconfigured to omit it would have every client served as the balancer's address, the failure of [ADR 0025](0025-no-proxy-is-trusted-by-default.md)'s stale list without its signal.
- **Reading the header with its own short deadline** instead of the idle wait: a balancer that sends it with the client's first bytes (a browser's preconnect, idle for seconds) would have its connections closed.
- **Trusting a Unix socket's peer by default**, or by the listener's `ProxyProtocol` alone: [ADR 0068](0068-one-app-serves-several-listeners-and-a-unix-socket-is-a-socket-like-tcp.md) proposed that it be named, and `UnixSockets` names it once for forwarding headers and the protocol together.
- **Storing the named address in the connection struct**: 32 bytes would move every connection, proxied or not, from the 416 to the 448 size class.
