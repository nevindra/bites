# A JSON value of several kinds is a tagged union: a struct of Opt variants with a Discriminator method

A WebSocket protocol is a dozen kinds of frame (join, leave, say, typing, an error, an acknowledgement), and a route has one client type and one server type ([ADR 0047](0047-a-socket-is-a-handle-and-a-topic-is-a-broadcast.md)). Before this decision the only shape was one struct with a `type` enum and every other field optional, so neither the compiler nor the API document could say which fields belong to which kind; an application wrote its protocol that way and its generated `schema.d.ts` could not narrow a frame by its `type`. `OneOf2` to `OneOf4` ([ADR 0013](0013-other-statuses-are-wrapper-types.md)) choose among a handler's answers, each with its own status, and stop at four. Decided 2026-11-04; the server-only variant added 2026-11-05, from an application whose Topic carries a reference.

**Decision.** A struct whose method `Discriminator() string`, on the value receiver, names a member is a **tagged union**. Each of its fields is an `Opt` of a struct, one **variant**, and the field's wire name (the naming policy, a `json` tag or `WireNames`) is the variant's **tag**. Exactly one variant is set in a value.

```go
type Join struct{ Room int64 }
type Say struct{ Text string }

type ClientFrame struct {
	Join bites.Opt[Join]
	Say  bites.Opt[Say]
}

func (ClientFrame) Discriminator() string { return "type" }
```

- **On the wire** a value is its variant's object with the discriminator as a member: `{"type":"join","room":7}`, `{"type":"say","text":"hi"}`. The encoder writes the discriminator first; the decoder finds it wherever it sits in the object, so a client that orders members differently is read the same.
- **Reading it** is the Opt the handler already knows: `if j, ok := f.Join.Get(); ok { ... }`. Writing it is `out.Joined.Set(Joined{Room: 7})`.
- **It is a JSON shape, not a WebSocket one.** The codec ([ADR 0011](0011-one-naming-policy-for-wire-names.md)) compiles it, so it works as an Inbox's message, a Socket's message, a Topic's payload ([ADR 0081](0081-a-topic-reaches-other-instances-through-a-broker-and-postgres-is-a-module.md)), a JSON request Body, a response and a field nested in any of them.
- **A mistake is located as in any object.** A tag that names no variant is `type: expected one of: join, say` (rule `values`), a missing discriminator is `type: required`, a member the variant does not have is `unknown field` as for any body, and a variant's own fields are located as `room`, `frames[2].text`. On a socket a malformed message is answered as any other ([ADR 0035](0035-websockets-are-message-handlers-with-no-user-read-loop.md)).
- **Sending one with no variant set, or two, is an error from `Send`** (`the union ClientFrame has no variant set: set the Opt of the one to send`), never `{}` written in silence.
- **A variant only the server carries is named by a `ServerOnly() []string` method of the union**, on the value receiver, in the style of `Discriminator` and of `DeprecatedFields` ([ADR 0020](0020-descriptions-come-from-registration-and-later-from-doc-comments.md)): the strings are Go field names of variants. The case is a message too large for its broker ([ADR 0081](0081-a-topic-reaches-other-instances-through-a-broker-and-postgres-is-a-module.md)), published as a reference that `Topic.Resolve` turns back into the message on each instance. The reference must be a value of the Topic's `Out`, so with a union it is a variant, and before this rule that variant was in the API document and in every generated client although no client ever receives one, and nothing stopped the server from sending it to a client by mistake.

```go
type ServerFrame struct {
	Said bites.Opt[Said]
	Ref  bites.Opt[MessageRef] // carried between instances, never sent to a client
}

func (ServerFrame) Discriminator() string { return "type" }
func (ServerFrame) ServerOnly() []string  { return []string{"Ref"} }
```

  - **Left out for clients:** the variant is not in the API document (the `oneOf` and the discriminator of either direction), and a client that sends its tag is told the tags it may use, without it (`type: expected one of: said`), so a client cannot forge a reference. Anything else that describes the union to clients reads `Describe`, which omits it.
  - **Carried by the server:** the Topic's payload codec ([ADR 0081](0081-a-topic-reaches-other-instances-through-a-broker-and-postgres-is-a-module.md)) writes and reads it as any variant (`Options.ServerVariants`), so it crosses the broker, and `Listen` functions, which are the server's own code, get it.
  - **Never sent to a client, refused when it would be:** `Socket.Send` of a value whose present variant is server-only returns an error naming the union, the tag and the field (`the union ServerFrame has its server-only variant ref (field Ref) set, which is never sent to a client`) and sends nothing, the socket staying open. A Topic's delivery to its Sockets of a value that still holds one (after `Resolve`, or on a Topic with none) sends nothing to its Sockets and logs a Warn naming the Topic and the variant; a Topic with no broker returns the same error from `Publish` when it has a Socket, since the publisher is the caller. An HTTP answer that encodes one is a 500 with the reason logged and no body of it sent, as any encoding error is.
  - **The name.** `ServerOnly` says who carries the variant, in the words of the types it sits beside (`Socket[ServerFrame]`, "the server's own code"), and reads as a fact of the type, as `Discriminator` does. Refused names: `Internal`, which Go reads as an import rule and an API document as `x-internal` (a thing hidden from a document yet sent to clients), neither of which is this; `Unsent`, which says nothing of who carries it and is false, since the broker carries it; `Hidden` and `Private`, which say what the document does and not what the variant is; `BrokerOnly`, which names one use when the rule is about clients.
- **The API document** names the type as a component that is `oneOf` its variants with `discriminator: {propertyName: type}`; each variant is its object written inline with the discriminator as a required member of one `const` value and `title` its tag. Inline and not a `$ref` to the variant's type: a request object lists its members with `additionalProperties: false`, and the discriminator is a member of the variant only inside the union, so a reference with the member beside it would describe a body the schema refuses. A generator (openapi-typescript) makes a discriminated union of it.

**Refusals** at Registration, from the codec, each naming the field and saying what to change (rows of `refusal_test.go` and of the codec's own tests): `Discriminator` on the pointer receiver (the codec holds a value, so it would never be found); a `Discriminator` that returns `""`; fewer than two variants; a field that is not an `Opt` of a struct; a variant that writes or reads its own JSON (the union writes its object); a variant that is a union itself; a variant with `omitempty` or `omitzero` (only the one set is written); a variant with a member whose wire name is the discriminator. `ServerOnly` adds four, each from the codec naming the union and saying what to change: on the pointer receiver (never found); a name that is not a variant, listing the variants there are (`ServerOnly names Rfe, which is not a variant of Frame (its variants: Said, Ref)`, as `DeprecatedFields` does, so a stale name cannot outlive its field); a name twice; and every variant named, since no client could be sent or send any.

**What it costs** ([ADR 0003](0003-the-trade-budget.md)). Nothing for a type that is not a union: the check is one method lookup at Registration. A union decode reads the object twice, once to find the discriminator and once as the variant, through a pooled decoding state, and allocates nothing of its own (`TestDecodingAUnionCostsNoAllocationOfItsOwn`); the variant's own strings and slices cost what they cost in a plain object. It takes no fast path ([ADR 0003](0003-the-trade-budget.md), the flat-struct decoder), so a union message decodes as a nested object does. Encoding writes the head and the variant's object once, and splices the two in place. A server-only variant costs nothing more: the check is one string-length test on the variant that is set, made only in a plan that refuses server-only variants and set only for a variant that is one, so the encoding of a type with no union, and of a union with no `ServerOnly`, takes no new step and none is on the path of a typed JSON request, which stays at 2 allocations (`TestEncodingAUnionWithAServerOnlyMethodAllocatesNothingMoreThanOneWithout`, and the guard of [ADR 0003](0003-the-trade-budget.md)). A Topic's payload codec is compiled with `ServerVariants` once per `Out`, as before.

**Scenarios it was put against.**

- _A chat protocol of twelve frames_, client and server: two unions, each variant a struct of its own fields, and a handler that switches on which `Opt` is set; the document lists twelve variants with their own required members.
- _A hostile client_ sends `{"type":"join","type":"say"}`: the object is refused as a duplicate member by the JSON reader before any variant is chosen. One that sends `{"type":7}` or `{"type":null}` is told the tags it may use. One that nests a union a thousand deep is held by `MaxDepth` as any body is.
- _An older client_ that does not know a new server frame: the client's own concern, as for an added field; the server never sends `{}`.
- _A frame through a Topic and pgnotify_: the payload is the codec's own JSON, so the union crosses the broker as it reaches a socket.
- _A message too large for pgnotify_ (7999 bytes): published as `Ref`, delivered to every instance, turned into `Said` by `Resolve` there; the sockets get `Said`, the document never lists `Ref`, and a `Ref` that a `Resolve` forgot to turn (a missing row returning `f, true`) is dropped for the sockets with a Warn naming the Topic and `ref`, not sent.
- _A hostile client_ sends `{"type":"ref","id":"x"}` to an Inbox whose union has it: told `expected one of: said`, so it cannot make the server resolve a reference it chose.
- _A handler that sets two variants by mistake_: `Send` returns the error naming both tags, and the socket stays open.

**What it fails at.** The compiler does not stop a handler from setting two variants or none; the codec does, when the value is sent. A variant cannot be a type that is not a struct (a bare string kind is a variant with one field). The tag is the field's wire name, so renaming the Go field renames the tag unless `WireNames` or a `json` tag fixes it. A server-only variant is refused when a value is sent, not when it is built: nothing in the type stops a handler from setting `Ref` and calling `Send`, so the first send is the error, and a Topic whose messages are published by the same code that forgets `Resolve` learns it from a Warn, not at Registration (the Topic's `Out` is known at `NewTopic`, but whether a `Resolve` follows is not). A drop on a Topic is a log line and not an error to the publisher, which is on another instance. `ServerOnly` marks a variant for every direction of its union: a union used as an Inbox's message and a Socket's cannot have a variant that the client sends and the server never does, so such a protocol has two unions, as it has two for its two directions. The decoder reads a union's object twice, which a body of megabytes made of one huge union would pay; such a body is a list of unions, each small.

**What was rejected.**

- _A second type parameter for the broker's payload, `Topics[Out, Wire]`_ (a `Wire` type holding the reference, converted to `Out` by `Resolve`): the document and the clients would never see the reference, and the Topic would be typed as it is delivered. It doubles every Topic signature (`Topic[Out, Wire]`, `Topics[Out, Wire]`, `Socket` subscriptions, `SubscribeUnless`, the module's and bitetest's helpers) for the one application that carries a reference, and a Topic that needs no reference would still name a `Wire`, or a second spelling of `Topic[Out]` would have to exist beside it. A method of the union is one line on a type the application already has.
- _The reference as an ordinary variant, as before_: the document and the generated clients list a variant no client receives, and `Send` writes it to a client when a `Resolve` is forgotten.
- _A struct tag on the field_ (`bites:"server"`): a tag the compiler cannot check, refused across the framework ([ADR 0042](0042-text-values-are-decoded-by-type.md)); a method is checked at Registration against the variants.
- _A refusal at Registration of a Topic with no `Resolve`_: a Topic does not know whether the application publishes a server-only variant, only that its `Out` has one, and an application may publish a reference only for a few messages and use `Listen` for the rest.
- _`OneOf5` to `OneOf16` with a discriminator type argument_: one type per count, a letter per variant (`f.G(...)`) that says nothing of what the variant is, and the tag would have to come from somewhere else anyway.
- _An interface with a sealed method and a registration of its variants_ (`bites.Union[Frame](Join{}, Say{})`): a second place to state the variants beside the type, checked only where the registration runs, and an interface value is boxed on every message.
- _A `type` tag on the struct_ (`bites:"union=type"`): a tag the compiler cannot check, refused across the framework ([ADR 0042](0042-text-values-are-decoded-by-type.md)).
- _Externally tagged JSON_ (`{"join":{"room":7}}`): it needs no new feature, a struct of Opts already reads it, but clients and generators expect a `type` member, and the document could not say "exactly one" without `oneOf` either.
- _Variants as `$ref` to their own components_: the request object's `additionalProperties: false` would refuse the discriminator (above).
