# No proxy is trusted unless the application names it

The client address and scheme come from the socket. A forwarding header is read only when the connection comes from an address the application listed as a trusted proxy, by CIDR. Echo 5.4.0 had to change its forwarded-header trust as a security fix, after release, which broke HTTPS redirects and HSTS for users behind proxies ([`docs/research/gin-echo/`](../research/gin-echo/report.md)). A default that trusts nothing cannot need that fix.

**How the list is given, and what is read** (decided on 2026-11-01 for milestone 3; built 2026-11-01, milestone 3 wave 1, security track, `proxies.go`, see _Built_ below). `Request.RemoteAddr()` stays the peer of the connection. `Request.ClientAddr() netip.Addr` is the client's address as far as the app can trust it, and it is what rate limiting by address, the access log and an application's audit use. An app behind proxies names them with `WithTrustedProxies(TrustedProxies{Prefixes: ..., Header: ...})`. With no trusted proxies, `ClientAddr` is the peer's address and no forwarding header is read. With them:

1. If the peer is not in `Prefixes`, the answer is the peer. A client that talks to the app directly cannot name another address, whatever it sends.
2. If the peer is trusted, the header is read **from the right**. `X-Forwarded-For`, the default `Header`, is a list each proxy appends to, so its rightmost element was written by the nearest proxy and its leftmost by whoever sent the request first, which may be the client lying. The walk skips every element inside `Prefixes` and returns the first that is not: the rightmost untrusted address. Every line of a repeated header is read, the last line rightmost, as a list header is joined.
3. An element with a port (`203.0.113.7:5123`, `[2001:db8::1]:443`, which some balancers write) has the port dropped. An element that does not parse, or is `unknown`, stops the walk, and the answer is the nearest address to its right, the last proxy the app trusts: never a guess past a broken link.
4. If every element is trusted, the answer is the leftmost one: the client is inside the trusted network.
5. `Header` set to another name (`CF-Connecting-IP`, `X-Real-IP`, `Fly-Client-IP`) reads that header as one address written by the trusted proxy, used only when the peer is trusted. Behind some CDNs it is the only reliable source.

**Scheme.** `Request.Scheme()` is `https` on a TLS connection, the value of `X-Forwarded-Proto` when the peer is trusted and it says `http` or `https`, and `http` otherwise. It is what a redirect and a `Secure` cookie need. It is read from any trusted peer with no switch, unlike `X-Forwarded-Host` (decided 2026-11-02): its value can only be one of two words, so a balancer that passes the client's header through lets that client choose between `http` and `https` for its own answers, never name a host or a path, and the balancers of the reference deployment write it.

**The public host and prefix** (decided and built on 2026-11-02, milestone 3, `proxies.go` and `openapi.go`; it replaces the 2026-11-01 position that none of these headers is read, under _What was rejected_). Behind a proxy, a link the app writes for a client (the `Location` of a `Created`, `SeeOther` or `Redirect`, a link in a body) must name the host and the path the client used, not the ones the proxy forwarded to; and the API document must say where the API is served. Three methods of `Request`, two fields of `TrustedProxies` and one of `Info` do it:

```go
func (r Request) PublicHost() string           // the host, with its port, the client asked for
func (r Request) PublicPrefix() string         // the path prefix a trusted proxy stripped, "" for none
func (r Request) PublicURL(path string) string // Scheme() + "://" + PublicHost() + PublicPrefix() + path

type TrustedProxies struct{ /* Prefixes, UnixSockets, Header */ ForwardedHost, ForwardedPrefix bool }
type Info struct{ /* Title, Version, Description */ Servers []Server }
type Server struct{ URL, Description string }
```

1. **`Request.Host` stays the `Host` header**, what this hop was sent, as `RemoteAddr` stays the peer. `PublicHost` is the host to build a link with: `X-Forwarded-Host` when it may be read (2), `Host` otherwise. `PublicPrefix` is `X-Forwarded-Prefix` when it may be read, `""` otherwise. `PublicURL` joins the scheme of `Scheme`, the host and the prefix to a path of the app's own routes, and is `PublicPrefix` and the path alone when there is no host (an HTTP/1.0 request without one).
2. **Read only from a trusted peer, and only when the app says its proxies write the header.** `X-Forwarded-Host` is read when `TrustedProxies.ForwardedHost` is set and the peer is a trusted proxy (rule 1 above, the same test as `ClientAddr`'s); `X-Forwarded-Prefix` when `ForwardedPrefix` is set and the peer is trusted. Both are false by default. Being trusted for `X-Forwarded-For` is not enough, because a balancer can append to `X-Forwarded-For` and set `X-Forwarded-Proto` while it passes a client's `X-Forwarded-Host` through untouched (AWS's Application Load Balancer documents the first two headers and not the third; a claim from the vendor's documentation, not confirmed with a probe), and a host the client chooses in every link the app builds is the password-reset poisoning attack: the reset mail links to the attacker's host. Whether a proxy replaces the header is known only to whoever configured it, so the app says it.
3. **The element the nearest proxy wrote.** Of each header the rightmost element of the last line is read, as `X-Forwarded-Proto` is: the one the trusted peer wrote. An address can be checked against `Prefixes`, so the walk of `X-Forwarded-For` goes on to the left past trusted proxies; a host or a prefix carries nothing to check, so no element left of the peer's is known to come from a trusted proxy. Behind two proxies the nearest must write the public value, by replacing the header or by passing on the one the edge wrote.
4. **A hostile value answers what the connection says, never a guess.** `X-Forwarded-Host` must be a host name or IPv4 address of letters, digits, `-`, `.` and `_`, or an IPv6 address in brackets without a zone, then optionally `:` and a port of at most 65535; a path, a userinfo (`user@host`), a space, a comma, a backslash, a `%`, a control byte, an IPv6 address without brackets or an empty port fails, and `PublicHost` is then the `Host` header. `X-Forwarded-Prefix` must be an absolute path of RFC 3986 path characters with no empty, `.` or `..` segment, a dot written as itself or as `%2e`, and a `%` followed by two hex digits; its trailing slash is dropped, so `/api/` is `/api` and `/` is `""`. That refuses `//evil.example` and `/\evil.example`, which a browser following a `Location` of the prefix and a path reads as another host, and `/api/../admin`; a prefix that fails is `""`. Neither CR nor LF is in either set, so neither value can split a header the app writes it into.
5. **`Forwarded` is not read, and the two families are never mixed.** A proxy that writes one family of forwarding headers commonly passes the other through as the client sent it, so any precedence between them (`Forwarded` first and `X-Forwarded-*` as a fallback, or the reverse) lets the client write whichever one the proxy does not touch. One family is read, `X-Forwarded-*`, the one the balancers of the reference deployment write and the one `ClientAddr` already reads. `Header: "Forwarded"` is refused in `New`: it was accepted before and read as one address, which its `for=...` elements never are, so `ClientAddr` silently answered the peer. Naming `X-Forwarded-Host`, `X-Forwarded-Proto` or `X-Forwarded-Prefix` as `Header` is refused for the same reason. Reading `Forwarded` would be a switch of the whole family (`for`, `proto` and `host` together, and no prefix, which RFC 7239 does not define), added when a deployment's proxy writes it (decided 2026-11-02: none of the reference deployment's proxies writes only `Forwarded`).
6. **The document's `servers` are configuration, fixed at Registration.** `Info.Servers` lists where the API is served, each an absolute `http` or `https` URL (`https://api.example.com/chat`) or a path on the host the document was fetched from (`/chat`), with an optional description, and they are written as the document's top-level `servers`. They are not read from a request: the document is the same bytes for every request, built once at start ([ADR 0020](0020-descriptions-come-from-registration-and-later-from-doc-comments.md)), and a document that followed `X-Forwarded-Host` would have to be built per request, with its allocations, and would let a cache in front of the app store one client's host for everyone unless every answer carried `Vary`. The public URL is a fact of the deployment, known when the process starts, as its certificate is. Without `Servers` the document has none, which OpenAPI reads as `/` on the host the document came from: right for an app at the root of its host, wrong behind a prefix.
7. **Nothing the framework writes changes.** The framework builds no absolute URL and redirects nowhere on its own (a directory named without its slash is a 404, [ADR 0065](0065-static-files-are-a-route-with-twins-cache-rules-and-a-fallback-that-never-hides-a-404.md); the router redirects nothing, [ADR 0018](0018-the-router-follows-servemux-rules.md)), and a `Location` a handler returns is written as returned ([ADR 0009](0009-the-response-comes-only-from-the-return-value.md)). An app that wants its links right behind a prefix builds them with `PublicPrefix` or `PublicURL` in a Provider, or from its own configured public URL, which `examples/chat` does with `CHAT_PUBLIC_URL`. CSRF still takes its allowed origins as a list, as CORS does ([ADR 0057](0057-csrf-trusts-the-browsers-origin-and-falls-back-to-a-double-submit-token.md)), rather than comparing with either host.

**What it costs.** Nothing for a request that reads none of the three: the policy gained two booleans and no request does any work for them. `PublicHost` and `PublicPrefix` scan the copied head as `Header` does and answer a substring of it, checked in place (an IPv6 host goes through `netip.ParseAddr`, which allocates nothing for an address without a zone): **0 allocations**. `PublicURL` allocates the string it returns: **1**. Exact in `TestPublicHostAndPrefixAllocateNothingAndPublicURLAllocatesItsString` (`security_budget_test.go`): a typed POST behind a trusted peer that sends an IPv6 `X-Forwarded-Host` with a port, a two-element `X-Forwarded-Prefix` and `X-Forwarded-Proto` is 2 allocations with a middleware that reads `PublicHost` and `PublicPrefix`, and 3 with one that calls `PublicURL`; [ADR 0003](0003-the-trade-budget.md) names the 3. Memory per idle connection: none. Throughput and p99: not measured; a call is a scan of the head, like `ClientAddr`'s. The document's `servers` are written once at start and cost no request anything. **Axes:** none of the four moves for a request that does not call `PublicURL`.

**Refusals** (rows of `refusal_test.go`): in `New`, `Header` set to `Forwarded`, and to `X-Forwarded-Host` (with `X-Forwarded-Proto` and `X-Forwarded-Prefix`, one message). In `OpenAPI`, a `Server` whose URL is empty; is `/`, which OpenAPI reads when `servers` is absent; ends with a slash, since every path of the document begins with one and a client would ask for `//rooms`; has a server variable (`{region}`), which is not built; has a query or a fragment; is neither an `http` or `https` URL nor a path that starts with a slash; has a host that is not one by rule 4 (a userinfo, a space); has a path that is not one by rule 4 (`/api/../admin`); or is given twice. **What cannot be caught before the first request:** a proxy that passes a client's `X-Forwarded-Host` through while the app set `ForwardedHost` (the app's word is believed, as the list of `Prefixes` is), and a `Servers` URL that is wrong for the deployment.

**Scenarios it was put against.**

- _A hostile client, direct_: sends `X-Forwarded-Host: evil.example` and `X-Forwarded-Prefix: /evil`, with and without trusted proxies. Its peer is not trusted, so `PublicHost` is its `Host` and `PublicPrefix` is `""` (`TestAClientTalkingDirectlyCannotNameThePublicHostOrPrefixWhateverItSends`).
- _A hostile client behind a balancer trusted only for `X-Forwarded-For`_ that passes `X-Forwarded-Host` through: `ForwardedHost` is false, so the header is not read (`TestAForwardedHostAndPrefixAreReadOnlyWhenTheAppSaysItsProxiesWriteThem`).
- _Two proxies_, a CDN and an ingress, both trusted, the client sending its own `X-Forwarded-Host`: an ingress that appends gives `evil.example, api.example.com` and one that adds a line gives two lines; both answer `api.example.com`, the nearest proxy's (`TestOfTwoProxiesTheForwardedHostAndPrefixAreTheElementsTheNearestWrote`). A chain in which every proxy appends the host it received answers the host the nearest one received, which is the edge's internal name: the nearest must be configured to pass the public one on.
- _A proxy that strips `/api`_ and writes `X-Forwarded-Host: api.example.com`, `X-Forwarded-Prefix: /api` and `X-Forwarded-Proto: https`: `PublicURL("/rooms/7")` is `https://api.example.com/api/rooms/7` while `Host` stays `chat.internal:8080` (`TestBehindAProxyThatStripsAPrefixThePublicURLHasTheForwardedSchemeHostAndPrefix`). The document says `servers: [{"url": "https://api.example.com/api"}]` or `[{"url": "/api"}]` from `Info.Servers` (`testdata/openapi/secured.json`, valid against the official OAS 3.1 schema in [`docs/research/openapi-valid/`](../research/openapi-valid/)).
- _An IPv6 host_: `[2001:db8::1]:8443` is kept with its brackets and port, and `2001:db8::1` without brackets, a zone and `[192.0.2.1]` fail and answer `Host` (`TestAnIPv6ForwardedHostKeepsItsBracketsAndPort`, `TestAForwardedHostThatIsNotAHostAnswersTheHostHeader`).
- _A hostile prefix through a proxy that passes it on_: `//evil.example`, `/\evil.example`, `/a/../b`, `/a/%2e%2E`, `/a?x=1` and `api` are `""`, so a `Location` built as `PublicPrefix() + "/rooms/7"` cannot point at another host (`TestAForwardedPrefixThatCouldNameAnotherHostOrClimbOutAnswersNoPrefix`).

**Tests** besides those named: `TestARequestKeptPastItsAnswerHasNoPublicHostPrefixOrURL`; in `examples/chat`, `TestBehindAProxyThatStripsAPrefixTheLocationAndTheDocumentsServersCarryThePublicURL`.

**The PROXY protocol** uses the same list (built in milestone 3, wave 2, [ADR 0058](0058-the-proxy-protocol-is-turned-on-per-listener-and-accepted-only-from-a-trusted-proxy.md)): a listener given `ProxyProtocol()` accepts a header only from a trusted peer, closes any other peer at accept, and the client the header names becomes the connection's peer, so `RemoteAddr` and the walk start from it. One list of trusted networks for both is one place to get it wrong rather than two.

**A Unix socket's peer** has no address to list, so it is trusted only when `TrustedProxies.UnixSockets` is set ([ADR 0058](0058-the-proxy-protocol-is-turned-on-per-listener-and-accepted-only-from-a-trusted-proxy.md)): the permission bits of `ListenUnix`'s socket file decide who may connect, and are the list. It is false by default; with it set, `Prefixes` may be empty, for an app whose only proxy is on its Unix socket. A trusted Unix peer's `X-Forwarded-For` is walked as any trusted proxy's, and `X-Forwarded-Proto` read.

**Refusals in `New`** (rows of `refusal_test.go`): `WithTrustedProxies` given twice; an empty `Prefixes` when `UnixSockets` is false; a zero (invalid) prefix; a prefix of length 0 (`0.0.0.0/0`, `::/0`), which trusts every peer and so lets any client name any address; a `Header` that is not a token. A prefix with host bits set is masked, not refused.

**What it costs.** Nothing unless `ClientAddr` or `Scheme` is called. A call scans the copied head as `Request.Header` does and parses with `netip.ParseAddr`, which allocates nothing for an address without a zone: 0 allocations, held by the test named below. `Prefixes` is checked linearly; a few dozen ranges (a CDN's published list) are a few dozen comparisons, and a longer list is a reason to build a table, not now.

**Scenarios it was put against.**

- _A hostile client, direct_: sends `X-Forwarded-For: 10.0.0.1`. Its peer is not trusted, so `ClientAddr` is its own address.
- _A hostile client behind the app's balancer_: sends `X-Forwarded-For: 1.2.3.4`, and the balancer appends the real address: `1.2.3.4, 198.51.100.9`. The rightmost untrusted element, `198.51.100.9`, is the real one; reading from the left would return `1.2.3.4`, the lie.
- _A CDN in front of a balancer_: both ranges must be in `Prefixes`. When the CDN publishes a new range and the list is stale, `ClientAddr` returns a CDN edge's address, and every client behind that edge shares one rate-limit bucket: coarse, but no client can choose its bucket. The rule fails closed.
- _Kubernetes ingress_: the ingress pods' range is trusted. A client inside the cluster that calls the service directly has a peer in that range and can name any address in its own `X-Forwarded-For`. Trusting a pod network trusts every pod in it, and the deploy guide says so.
- _Rate limiting_ (milestone 3): keyed by `ClientAddr`, so an attacker behind a correctly configured balancer cannot rotate its bucket with a header.

**Built in milestone 3, wave 1.** `WithTrustedProxies(TrustedProxies{Prefixes, Header})`, `Request.ClientAddr() netip.Addr` and `Request.Scheme() string` are in `proxies.go`, and the rules above hold as written, with these details the text did not settle. The peer and every element are unmapped first, so a dual-stack listener's `::ffff:10.0.0.5` is matched against `10.0.0.0/8`, and a prefix given in the mapped form (`::ffff:10.0.0.0/104`) is turned into its IPv4 one. An empty element (`a,, b`) is skipped, as a list header's empty elements are. A zone (`fe80::1%eth0`) is dropped. A single-address `Header` is read from its last line, the one the nearest proxy wrote; a value that does not parse answers the peer. `X-Forwarded-Proto` is read from its last line's rightmost element, the one the nearest proxy wrote, matched without regard to case. `Request.Scheme` is `https` on TLS the engine terminated whatever a proxy says; knowing that needed one method on the engine's exchange, `Exchange.IsTLS`, in a file of its own (`internal/engine/scheme.go`). Both methods answer zero values for a `Request` kept past its answer ([ADR 0022](0022-middleware-sees-a-request-view-and-returns-a-response-value.md)). The start-up log has a `trusted proxies` line. **The cost is 0 allocations**, held exactly by `TestClientAddrAndSchemeAllocateNothingBehindTrustedProxies` (`security_budget_test.go`): no proxy, a trusted peer with three elements and a port, a bracketed IPv6 element, and a single-address header, each 2 allocations a typed POST, the same as without. **Tests:** `proxies_test.go` (`TestAClientTalkingDirectlyCannotNameAnotherAddressWhateverItSends`, `TestBehindATrustedBalancerTheClientAddrIsTheRightmostUntrustedElementNotTheLeftmostLie`, `TestEveryLineOfARepeatedForwardedForIsReadWithTheLastLineRightmost`, `TestASingleAddressHeaderIsReadOnlyFromATrustedPeer`, `TestTheSchemeIsTheForwardedProtoOfATrustedPeerAndHttpOtherwise`, `TestTheSchemeOfARequestOverTLSIsHttpsWhateverAForwardedProtoSays`, `TestAPrefixWithHostBitsSetIsMaskedNotRefused`, `TestARequestKeptPastItsAnswerHasNoClientAddrAndNoScheme`), and rows of `refusal_test.go` for each refusal below plus a zero `netip.Prefix`, which the text did not list and which `netip` reports as invalid. Rate limiting by address keys on `ClientAddr` ([ADR 0055](0055-rate-limiting-is-a-token-bucket-per-key-with-a-bounded-store.md)), and HSTS is sent only when `Scheme` is `https` ([ADR 0053](0053-security-headers-are-one-middleware-with-safe-defaults.md)). A Unix socket peer has no address, so it cannot be listed; wave 2 decided that it is trusted only with `UnixSockets` (above, and [ADR 0058](0058-the-proxy-protocol-is-turned-on-per-listener-and-accepted-only-from-a-trusted-proxy.md)), which needed one method on the engine's exchange, `Exchange.PeerIsUnix`, beside `RemoteAddrPort`. The start-up line now says `unix sockets true` or `false` beside the prefixes.

**What it fails at.** A trusted range that also holds untrusted clients (the pod network above) lets those clients choose their address. A stale CDN list groups clients by edge. `ForwardedHost` is the operator's word that the proxy replaces the header, and nothing checks it. Behind two proxies that each strip a prefix, the nearest must write the whole prefix (`/api/v1`), since only its element is read. The same-origin check of a WebSocket handshake compares `Origin` with `Host` and with the forwarded host ([ADR 0046](0046-websocket-origins-and-inbound-limits.md)), so it believes `ForwardedHost` as `PublicHost` does; without it the public origin is listed with `AllowOrigins`, and the refusal fails closed. An allow-list of public hosts (`TrustedProxies.Hosts`), which would bound what a passed-through value could name, is not built (decided 2026-11-02): every proxy of the reference deployment replaces the header, and the list would be a second place to keep each public host; it is the answer when a deployment cannot vouch for its proxy. A balancer that passes `X-Forwarded-Proto` through lets a client choose the scheme of its own answers, and a shared cache in front of such a balancer could keep one. One app served under two public URLs lists both in `Servers`, and a client chooses. `Forwarded` and `X-Forwarded-Port` are not read; the port of a public host is in `X-Forwarded-Host`.

**What was rejected.** _Not reading `X-Forwarded-Host`, `X-Forwarded-Prefix` or `Forwarded` at all_, the position of 2026-11-01: an app behind a proxy that rewrites the host or strips a prefix wrote every `Location` with the internal host or without the prefix, and its API document could not name the public URL. What moved it: the reference deployment's ingress routes by path, so the example application's `Location` was wrong behind it, and with the reading turned on per header and the value checked, an app that does not turn it on pays nothing and is exposed to nothing. _Reading `X-Forwarded-Host` whenever the peer is trusted_, as `X-Forwarded-Proto` is: a balancer that passes it through hands the client the host of every link (rule 2). _Making `Request.Host` the public host_: it would change what `stdhttp` gives `http.Request.Host` and what the OpenTelemetry module records for every app, and hide the host this hop received, as overwriting `RemoteAddr` would hide the peer. _Walking `X-Forwarded-Host` from the right like `X-Forwarded-For`, or pairing its elements with `X-Forwarded-For`'s by position_: a host has no address to check, and positions shift when one proxy replaces a header that another appends to. _Joining every element of `X-Forwarded-Prefix`_ for a chain of stripping proxies: the elements on the left may be the client's. _Adding the prefix to a `Location` that starts with a slash_: the answer comes only from the return value ([ADR 0009](0009-the-response-comes-only-from-the-return-value.md)), a handler that already added it would get it twice, and a proxy that rewrites `Location` itself would add it again. _A precedence between `Forwarded` and `X-Forwarded-*`_ (rule 5). _A document built per request with the forwarded host as its server_ (rule 6). _A relative server URL computed from the document's path_ (`.` for `/openapi.json`), which would make the document right behind any prefix with no configuration: how the tools that read the document join a relative server with a path was not measured, so it is not built. Reading `X-Forwarded-For` from the left, which returns whatever the client wrote first. Trusting a number of hops instead of networks: a hop count is right only while the topology does not change, and a removed proxy turns it into a spoofable read. A middleware that overwrites `RemoteAddr` from a header: it hides the peer, and an app that adds it without a list believes every client. Trusting every peer by default, and allowing a `/0` prefix with a warning: both make the header the client's to write. What other Go frameworks do by default (Gin trusting every proxy, chi's `RealIP` reading headers unconditionally) is a claim to confirm with a probe under `docs/research/`, not a reason for this rule.
