# An error that carries data states its type with ErrorStatus[T] and sends it with WithMembers

A `409` can carry the data a client needs to recover: a stale batch of edits answers with the Blocks as they are now, so the editor rebases without another request (Athena's `POST /docs/{id}/ops`, `bites-feedback.md`, "A 409 that carries data"). [ADR 0049](0049-errors-are-found-with-errors-as-and-timeouts-wait.md) gave `StatusError.With(name, value)` for such a member and [ADR 0069](0069-the-api-document-states-what-a-routes-providers-and-middleware-ask-and-answer-and-a-route-can-be-left-out.md) gave `ErrorStatuses(409)` for the status, but the two did not meet: the document listed the 409 as the shared `Error` response, so a client generated from it knew nothing of the members, and nothing failed when the server's shape and the client's drifted apart. The value of a member was also written by `encoding/json/v2` and not by the codec that writes every response, so a struct in it needed its own `json` tags for snake case and a `bites.Opt` in it was written as a struct, not left out when empty. Both broke the second principle (a client reads the document, and the same type must come out the same way on the wire as in a success) and the first (the document is where an agent reads what an endpoint returns).

**Decision.**

- **`ErrorStatus[T any](status int)` is a route option that states an error status together with the type of its members.** The document's response for that status is `application/problem+json` whose schema is `allOf` the problem's own members (`title`, `status`, `detail`, `request_id`) and the schema of `T`, built by the same Registry as a success body, so `T` is a named component with the wire names of its fields. It is the typed form of `ErrorStatuses` for one status: `ErrorStatuses(404, 412)` stays for statuses whose answer is the problem alone, and `ErrorStatus[T](409)` is for a status that also carries data. On one route the two never name the same status (the typed response wins where both are given, so a group's `ErrorStatuses(409)` and a route's `ErrorStatus[T](409)` are fine). Given to a group it covers every route of the group.
- **`WithMembers[T any](e *StatusError, members T) *StatusError` attaches the data.** Go has no generic methods, so it is a function, not `e.WithMembers(v)`. The fields of `T` become top-level members of the problem body, after `detail` and before `request_id`, written by the response codec of the app: wire names by its naming policy, `Opt` left out when empty, the same rules as for a success. A `T` whose fields are all empty adds nothing.
- **`With(name, value)` stays, for a member that is not a type the client reads**: a machine-readable `code`, a flag, set by a mapper (`WithErrorMapper`) that knows no route. Its value is now written by the same codec (a type the codec refuses falls back to `encoding/json/v2` and is never lost), so there is one way to write a value and the docs say which API states it: `With` is not in the document, `WithMembers` with `ErrorStatus` is. The names `title`, `status`, `detail` and `request_id` are the problem's and a member of that name is left out and logged (it was left out silently for the first three, and `request_id` was written twice).
- **A clash is refused at Registration.** `ErrorStatus[T]` refuses a field of `T` whose wire name is `type`, `title`, `status`, `detail`, `instance`, `errors`, `truncated` or `request_id`, naming the field's wire name and the fix (a json tag). `type` and `instance` are RFC 9457 members the framework does not write today and reserves, so a later release can write them without breaking an application; `errors` and `truncated` are the 400's list. Also refused, each with a row in the refusal table: a status outside 400 to 599; `400`, `401` and `429`, which the framework answers in shapes of its own (the Input's list, the challenge and the rate limit's headers); a status the framework already answers on that route (`413`, `415` on a route with a body); a `T` that is not a struct or cannot be written as JSON; a status named twice on a route and its groups; the option on an `Undocumented` or static route.
- **A mismatch at run time is reported in the log, where an agent reads it.** The app keeps the pairs of status and type that routes state. An error that carries members of a type no route states for that status is still sent, and logged at `WARN` with the option to add (`give the route ErrorStatus[pkg.T](409)`). `WithMembers` of a value that is not a struct, or one the codec cannot write, is left out and logged at `ERROR`, because the handler asked for data the client will not get. It is app-wide and not per route: an error does not know the route that returned it (a Provider's and a middleware's errors are answered by the same function), and the common mistake, forgetting the option, is found either way.
- **Cost.** A success pays nothing: no field or step is added to any success path. An error answer with members pays for a `sync.Map` lookup of the type's plan (filled at Registration for a stated type, compiled once for another), one copy of the value (`reflect.New`) and the encoder's append into the pooled response body. Measured on 2026-11-09 with `testing.AllocsPerRun` over 200 requests through `bitetest` (the harness's own allocations included, so only the difference means anything): an error with no member 63, `With("code", "k")` 65, `WithMembers` of a struct with one list entry 64. The error path is not one of the guarded axes of [ADR 0003](0003-the-trade-budget.md); the typed JSON request (2 allocations) and the idle connection are unchanged and `budget_test.go` passes.

**What it fails at.** `ErrorStatus` states and does not check, as `ErrorStatuses` does: a handler that returns members of another type for the status is sent as it is and logged, not refused, because Registration cannot see what a handler returns. The run-time warning is per app: a route that states the type for a status where another route returns it by mistake is not warned about. A `T` with a field named `type` or `instance` is refused although the framework does not write them today; that is the price of reserving them. A `T` that embeds the problem's own members under other wire names (a `Title` renamed `heading`) passes, and is the application's choice. A client generator that does not support `allOf` with an inline schema reads the response as the problem alone, which is what it read before.

**What was rejected.**

- **`With` taking the type** (`With(name string, value any)` plus a stated type in the option): the document would still be a second place to keep in step with the value, and `ErrorStatus[T]` with a bare `With` would not tie the value's type to the stated one. A typed value passed to a function whose type parameter is the stated type is the one thing an agent can check by reading the two names side by side.
- **`ErrorStatus[T]` replacing `ErrorStatuses`**: two spellings of the same option would be one too many, and most error statuses carry no data. They stay separate because they say different things, a status and a status with a schema, and the second refuses what the first allows.
- **A method `e.WithMembers(v)` or `ErrorStatus` taking a value** (`ErrorStatus(409, StaleBlocks{})`): Go has no generic methods, and a value in an option invites a populated one that is never used.
- **Reading the stated type at run time to refuse a mismatch with a 500**: it would turn a missing option, a documentation mistake, into a failure the client sees, and the errors that matter most (a conflict) are the ones a client needs. A log line the agent reads is the cost the mistake deserves.
- **A registry of problem types by `type` URI** (the full RFC 9457 model): it is a second system beside the status, for a need one option meets. Reopen if an application wants several shapes under one status.
- **Making `With` typed too** (`With[T]`): impossible as a method, and a function beside `WithMembers` would be the second spelling this ADR removes.
