# The core carries W3C trace context and records no span

With `WithTraceContext(TraceContext{Begin})` the app takes part in W3C Trace Context: it reads a request's `traceparent` and `tracestate`, gives the request a span id of its own, and hands the result to everything that runs for the request through `TraceFrom(ctx)`. It records no span and sends nothing back; recording is the OpenTelemetry module's, which builds on this through the Observer of [ADR 0051](0051-a-request-is-observed-when-it-starts-and-when-it-has-really-ended.md). Decided and built on 2026-11-01 for milestone 3 (`trace.go`, `trace_test.go`).

```go
type Trace struct {
	ID     TraceID // the trace, as the caller sent it, or new when it began here
	Span   SpanID  // this request's span, generated for each request
	Parent SpanID  // the caller's span (the parent-id it sent); zero when the trace began here
	Flags  byte    // trace-flags as received, bit 0 sampled; 0 for a trace begun here
	State  string  // tracestate as received, lines joined with ","
}

func TraceFrom(ctx context.Context) (Trace, bool)
func (t Trace) Child() Trace          // an outgoing call: same trace, new span, Parent = t.Span
func (t Trace) Traceparent() string   // "00-<ID>-<Span>-<Flags>", the header for that call
func ParseTraceparent(v string) (Trace, bool)
func ContextWithTrace(ctx context.Context, t Trace) context.Context
func (r Request) SetTrace(t Trace)    // a tracer's Observer replaces the span with its own
```

**The rule.**

- _Read once, before anything else of the app._ The header lines are scanned when the request reaches the app, after `WithHealth` ([ADR 0052](0052-health-and-readiness-follow-shutdown.md)) and before any Observer's Start or middleware, so every one of them sees the same trace. A valid `traceparent` is one line (two lines are not a trace) of version 00 at exactly 55 bytes, or a later version that may carry more after a further `-`, with lower-case hex, a trace id and a parent id that are not all zeros, and a version that is not `ff`, as the specification says. A later version's flags keep only sampled and random (0x03); the app always sends version 00.
- _Invalid or absent._ No trace, and the `tracestate` is dropped with it, as the specification says. With `Begin` the request begins a trace instead: a new random trace id, no parent, flags 0.
- _A span of its own._ Each request gets a random 64-bit span id, never zero (`math/rand/v2`), so two requests of one trace are told apart, and `Child()` gives an outgoing call a further one with this request's span as its parent. `Traceparent()` writes the header for the call; `tracestate` is passed on as `State`.
- _Where it lives._ The trace is written as hex (the ids and the flags, 66 bytes, then the tracestate) into the request's slab and the request's context points at it, so it is the request's own memory ([ADR 0008](0008-no-pooled-object-reaches-the-user.md)): `TraceFrom` works for Providers, middleware, the handler, an Observer's Start and End, and a goroutine that kept the context after the request; a derived context (`WithValue`, `WithTimeout`) finds it the way `Cause` finds the request's cause ([ADR 0016](0016-the-handler-context-is-cancelled-on-disconnect.md)). Hex rather than bytes so that a log line slices the two ids out of it without allocating.
- _A tracer sets its own._ `Request.SetTrace`, from an Observer's Start or a middleware before `next`, replaces the request's trace (a zero ID or Span removes it), so the OpenTelemetry module's Start does: read `TraceFrom(ctx)` (or `ParseTraceparent` of the header, without this option), start a server span whose remote parent is `ID` and `Parent`, make its sampling decision, `SetTrace` with its own span id and flags, and return the context holding its span; its End names the span from `Outcome.Route` and ends it. Log lines and `TraceFrom` then name the span it records.
- _Outside a request._ `ContextWithTrace` gives `TraceFrom` a trace for work that is not a request, a job read from a queue beside its traceparent.
- _What is answered:_ nothing. No `traceparent` or `traceresponse` header, no member of a problem+json. _What is logged:_ `AccessLog` adds `trace_id` and `span_id` ([ADR 0032](0032-four-first-party-middleware.md)); the engine's own lines (a panic's stack) do not, since the engine never reads the trace.

**What it costs.** Without the option, one boolean test a request. With it, a scan of the header lines for two names, the parse of 55 bytes, one or three random numbers, and 66 bytes plus the tracestate in the slab, which is sized for it before it is made: **measured 0 allocations**, the typed JSON POST staying at 2 with a valid traceparent and two tracestate members, behind middleware, with `Begin` and no traceparent, and with neither (`TestATypedJSONPOSTWithATraceContextStillAllocatesTwice`). `AccessLog` with the two ids is 3, the same as with a request id, because a `slog.Record` holds five attributes inline (`TestAnAccessLogWithATraceCostsWhatTheTableOfADR0059Says`). The request's context gains one string field for every app, with or without the option: it was 152 bytes and is 168, which moves it from Go's 160-byte size class to the 176-byte one, **16 bytes more allocated a request** (arithmetic from `unsafe.Sizeof` and the size classes, not a run); the count of allocations, the guarded axis of [ADR 0003](0003-the-trade-budget.md), is unchanged, and so is memory per idle connection, since the context is not held between requests. `SetTrace` allocates its encoding, one string, which is the tracer's cost; `ContextWithTrace` allocates the context it returns. Throughput and p99 are not measured yet; they wait for the serial run of wave 2.

**Refusals** (rows of `refusal_test.go`): `WithTraceContext` given twice, naming both places. **What cannot be caught before the first request:** a malformed `traceparent` is the client's and is ignored as the specification says; an Observer that reads `TraceFrom` in its Start before a later Observer's `SetTrace` sees the trace from the header, which is the order the application gave.

**Scenarios it was put against.**

- _The reference workload_ ([ADR 0002](0002-the-reference-workload.md)) behind an ingress that sends `traceparent`: a handler's query passes `ctx` to pgx, whose tracer finds the trace with `TraceFrom` through the contexts pgx derives; the access record carries `trace_id`, so one search finds the ingress's, this service's and Postgres' records; a call to another service sends `TraceFrom(ctx).Child().Traceparent()`. An SSE stream's record has the trace of the request that opened it.
- _A WebSocket_: the handshake has the trace; a message does not, since `OnMessage` gets the socket's own context ([ADR 0047](0047-a-socket-is-a-handle-and-a-topic-is-a-broadcast.md)). Carrying the handshake's trace into the socket is a later decision.
- _A hostile client_ that sends a malformed `traceparent`, two of them, upper-case hex or zero ids: no trace, nothing logged, no error. One that sends a 7 KiB `tracestate` in many lines: it is bounded by the head limit and the field limit ([ADR 0024](0024-limits-are-on-by-default.md)) and copied into its own request's slab, so the client pays for it in its own request. One that sets the sampled flag on every request: the flag is passed on, as the specification has it, and a downstream parent-based sampler records what the client asked for.
- _A goroutine the handler started_ that outlives the request and logs with the context: the trace is still there (`TestTheTraceIsSeenByObserversMiddlewareProvidersAndAContextKeptAfterTheRequest`).
- _The OpenTelemetry module_ given before `AccessLog`: its Start runs first and `SetTrace` changes the context's trace, which `AccessLog` reads at End, so the record names the module's span (`TestAnObserverThatSetsTheTraceIsWhatTheHandlerAndTheAccessLogSee`).

**The OpenTelemetry module is built** ([ADR 0063](0063-opentelemetry-is-a-module-whose-observer-records-the-server-span-and-names-it-to-the-core.md), milestone 3 wave 2), as the rule above describes: `otel.Tracing` reads `TraceFrom` or, without this option, `ParseTraceparent` of the header, starts the server span with the caller as its remote parent, and calls `SetTrace` with the span's ids, so `TraceFrom`, `Child()` and `AccessLog` name the span it records.

**What it fails at.** The core records no span, so until the OpenTelemetry module is used a trace that passes through this service has a gap where it was, and the outgoing call's parent is a span nobody recorded. A trace begun here with `Begin` has the sampled flag clear, so a downstream parent-based sampler records none of them; an edge service that wants its traces recorded uses the module, which samples. An edge service facing the internet lets clients choose the trace id and the sampled flag; restarting the trace at the edge is not an option yet. `tracestate` is carried as received, without checking its members or their limit of 32, since the core never reads it. Every request allocates 16 bytes more for the context's new field, also in an app that never traces. The engine's panic line has no `trace_id`. An `OPTIONS *` and the health probes are answered before the trace is read.

**What was rejected.** Reading the trace on every request without an option: the scan and the random span are paid by apps that do not trace, and whether to begin a trace has no answer that suits everyone. An Observer that reads the header and sets the trace: the Observers before it would not see the trace in their Start, and the order would become something to get right. `context.WithValue` for the request's trace: two allocations a request (the context and the boxed value). A pointer to a `Trace` on the request's context: one allocation a request. The ids as bytes in the context: a log line would format them and allocate. A `traceresponse` header: it is a draft of Trace Context level 2, and it tells an internet client the ids of internal spans. The trace id in problem+json: `request_id` already finds the request ([ADR 0012](0012-client-errors-are-400-problem-json.md)), and a trace id names records of other services too. Beginning traces with the sampled flag set: every downstream parent-based sampler would record every request that began here. The OpenTelemetry API in the core: a third-party dependency ([ADR 0006](0006-no-third-party-dependency-in-the-core.md)).
