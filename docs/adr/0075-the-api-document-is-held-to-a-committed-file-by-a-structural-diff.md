# The API document is held to a committed file by `bitetest.Document`, which fails with a structural diff and is updated by an environment variable

`bitetest.Document(tb, app, "testdata/openapi.json")` takes the bytes of `App.OpenAPIDocument` ([ADR 0027](0027-an-in-memory-entry-point-runs-the-engine-path.md)), writes them in a canonical form, and fails the test when the file differs. It exists because the contract a client is built from changes in ways nobody meant to change it: a property that becomes nullable and required, a `default` that is lost, a component renamed, a field whose schema becomes `{}`, a header documented that no route sets. Three spikes found these only by a diff script written again each time, and one test dumped `/openapi.json` through the server, wrote a 401 body to the file and passed.

**The document never comes through the server.** `Document` calls `App.OpenAPIDocument`, so a middleware that answers the document route with a 401 cannot put its body in the file, and an App without `OpenAPI` fails the test with the method's own message.

**The canonical form is JSON with keys sorted, two-space indentation and one trailing newline** (`jsontext.Value.Canonicalize` then `Indent`). A file edited by hand into another layout is not accepted silently: when it holds the same document, the failure says it is not in the canonical form and how to rewrite it, because a diff that is empty for the reader and non-empty for the byte comparison would otherwise be a failure with nothing to read.

**A mismatch is a list of changes, not a byte diff.** `bitetest.DiffDocuments(before, after)` returns one line per change in a fixed order: object keys sorted, depth first, array elements by index. A line is a JSON Pointer ([RFC 6901](https://www.rfc-editor.org/rfc/rfc6901), so `/paths/~1users`) and `-` (only in the file), `+` (only in the app) or `~ old -> new`. A value is shown as compact JSON cut at 80 bytes. An added or removed object is one line, not one per member. `Document` prints the first 40 lines and the count of the rest. The function is exported because it costs nothing extra (`Document` is built on it) and a caller comparing two builds of an App, the one before a refactor and the one after, has no file to hold.

**The update is `BITETEST_UPDATE=1`, an environment variable.** A flag registered by `bitetest` would be defined in every test binary that imports it, and a package that already has its own `-update` (this repository's `docs_test.go` has one) would panic on the redefinition; and `go test ./... -update` fails in every package that does not link `bitetest` with "flag provided but not defined". An environment variable reaches every package of one `go test ./...` and needs no declaration. The failure message prints the exact command, naming the test.

**A file that does not exist yet fails the test; it is not written.** Writing it would make the first run in CI pass by recording whatever the app answered, which is the vacuous pass this helper is built against, and a deleted file would silently re-bless the contract. The cost is one extra command the first time, which the message gives. Under `BITETEST_UPDATE=1` the directory is made and the file written.

**Axes:** none; test support, outside the request path. **Its refusals:** none at Registration; it fails the test for an App without `OpenAPI`, a document that cannot be built, a missing file, an unreadable or non-JSON file, and a difference.

**What it fails at.** Numbers are compared as `float64`, so two integers above 2^53 that differ only in the low bits compare equal in the diff (the byte comparison still sees them, and the failure says the layout differs). An array is compared by index, so an element inserted at the front reads as a change to every element after it; OpenAPI's arrays that matter (`parameters`, `servers`, `required`) are short. It does not know which changes break a client: a removed property and an added one are both lines, and judging them is the reader's.

**What was rejected:** writing a missing file (above); a `-update` flag (above); a byte diff of the two files (a one-line change in a minified or reordered document is unreadable, and key order is not a change); a semantic classifier of breaking changes (a project of its own, and a wrong "compatible" is worse than a plain list); comparing the response of `/openapi.json` (the silent 401 above).
