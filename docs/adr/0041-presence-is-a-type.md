# Whether a field may be absent or null is said by its type, and a pointer in an Input is refused

The same rule holds in every section of an Input ([ADR 0010](0010-one-input-struct-with-sections-by-field-name.md)):

- **A plain field is required.** A request without it is a 400 that says `required` at its location.
- **`Opt[T]` may be absent.** `in.Query.Page.Or(1)` reads it with a default; `in.Query.Page.Get()` says whether it was sent.
- **`Null[T]` may be `null`.** A required field that is sent as `null` is otherwise a 400. The zero `Null[T]` is null and `NonNull(v)` makes one with a value; the zero `Opt[T]` is absent and `Some(v)` makes one present.
- **`Opt[Null[T]]` is the PATCH field:** absent leaves the stored value alone, `null` clears it, a value sets it.
- **A plain field with a default is optional on the wire and never absent in the handler** (2026-11-03). A text Section's struct (`Query`, `Header`, `Cookie`, or the `T` of a `Form[T]`) may have the method `Defaults() map[string]string`, which says by Go field name what an omitted field means, written as a client would send it: `{"Limit": "50", "Sort": "risk"}`. The field stays a plain `T`, so the handler reads `in.Query.Limit` with nothing to `Or`, and the API document says `required: false` with `default: 50` in the parameter's schema, from the same entry. The type still says what the handler sees (a value, never an absence); the Defaults method says whether a client may leave it out. An `Opt[T]` is for a field whose absence the handler acts on, and a field cannot be both: a default on an `Opt` is refused.
- **A pointer in an Input is refused at Registration**, with a message saying to use `Opt[T]` or `Null[T]`, because a pointer cannot say whether `nil` meant absent or null.

**Pointers are still refused in an Input, and `Opt` converts to and from them at the boundary.** A service layer often speaks `*T` (a nullable column, a generated client), and writing `if v, ok := o.Get(); ok { p = &v }` at each call is the part of a port nobody enjoys. `Opt[T].Ptr()` returns nil when the value was not sent and a pointer to a copy when it was, and `OptOf(p *T)` makes an `Opt` from a pointer, absent for nil. Both copy, so a pointer taken from an `Opt` is the caller's own and writing through it changes nothing in the Input, which keeps ADR 0008's rule that nothing the framework pooled is aliased. They exist for the conversion only: the Input's field is still an `Opt`, because a pointer field still cannot say whether `nil` meant absent or null. There is no `Null` counterpart yet, because a `*T` has one nil and `Opt[Null[T]]` has two states to map it onto, which is a choice for the caller.

`Opt` is a field type only: an `Opt` as a list element, a map value or a type argument anywhere but a struct field is refused at Registration, because absence means nothing there. A `json:",omitempty"` tag does not make a field optional in a request; only `Opt` does, so one rule says what may be absent.

In an Output, an empty `Opt` is left out of the JSON and a `Null` is written as `null`; pointers are allowed there and `nil` is `null`. The API description's `required` and `nullable` come from these types, so it cannot disagree with the code.

**What it costs:** an API whose query parameters are nearly all optional writes `Opt` on nearly every field (`Expand Opt[bool]`), and a model type full of pointers, often shared with a database layer, cannot be an Input as it is. Separating the request's type from the table's is the cure, and usually the better design anyway.

**What was rejected: no way out for a `*T` service.** Until 2026-11-03 the reference said to convert by hand. An application whose services take and return `*T` writes `Ptr` and `OptOf` itself in its first file and calls them every few lines.

**Considered:** optional by default with zero values, as Huma does for query parameters, which reads shorter but lets a missing `page` silently become 0; and pointers for optional fields, as encoding/json users do, which cannot express PATCH.

**How a default is held, and what it is checked against.** The entry is text, decoded by the field's own text decoder, so a default is checked by exactly the rules a client's value meets: `Range`, `Length`, `Values`, `Pattern`, `Check`, `Date`, `uuid.UUID` and a `TextUnmarshaler` all apply, and a default its type refuses is a Registration panic naming the field, the text and the type's own sentence. The same decoder fills the field on each request that omits it, so no value is shared between requests (ADR 0008), a default is not a second spelling of the type's rules, and a field the Defaults method does not name is exactly as required as before. The cost is that the text is parsed on each such request: a built-in type allocates nothing, so a typed GET that takes four defaults still allocates twice (`TestATypedGETThatTakesFourDefaultsAllocatesTwice`), and a `TextUnmarshaler` costs what it costs a sent value ([ADR 0042](0042-text-values-are-decoded-by-type.md)).

**Where it is read and where it is not.** The method is read on the Section's struct and on every struct it embeds, with the rule of `Descriptions` and `WireNames`: each embedded struct states the defaults of its own fields, the Section's own method wins for a field both name, and a name that is a field of nothing is refused. That is how one `Paging` shared by two routes has a default `limit` of 20 on one and 100 on the other: the second route's Section embeds `Paging` and states its own `Limit`. It is not read in `Path` (a path parameter is always present; refused), for a list or a `CSV` (one shared slice or one copy per request; refused), for an `Opt` (refused), or in a JSON `Body` (refused: the codec does not read it, and a method accepted and ignored would leave required a field its author wrote a default for; use `Opt` and `Or`, or a `Form[T]`). A value sent badly, `?limit=` or `?limit=x`, is a 400 and never falls back to the default: the client said something.

**What was rejected: a default stated by a route option, and a `Default()` method on the type.** Until 2026-11-03 this paragraph said "considered and not built" ([`docs/research/defaults-on-route/`](../research/defaults-on-route/report.md)). A route option `Defaults(func(in *In){ in.Query.Limit = 50 })` was prototyped: Registration ran it on a zero and on a poisoned Input and took the fields both runs left alone as defaulted. It failed where this ADR is strongest: a type the poison could not reach (a `[16]byte` UUID) was reported as defaulted to its zero value though nothing mentioned it, so a required field silently became optional; a zero default looked redundant and was load-bearing; a default frozen at start went stale; a slice default allocated or aliased; and it moved whether a field may be absent from the field's type to a route option. A `Default()` method on the field's type was rejected too, because a default belongs to the Section and not the value (one `Paging` had defaults of 20, 25, 50 and 100 in the application it came from) and a PATCH body shares its field types with a create body. The reopening condition recorded then was a client generator that needs `default`, and a way to make the unreachable type a Registration refusal. Both came: an API moved from Huma lost `default: 50` on a `limit` and a default on a `sort` from its document, and the new design never infers a default, it reads a named entry and decodes it with the decoder the field already has, so there is no type it cannot reach. A zero default is a visible entry (`"Archived": "false"`), and deleting it makes the field required, which a test that omits it fails loudly. A dynamic default (`start of today`, `now-24h`) cannot be written as text and so cannot go stale; a handler that wants one keeps an `Opt` and computes it.

**What a default still fails at.** It is not for the body, so a create body's `visibility = private` stays `Opt` and `Or` until the codec reads it. A `Check` that depends on the clock can refuse at request time a default that passed at Registration; the answer is a 400 at that field, loud and not silent. A default that disagrees with a `Descriptions` sentence ("defaults to 20" in prose and `"50"` in the entry) is two places again: the sentence should be dropped, since the document now states the value.

**`Opt.Set` is a reflection hook, not a third constructor.** `func (o *Opt[T]) Set(v T)` makes an `Opt` present holding `v`, so a decoder that fills an `Opt` through `reflect` (the configuration module, [ADR 0080](0080-configuration-is-a-module-that-fills-a-typed-struct-from-flags-environment-and-files.md)) can reach it; application code still builds an `Opt` with `Some` or `OptOf`.
