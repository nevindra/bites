# A store is held to its interface by a conformance suite in bitetest

`RateLimitStore`, `SessionStore`, `OwnerSessionStore` and `Broker` are interfaces whose doc comments carry promises the type system cannot check: a `Take` atomic for a key, a `Load` that never returns an expired session, a `DeleteOwner` that keeps nothing of an owner when `keep` is another owner's id, a payload over the limit that is an error and is never cut. Each is implemented outside the core (the modules `pgsession`, `pgnotify` and `pgratelimit`, a Redis module later, an application's own store), so each implementer reads the comment and writes tests from it, and each misses a different promise. An agent writing a store sees only the doc comment ([principle 1](0077-four-principles-in-the-order-they-win.md)). Decided on 2026-11-05 and built (`bitetest/stores.go`).

**Decision.**

- **`bitetest` has one suite for each interface**, an exported function a test calls with a `*testing.T` and a factory, so it names itself where an agent looks (`go doc ./bitetest Test`): `TestRateLimitStore(t, newStore)`, `TestSessionStore(t, newStore)`, `TestOwnerSessionStore(t, newStore)` and `TestBroker(t, BrokerSuite{...})`. Each runs one subtest for each promise of the interface's doc comment, named as a sentence about behaviour, so a failure says which promise broke. `bitetest` imports the standard library and `bites` only.
- **The factory takes `*testing.T` and is called once for each subtest**, and must return a store with no state of any earlier one (a new table, a new channel, a new prefix); it may call `t.Cleanup`. A suite that shared one store would make a subtest depend on the order of the others, and the one-table-a-test pattern is what the modules' tests already use. A `Broker` needs two that reach each other, so `BrokerSuite.New` returns the pair, and the suite's other fields say what the Broker cannot be asked: the names `Accepts` must refuse (`Refused`), the largest payload (`MaxPayload`), whose over-limit error must be a `*bites.PayloadError` with that `Name`, the size and a `Limit` of exactly `MaxPayload` (ADR 0081; a text to look for was the first form, which let a broker keep returning a plain error); with none given, those subtests are skipped, which `bitetest.Broker` has no limit to test. A struct and not four parameters because the suite will grow a field when a Broker has one more thing to say, and an unnamed list of arguments would not.
- **`TestOwnerSessionStore` checks the owner half only and `TestSessionStore` the rest; a store calls both.** A store written only for owned types may return an error from `Save` ([ADR 0056](0056-a-session-is-sealed-in-a-cookie-and-changed-by-returning-its-cookie.md)), and the owner suite then must not call `Save`; one suite that did both would make that store unable to pass either. The reference says to call both.
- **`TestOwnerSessionStore` takes one optional `OwnerSessionSuite` for a store that cannot take the owners the suite would choose.** Its `Owner(t, s, name)` returns the owner to save under for each of the eight names the suite uses; it is called in each subtest after `newStore`, with that subtest's store, at most once a name, so the caller creates the real row (a users row the owner column refers to) there. The suite fails the test, with a message saying what to change, for an empty owner, for two names given one owner, and for more than one `OwnerSessionSuite`. `NoEmptyOwner` skips the subtest about an empty owner, with the reason in the skip (nothing is skipped in silence, [principle 2](0077-four-principles-in-the-order-they-win.md)); the store then cannot keep an anonymous session, the application's `SessionOwner` must never return "", and `NewSessions` cannot refuse that since the owner is read from each value at `Save`, so the documentation says it where the switch is read. The zero call is unchanged. A variadic struct and not a second function, so there is one name to find and, like `BrokerSuite`, a field is added when a store has one more thing to say.
- **No sleeping except where the promise is about the real clock.** The rate limit suite gives `Take` its own `now` and moves it, so it needs no sleep and proves the store decides with the `now` it is given. The session suites judge expiry on `bites.Now(ctx)` ([ADR 0082](0082-a-postgres-session-store-is-a-module.md)): each subtest gets a context that carries an app on a `bitetest.Clock` (the context of a Service's `Start` in an app started with `bitetest.Start`, which `bites.Now` already reads, so the core gains no exported name), gives expiries relative to that clock and moves it with `Advance`, so they never sleep and a store that reads the wall clock fails at once, the fake clock being in 2026. The broker suite waits on a channel for a delivery (up to 5 s) and listens 100 ms for one that must not come.
- **What the suites pin is the doc comment and nothing past it.** Where a comment is silent they do not choose: a payload that is not JSON is not published (a Broker over Postgres text cannot carry it, and a Topic's payload is JSON), a session owner with a NUL byte is not saved (an owner is a User's id), a `Take` with a burst under one is not made, and a `Save` over an owned id is not asserted to clear the owner (the comment says "replacing what id had"; `pgsession` does). Durations are compared to within a millisecond, which a store that keeps milliseconds meets.
- **The core runs the suites against what it has**: `bitetest.Broker`, the in-memory buckets of `RateLimiter` through a test-only adapter, and a test session store; `pgsession`, `pgnotify` and `pgratelimit` run them against Postgres when `BITES_PG_URL` names one ([ADR 0082](0082-a-postgres-session-store-is-a-module.md), [ADR 0085](0085-a-postgres-rate-limit-store-is-a-module.md)).

**What they found.** The in-memory store of the core's session tests answered `DeleteOwner("", keep)` with the sessions saved with no owner, which the interface says no one reaches: the test store was given a wrapper that holds it (it is not shipped). `pgsession`, `pgnotify` and the in-memory buckets and `bitetest.Broker` passed on the first run, except that `pgsession.SaveOwned` returns Postgres's error for an owner with a NUL byte (a `text` column cannot hold one); the doc comment now says so, and the suite does not test it.

**What it costs** ([ADR 0003](0003-the-trade-budget.md)): none for the core's request path; it is test code in a package an application imports only in tests. The two guarded axes do not move.

**Refusals.** A nil factory fails the test with a message that says what to give; so does an `OwnerSessionSuite` whose `Owner` returns an empty or repeated owner, and more than one of them. Nothing is refused at Registration: a suite is called from a test.

**Scenarios it was put against.**

- _A store written by an agent from the doc comment alone_: a `Take` that reads, decides and writes in three statements passes every sequential subtest and fails `two callers never both get the last request of a key`, which is the promise an agent is most likely to break and the hardest to see by reading.
- _The Postgres modules_: each runs its suite against a real database in its own tests, so a change that breaks a promise fails there, not in an application.
- _A store with a different notion of time_ (a Redis script with `TIME`): fails the subtests that move `now`, which is the point, since a limiter measures on the app's clock ([ADR 0055](0055-rate-limiting-is-a-token-bucket-per-key-with-a-bounded-store.md)).

**What it fails at.** It cannot prove atomicity, only fail to find a break: the concurrent subtests run 60 rounds of 8 callers and a burst of 40, which catches a read-modify-write on a database and may miss a window narrower than that. A promise whose test needs a fault (a `Broker` that loses its connection and calls `gap`) is not in the suite, since the factory has no way to cause one; each module tests it itself. A store that changes the clock it keeps (a rounded `Reset`) is held to a millisecond, not exactly.

**Considered and what was rejected.**

- **A test file in each module with its own copy of the promises:** what exists, and each copy differs and drifts from the comment.
- **A table of cases in the docs only:** not run, so it is wrong the day a comment changes.
- **A separate module or `internal/` package for the suites:** an application and a module outside this repository could not call it; `bitetest` is already where an application's tests look.
- **One suite function that takes a store and detects the interfaces it implements:** the `OwnerSessionStore` case would run `Save`, which a store written only for owned types does not support, and the type switch hides what is being checked from a reader.
- **A session suite that sleeps for an expiry in the real near future** (what it did: about 1.7 s once, because expiry was the store's own clock): slow, and it let a store judge expiry on a clock that disagrees with the cookie's; `bites.Now(ctx)` is the one clock, so the suite moves it.
- **Owners as a list in the suite (`Owners []string`):** the store of each subtest is new, so a row made once before the suite is not in it; a function called per subtest with the store is the smallest thing that works for a table made per subtest.
- **Owners generated by the suite alone:** a store whose owner is a UUID or a number cannot take "alice" or "café", so the caller must choose.
- **No switch, the suite always saving an empty owner (what it did):** a store whose owner column is a foreign key could not be held to the contract at all, and refusing an empty owner is a real design (an application with no anonymous sessions).
- **Failing instead of skipping the `Broker` subtests with no limit given:** `bitetest.Broker` has none, and a suite that cannot pass the reference implementation of the interface is not usable.
