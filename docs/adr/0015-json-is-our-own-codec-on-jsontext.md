# JSON is our own codec, built per type at registration on top of jsontext

Each Input and Output type is compiled at Registration into a plan: for every field its wire name ([ADR 0011](0011-one-naming-policy-for-wire-names.md)), its kind and its offset. Decoding reads tokens with the standard library's `encoding/json/jsontext`, so the JSON grammar, UTF-8 validity and duplicate names are still checked by the standard library, and fills the value through the plan. Encoding writes through the plan into the connection's write buffer.

**What the codec does that encoding/json/v2 cannot** (probed on Go 1.27.2, [`docs/research/facts/`](../research/facts/report.md)):

- **Wire names without tags.** v2 has no naming option; `MatchCaseInsensitiveNames` helps input only, and a marshaler hook cannot rename the members of the default struct encoding.
- **Every error, not the first.** v2 stops at the first semantic error and reports one unknown member. The codec records an error, skips the value and goes on; a syntax error is the only one that ends decoding ([ADR 0012](0012-client-errors-are-400-problem-json.md)).
- **No allocation per string.** v2 allocates each decoded string (3 allocations for 3 distinct strings in the probe). The body is read into the request's slab ([ADR 0008](0008-no-pooled-object-reaches-the-user.md)); a string with no escapes points into it, and an escaped one is unescaped into the slab's spare room.
- **The input stays on the stack.** Passing `&in` to v2 moved `in` to the heap; filling it through `reflect.Value` did not (0 allocations in the probe).

**Wire semantics kept from v2:** a nil slice is `[]` and a nil map `{}`; a duplicated name in a request is an error; names match case-sensitively; a request body with a member the type does not have is refused with a 400 naming it, unless the route says it accepts unknown members.

**An unexported field in a type the decoder fills is refused at Registration**, with the path of the field, in a JSON `Body` at any depth as in a text Section: `it is unexported, so nothing can fill it`, and a field tagged `json:"-"` is left out on purpose and accepted. The encoder keeps skipping an unexported field, because a response type with a private cache field is ordinary and harms no client. Before 2026-11-03 the decoder skipped it silently as `encoding/json` does, and a `Body` field misspelled in the lower case (`name string`) was never filled, never refused and never mentioned, while the same slip in a `Query` was a panic at start.

**What the codec delegates or refuses:** `time.Time` and `uuid.UUID` are read and written by the codec itself, with no allocation; a time is read by strict RFC 3339 (the three checks v2 adds on top of `UnmarshalText`, which alone accepts a one-digit hour), and the differential fuzz test keeps the two in step. Any other type with its own JSON or text methods (a decimal type with `UnmarshalJSON`), and `[]byte` as base64, is handed to `encoding/json/v2` for that value, correct but with its allocations. A type with its own JSON method is refused at Registration unless the app declared its shape with `WithJSONSchema`, because the API document cannot see inside the method and would describe it as `{}` ([ADR 0076](0076-a-type-that-writes-its-own-json-is-described-by-a-registration-or-refused.md)); `json.RawMessage` and `jsontext.Value` are free-form by name and need nothing. A delegated value is decoded into a fresh variable and copied over, and encoded from a copy, so a user's method never holds a pointer into the codec's destination, which may be on a stack. `json` tags are honoured for the name, `omitempty` and `omitzero`; any other tag option is refused at Registration. Embedded structs are inlined, and two fields that end up with the same wire name after inlining are refused at Registration; v1 and v2 settle that silently by depth, which hides a field. Map members are written in key order. `map[string]T` is supported, any other map key is refused. A field of type `any` or of an interface type is refused in an Input, because it can be neither decoded with a plan nor described. Nesting deeper than 64 levels is refused with a 400, the limit settable per route.

**Errors the client sees:** a syntax error is a fixed text ("invalid JSON", "unexpected end of JSON", "duplicate member name") with its byte offset, and jsontext's own message, which can quote the client's bytes, stays off the answer. An unknown member's name is clipped to 64 bytes in its location. The 20-error cap of [ADR 0012](0012-client-errors-are-400-problem-json.md) is shared with the errors the path and query sections already found.

**How the input stays on the stack:** reflect's `Set` and `Grow` make the compiler believe the destination escapes, so the codec hides the pointer from escape analysis (`noescape` in `decode.go`) and walks the plan with switches and static calls rather than stored closures. That is sound only while nothing the codec calls keeps the pointer, which is why every user method gets a copy (above) and a pointer-receiver `IsZero` is called on a copy too. Measured: 0 allocations decoding into a reused value, 1 into a fresh one (its list), against 7 for v2 ([`bench/result/jsoncodec.md`](../../bench/result/jsoncodec.md)).

**A fast path for flat bodies:** a type whose fields are all bools, numbers, strings or enums, or an `Opt` of one, at most 64, is marked at Registration, and its body is first read by a scanner of its own (`internal/jsoncodec/fast.go`) that accepts only a subset whose meaning is certain: strings of printable ASCII with no escape, integers with no fraction or exponent, each member once, every member known, every required member present, nothing but whitespace after. Anything else gives up and the tokenizer decodes the body again from its first byte, so the grammar, UTF-8 and duplicate checks above, and every error a client sees, still come from jsontext. `FuzzTheFastPathAgreesWithTheTokenizer` holds the property that whatever the fast path accepts, the tokenizer accepts with no error and decodes to the same value (22.9M executions, no difference, 2026-11-02). A 13-member flat body decodes in 395 ns against 1,061 through the tokenizer, and the reference POST is 12% faster end to end over memory ([`docs/research/hotpath-mac/`](../research/hotpath-mac/report.md)).

**What it costs:** a JSON codec is a correctness burden for as long as the project lives. Each type the tests use is fuzzed differentially against `encoding/json/v2` given the same names through a wire type built with `reflect.StructOf` (the trick the probe proved), and a difference is a failing test until explained ([ADR 0033](0033-the-rules-are-build-steps.md)). It is the largest single piece of milestone 1.

**What was rejected:** `encoding/json/v2` as the codec, which this ADR first chose; the four points above are why. Also rejected: generating a wire type with `reflect.StructOf` and `json` tags at Registration and decoding with v2. It gives wire names, but not every error, not strings in the slab and not an input on the stack.
