# Validation beyond types is a method: on a type for one value, on the Input across fields

Types refuse "not a number"; they cannot say "between 1 and 100" or "end after start", and Go has no value-level generics, so `Min[1]` cannot be a type. An Input may have a `Validate() error` method, run after decoding has succeeded, which reports its errors with locations through a small helper, so they are answered in the same 400 as decoding errors ([ADR 0012](0012-client-errors-are-400-problem-json.md)). The rule for one value belongs to its type: an application's own named type carries it in a method (`Length`, `Range`, `Items`, `Pattern`, `Check`, and `Format`, which names the document's `format` and checks the ones in the table below; and, from 2026-11-05, `ExclusiveMin`, `ExclusiveMax`, `MultipleOf`, `Unique` and `Members`), read at Registration as an enum's `Values` is ([ADR 0042](0042-text-values-are-decoded-by-type.md)), and three reusable types name the commonest (a non-empty string, a positive integer). The bounds reach the API description, which a `Validate` method cannot.

**`Validate`.** It is declared on the Input by value, with the signature `func() error`, and it is the Input's own: a `Validate` on a section type (`Body`, `Query`, ...) would never be called, so Registration refuses it. It runs once, after every section has decoded without an error and before the handler (step 5 of [ADR 0048](0048-groups-and-the-order-things-run-in.md)), so it never sees a half-filled Input, and a request that fails a type's rule or any other decoding rule is answered before `Validate` is asked. Registration finds the method and keeps it as a method expression, so a request pays one plain call that takes the Input by value, no interface and no allocation when it returns nil.

`Invalid(location, message)` returns the located error; `errors.Join` returns several, and a located error wrapped with `%w` is found too. The 400 lists them in the order returned, within the same cap of 20 and with the same `truncated` as decoding errors. The location is written by hand in wire names (`body.end`, `query.limit`, `body.items[2].qty`); the framework cannot check it, so a wire name changed by the naming policy or a tag leaves a stale string behind. An error from `Validate` with no located error in it is not an input mistake the client can fix: it is answered as a handler's error would be ([ADR 0049](0049-errors-are-found-with-errors-as-and-timeouts-wait.md)), the status it carries (`Conflict(...)`) or a 500 with no message, logged.

**Rules a type carries** (decided 2026-11-02). A named string type with `Length() (min, max int)` is a string whose length in characters lies within the two; a named `int` or `int64` type with `Range() (min, max int64)` is an integer between the two, both included, and a named `float32` or `float64` type with `Range() (min, max float64)` is a number between the two, both included; a named type of any kind with `Check() error` runs that method on each value decoded into it:

```go
type RoomName string

func (RoomName) Length() (min, max int) { return 3, 40 }

type Guests int

func (Guests) Range() (min, max int64) { return 1, 6 }

type Email string

func (e Email) Check() error { ... }
```

**A bound equal to the base type's own limit is not a bound** (decided 2026-11-03). `Range` on an `int64` type with `math.MaxInt64` as its max, on an `int` type with `math.MaxInt` as its max, and `Length` with `math.MaxInt` as its max, mean "at least": the document omits `maximum` or `maxLength`, the 400 says `expected an integer of at least 0` or `must be at least 12 characters`, and its `max` member is left out of the entry (a `min` equal to the type's minimum is left out the same way, `expected an integer of at most 10`). The limit is that of the type the method is declared on, so `math.MaxInt32` on an `int` type is a real bound on a 64-bit platform and is stated; only the constant that is the type's own limit is read as no limit, and `math.MinInt64` is the lower one. A method that leaves both sides open (`Range` of the whole type, `Length` of `(0, math.MaxInt)`) bounds nothing and is refused: the method would promise a rule no value could break. No `Min()` or `Max()` method is added, because the two-valued method already says it and a third and fourth name would be a second way to write one rule. The sentinel travels as `math.MinInt64` and `math.MaxInt64` in the `min` and `max` of the internal error, and `problem.go` leaves a sentinel side out; a client that needs the bound reads it from the document, where a missing `maximum` says the same.

**Range on a float** (decided 2026-11-03). An amount has a `minimum` and a `maximum`, so `Range() (min, max float64)` on a named `float32` or `float64` type is a number between the two, both included. It is read once at Registration on a zero receiver and checked on every value decoded into the type, in every Section, in a JSON body, inside `Opt` and lists, exactly where the integer `Range` is checked; the API description states `minimum` and `maximum` for a request. The 400 entry mirrors the integer one: the rule `range` with `min` and `max` as JSON numbers, and the sentence `expected a number between 0.01 and 1000000`, `expected a number of at least 0` or `expected a number of at most 9.5`. The same rule about a limit holds: `-math.MaxFloat64` and `math.MaxFloat64` (`math.MaxFloat32` on a `float32` type) are "not a bound", so the document omits that side and the entry leaves the member out. A `float32` is compared as a `float32`, so a bound written as `0.1` includes the `float32` nearest to it. Refused at Registration: a NaN or infinite bound, a `max` below the `min`, a `Range` of the whole type (`-math.MaxFloat64, math.MaxFloat64`), a bound outside a `float32`'s range on a `float32` type, a `Range` with the integer signature on a float type and one with the float signature on an integer type (a method of a rule's name is that rule, or a refusal). A decimal is not a float: a decimal type from another module, registered with `WithTextFormat`, bounds its value with `Check`, because comparing it as a `float64` would lose the digits that make it a decimal.

```go
type Amount float64

func (Amount) Range() (min, max float64) { return 0.01, 1000000 }
```

**The rest of what a type can state** (decided 2026-11-05). Five more methods, each read once at Registration on a zero receiver, each checked where the value is decoded and stated in the document, each a rule a person would otherwise write by hand in a `Check` (Huma and go-playground/validator have them all). One spelling each:

```go
type Price float64

func (Price) ExclusiveMin() float64 { return 0 } // a price above 0, and 0 itself is refused

type Cents float64

func (Cents) MultipleOf() float64 { return 0.01 }

type Handles []string

func (Handles) Unique() bool { return true }

type Options map[string]string

func (Options) Members() (min, max int) { return 1, 20 }
```

- **`ExclusiveMin() float64` and `ExclusiveMax() float64`, on a `float32` or `float64` type only.** A bound a value must be beyond and not equal to. They are separate methods and not extra results of `Range`, because `Range() (min, max float64)` has one signature on every number type and an agent that has read it once writes it right; a third result would make one name two signatures. They are named as the document names them (`exclusiveMinimum`), which is what an agent that read the OpenAPI document or Huma's tags reaches for. Each is optional and alone: a price above 0 is `ExclusiveMin` and nothing else. **A side is stated once**: `Range` bounds a side inclusively, an exclusive method bounds it exclusively, and a type that states the same side with both is refused, naming the side; to bound one side inclusively and the other exclusively the author leaves the other `Range` side at the type's limit (`Range() (-math.MaxFloat64, 1000)` with `ExclusiveMin() 0`, a price above 0 up to and including 1000). A type whose bounds leave no value (`ExclusiveMin` 5 with `ExclusiveMax` 5, or with a `Range` max of 5) is refused as an inclusive `Range` with `max` below `min` is. An exclusive bound at the type's own limit (`-math.MaxFloat64`) is refused as "not a bound", and a NaN or infinite one. **On an integer type they are refused**, with the message that says what to write: an integer above 0 is `Range() (1, ...)`, which is already one way to say it, and a second spelling of an integer bound would be two ways to write one rule (the same argument that kept `Min()` and `Max()` out). The 400 is the rule `range` as before, with the sentence `expected a number greater than 0`, `less than 1`, `greater than 0 and at most 1000` or `greater than 0 and less than 1` (an inclusive side keeps `at least`, `at most` and `between`), and its members `min` and `max` for an inclusive side and `exclusive_min` and `exclusive_max` for an exclusive one, as JSON numbers, so a client reads from the member name whether the bound is included. The document states `exclusiveMinimum` and `exclusiveMaximum` as numbers, which is what JSON Schema 2020-12 and so OpenAPI 3.1 say (the 3.0 spelling, a boolean beside `minimum`, is not what the document is). A `float32` is compared as the nearest `float32`, as `Range` is.
- **`MultipleOf()`, on `int` and `int64` as `int64` and on `float32` and `float64` as `float64`.** A value must be a whole multiple of the step. It is refused when the step is zero or negative (`a step must be at least 1`, `greater than 0`), when an integer step is 1 (every integer is a multiple, so it bounds nothing, as a whole-type `Range` is refused), on a string type or any type that is not one of those four (a `Range` on the other integer sizes is refused for the same reason: the text decoder writes `int` and `int64`), with another signature, and when it is stated with a `Range` that holds no multiple of the step (`Range` 6 to 9 with a step of 5), because no value could be valid. An integer is checked with `v % step == 0`. **A float is checked by division, with a tolerance**: `v / step` is compared with the nearest whole number and passes when they differ by at most `4 * 2^-52` times that number (`4 * 2^-23` for a `float32`), so 0.3 is a multiple of 0.1 although `0.3 / 0.1` is `2.9999999999999996`; zero is a multiple of every step and the only value within reach of the whole number 0, so `1e-20` is not a multiple of 0.1. The tolerance was set from every whole number of cents from -30.00 to 3000.00 (and, for a `float32`, to 1000.00), parsed from its decimal text as the decoder parses it, each of which must pass, and from the same text with a further `5` digit, which must fail ([`constraint_test.go`](../../internal/wire/constraint_test.go)). The 400 is the rule `multiple` with the member `multiple`, the step, a JSON integer or number, and the sentence `expected a multiple of 5` or `expected a multiple of 0.01`; it is asked after the bounds, so a value out of range is told it is out of range first. The document states `multipleOf`.
- **`Unique() bool`, on a named slice type.** Its items must be distinct. It returns `true`: a `Unique` that returns `false` states nothing and is refused, so there is no second way to turn it off. A bool and not a marker method because an agent that has read `Items` and `Format` reaches for a value-returning method, and because it reads as the question it answers. "Equal" is defined per element kind, and only the kinds whose equality a client can be told are accepted: a string (byte equality, so `a` and `A` differ, and an enum or a `NonEmpty` is a string), an integer of any size, a boolean, a float (`==`, so `1` and `1.0` are one number, as in JSON Schema; a JSON number is never NaN), and a `uuid.UUID`. **A struct, a list, a map or an `Opt` is refused** with the message that says to state which part must not repeat in the Input's `Validate`: no one reading of "equal" for a struct is the client's, a deep comparison would cost what the item costs to hold, and which field makes two items the same is the application's rule (an order's lines are the same when the product is, not when the quantity is). It also fails on a slice that decodes itself (`[]byte`, a `TextUnmarshaler`), as `Items` does, and is refused on any type that is not a slice with the exact signature (a struct's own `Unique() bool` is the domain's and is left alone). It works wherever a list does: a JSON array, repeated keys of a Query, Header, Cookie or Form, a `CSV`. The failure is one entry at **the first item that repeats an earlier one** (`body.tags[3]`, `query.ids[2]`), with the sentence `repeats an earlier item` and the rule `unique`, and no member, so it never carries the client's value. The check is made after the whole list decoded and only when every item did (an item that failed is left zero, and two zeros are not a repeat), and not when an `Items` bound already failed, whose entry says the list is the wrong length. **Cost:** a list of up to 16 items is compared pairwise, which allocates nothing and is at most 120 comparisons; a longer list goes through a set sized to it, one allocation whose memory is a constant factor on the list the request already holds. A client controls the length up to `Items`' `max`, or up to the body limit when the type states none, and the work is linear in the bytes it sent (hashing) or at most 120 comparisons (pairwise), never quadratic in a list a hostile client chose; a type that wants the set's allocation kept out states a small `Items` maximum. It composes with `Items` on the same type (`Items() (1, 40)` and `Unique() true`), which is how a bounded set of tags is written. The document states `uniqueItems: true`.
- **`Members() (min, max int)`, on a named map type**, mirroring `Items`: a map of between `min` and `max` members, both included, with `min` at least 0 and `max` at least `min` and 1. It is read on a map whose key is a string, as every map is. It is counted as the object is decoded: a member past `max` has its value skipped unstored (the key is read, the value is not decoded or kept), so an object is never held larger than its bound and a hostile one costs the tokenizer's skip and no memory, as an `Items` list does. The failure is one entry at the map's location, `must have between 1 and 20 members` (`at most 20` when `min` is 0, `exactly 2` when they are equal), with the rule `members` and `min` and `max`. The document states `minProperties` and `maxProperties`. It is refused on a type that is not a map with the exact signature (a list's length is `Items`, and `Items` on a map is refused with the message that names `Members`), on a type that decodes itself, and when it is not a count. A map is a JSON body member only (a text Section has no map), so there is no text form.

**Refused for these five, each a row of the table:** `ExclusiveMin` or `ExclusiveMax` on an integer type, on a string type or on a type that is not a number, with another signature, that is NaN, infinite or at the type's own limit, that states a side `Range` already states, or that leaves no value; `MultipleOf` of zero or below, of 1 on an integer, on a string, on an integer type other than `int` and `int64`, on a type that is not a number, with another signature, or with a `Range` that holds no multiple; `Unique` that returns false, on a type that is not a slice (a map, a string, an integer), on a slice that decodes itself, with another signature on a slice, or on a slice of structs, lists, maps or other kinds without a plain equality; `Members` that is not a count, on a type that is not a map (a list, a string, an integer), or with another signature on a map; an `Items` on a map; and a settings type ([`modules/config`](../../modules/config)) that carries any of the five, which settings do not check. The foreign tags `multipleOf`, `uniqueItems`, `minProperties` and `maxProperties` are refused beside `exclusiveMinimum` and `exclusiveMaximum`, which now point to the methods.

**What these five fail at.** A float multiple is a tolerance and not an exact test: a step of 0.01 accepts `0.30000000000000004` and `19.990000000000002`, which a client that did the arithmetic in floats sends, and above 2^50 steps (a value more than 10^15 times the step) every float passes because the spacing of floats is wider than the step; an application that needs exact decimal arithmetic stores money in integers (`Range` and `MultipleOf` on an `int64` of cents) or in a decimal type with a `Check`, as for `Range`. A validator that implements JSON Schema's `multipleOf` by an exact division (ajv by default) refuses `0.3` for a step of `0.1` where the server accepts it, so a client validated by the document is stricter than the server on a float step. `ExclusiveMin` on a float cannot say "the next float up", so an exclusive bound and a `Range` that is inclusive stay two spellings of two different things, and an integer's exclusive bound is the author's arithmetic (`Range(1, ...)` for "above 0"). `Unique` has no case-insensitive or normalised comparison (`a` and `A` are two items, and a `Check` does not change the value it checks, so an application that treats them as one states the rule in `Validate`), compares floats by value and not by the digits sent (`1` and `1.0` repeat), and does not compare structs, so an order with two lines for one product is the application's `Validate`; a list longer than 16 allocates a set. `Members` counts members and not their size, and a map's keys are not constrained (a key's rule is not checked, as before). None of the five is carried into a response schema, as no constraint is.

**Items and Format.** A named slice type with `Items() (min, max int)` is a list whose length lies within the two, both included; it is read once at Registration on a zero receiver, as `Length` is, and the API description states `minItems` and `maxItems` for a request. It is checked while the list is decoded: in a JSON body, an item past `max` is skipped unstored, so a list is never held longer than its bound and a hostile one costs the tokenizer's skip and no memory; in a text Section the values for the key are counted before the list is allocated, and a list outside the bounds is not allocated or decoded at all. The failure is one entry at the list's own location, `must have between 1 and 5 items` (`must have at most 5 items` when `min` is 0, `must have exactly 2 items` when they are equal), with the rule `items` and `min` and `max`. A named string type with `Format() string` names its JSON Schema `format` in the API description, in a request schema and in a response schema alike, and it is read once at Registration on a zero receiver. A name from the table below is also **checked** (decided 2026-11-03): every value decoded into the type, in every Section, inside `Opt` and lists, after the `Length` and the `Pattern` when the type has them, must be of that format, or the entry is a decoding error at its location with the rule `format`, a member `"format": "<name>"` and a fixed sentence that never carries the client's value. Any other name stays an annotation, because JSON Schema allows any; an empty one is refused. The check is made on a request only: nothing checks a value a handler returns, so a response states the format and does not enforce it. A string type that is also an enum (`Values`) or decodes itself from text carries its `Format` as an annotation only when the name is not in the table; with a checked name it is refused, because nothing would check it. A checked name on a type that is not a string is refused too (an integer or float type already is, whatever the name).

| `Format` | A value is accepted when it is | Sentence |
|---|---|---|
| `email` | one `@`; a local part of 1 to 64 bytes of RFC 5322 atext and dots, with no leading, trailing or doubled dot; a domain that is a `hostname` of at least two labels; 254 bytes at most. No quoted local part, no display name, no IP literal | `must be an email address` |
| `uri` | an absolute URI per RFC 3986: a scheme of letters, digits, `+`, `-` and `.` that starts with a letter, a `:`, and a non-empty rest of ASCII with no control character, no space, none of the nine characters RFC 3986 never allows unescaped (the double quote, `<`, `>`, the backslash, `^`, the backtick, `{`, `}` and the vertical bar) and only `%HH` escapes | `must be an absolute URI` |
| `hostname` | RFC 1123 labels of letters, digits and `-`, each 1 to 63 bytes and not starting or ending with `-`, 253 bytes at most; a trailing dot is refused | `must be a host name` |
| `ipv4` | `netip.ParseAddr` accepts it and it is an IPv4 address | `must be an IPv4 address` |
| `ipv6` | `netip.ParseAddr` accepts it and it is an IPv6 address, with no zone (`%eth0`) and not an IPv4 address written in dotted form (`::ffff:1.2.3.4`) | `must be an IPv6 address` |
| `date` | `YYYY-MM-DD`, a day that exists in the Gregorian calendar | `must be a date (YYYY-MM-DD)` |
| `date-time` | RFC 3339 as `time.Parse` reads it (a capital `T` and `Z`, seconds 00 to 59, a fraction of any length, `Z` or an offset), with an offset no later than 23:59 | `must be a date and time (RFC 3339)` |
| `uuid` | the canonical 8-4-4-4-12 form of hex digits, either case | `must be a UUID` |

Each check is written by hand and allocates nothing for a value that passes (`netip.ParseAddr` allocates nothing for an address without a zone, which is why a zone is refused; `time.Parse` allocates a zone for an offset, which is why `date-time` is not `time.Parse`; [`format_test.go`](../../internal/wire/format_test.go) holds both, and holds `date-time` equal to `time.Parse` on the cases that decide it). A format the table does not hold is the application's own `Check`, as before.

```go
type Tags []string

func (Tags) Items() (min, max int) { return 1, 8 }

type Email string

func (Email) Format() string { return "email" }
```

**Pattern.** A named string type with `Pattern() string` is a string that matches a regular expression. It is read once at Registration on a zero receiver, compiled once with `regexp` (Go's RE2), and checked on each value decoded into the type, in every Section, inside `Opt` and lists, after the length when the type has a `Length` too. The API description states it as `pattern`. Matching is unanchored in Go's `MatchString` and in JSON Schema, whose `pattern` is ECMA-262 and is not anchored either, so the two agree and the author writes `^` and `$` when the whole value must match. A value that fails is a decoding error at its location, `must match the pattern`, with the rule `pattern` and no `min`, `max` or `pattern` member. The sentence carries neither the client's value (as every sentence here) nor the pattern: the pattern is public in the API description, where a client reads it, and an entry that repeated it would be as long as the author's expression and would break the short-message bound of ADR 0012. A `Pattern` that is a Check would carry its own message; this one trades that for a document a client can run.

The expression is read by two engines, the server's RE2 and the client's ECMA-262, and a pattern that compiles in both can still mean something else in one. [`docs/research/pattern-dialect/`](../research/pattern-dialect/report.md) compiled 70 candidates in Go and in node (`new RegExp(p, 'u')`) and compared what they match. Registration therefore refuses any pattern outside the subset both read alike (the list is in the refusals below), and the document never states a pattern a client would read differently from the server. The subset is: literals; classes `[...]` of literals, ranges and `\d \D \w \W`; the escapes `\d \D \w \W \b \B \t \n \r \f \v \xHH`, `\p{X}` and `\P{X}` of a Unicode general category (`L`, `Lu`, `Nd`, ... , whose code points Go and node agree on), and a backslash before one of `^$\.*+?()[]{}|/` (and `-` in a class); the groups `(...)`, `(?:...)` and `(?<name>...)`; the quantifiers `* + ? {n} {n,} {n,m}`, each with an optional lazy `?`; `|`, `^` and `$`. What a type cannot be handed is not hidden: a Go-only construct is refused even where it is harmless to the server, because the document is the contract.

```go
type Slug string

func (Slug) Length() (min, max int) { return 3, 40 }
func (Slug) Pattern() string        { return `^[a-z0-9]+(-[a-z0-9]+)*$` }
```

**UUID.** The framework already has the type: a `uuid.UUID` decodes in every section, answers `expected a UUID` with the rule `type`, and is stated as `format: uuid`. No second type is added. The decoder is the standard library's `UnmarshalText`, which also accepts the `urn:uuid:` form, braces and 32 digits without hyphens; a service that wants only the canonical 36-character form writes a string type with `Format() string { return "uuid" }`, which is checked.

A bound needs a type to carry a value, and Go lets a type carry one only through a method or a type argument. A method on the field's own type costs one declaration and makes the rule part of a type the rest of the application can use; a type argument cost two (see what was rejected). `Length` and `Range` are called once at Registration on a zero receiver, so their results must not depend on the receiver's value; `Check` runs at request time on every value of the type that decoding stores, in every Section, inside `Opt` and lists, after the value decoded and before `Validate`.

**The constraint types.** `NonEmpty` (a string of at least one character), `PositiveInt` and `PositiveInt64` (greater than zero) are the bounds common enough to name, built the same way.

All of them are ordinary string and integer types, so a handler converts them (`string(in.Body.Name)`) and nothing is allocated for them. They decode wherever their base type does (path, query, header, cookie, JSON body, `Form`, inside `Opt`, `Null` and lists), and a value that fails is a decoding error at its wire location. A bound answers a fixed sentence (`must not be empty`, `expected a positive integer`, `must be between 3 and 40 characters`, `expected an integer between 1 and 6`) that never contains the client's value; a non-number keeps the base type's sentence (`expected an integer`). Each of these entries also names its rule in the 400 ([ADR 0012](0012-client-errors-are-400-problem-json.md)): `nonempty`, `positive`, `length`, `range`, `items` and `members` (the last four with `min` and `max`, and `range` on a float with `exclusive_min` or `exclusive_max` for an exclusive side), `multiple` (with the step as `multiple`), `unique`, and `pattern` for a value that does not match a `Pattern` (with no bounds), and `check` for a `Check` error, whose text stays the message, and `format` for a value that is not of its type's checked `Format` (with a `format` member naming it, and no bounds). A float `range` carries its `min` and `max` as JSON numbers. A `Check` answers its error's text: the message is the application's, so keeping the client's value out of it is the application's choice, as it is in a `Validate`. The schema generator states the bounds (a float's too) as `minLength`, `maxLength`, `minimum`, `maximum` and a `Pattern` as `pattern` for a request, and not for a response, because nothing checks a value a handler returns; what a `Check` tests it cannot state.

Length is counted in characters (Unicode code points), as JSON Schema counts it. A string longer in bytes than the most characters the bound allows is refused without being counted, so a hostile megabyte costs one comparison.

**A method of a rule's name is that rule, or a refusal.** On a string type the name `Length`, on an integer or float type `Range` and `MultipleOf`, on a float type `ExclusiveMin` and `ExclusiveMax`, on a slice type `Items` and `Unique`, on a map type `Members`, on a string type `Format` and `Pattern`, and on any decoded type the name `Check`, mean the rules above. A method of one of those names with another signature (`Length() int` counting something else), a `Range` on a string type, a `Range` with float bounds on an integer type, a `Range` with integer bounds on a float type and a `Length` on an integer type are refused at Registration, so a domain type whose method means something else is renamed rather than leave a reader to guess which one decoding obeys.

**A tag another framework reads is refused** (decided 2026-11-03). A Go developer moving from Gin, Fiber, Echo or Huma writes the rule where those frameworks read it, in a tag, and bites reads none of them, so before this a `validate:"required,min=3"` registered and a request breaking it was answered 201 ([`docs/research/foreign-tags/`](../research/foreign-tags/report.md)). Registration now refuses, in every Section and at any depth of a JSON Body (through `Opt`, `Null`, lists, maps and embedded structs), a field whose tag holds one of these keys, naming the field, the tag and where bites says the same thing: `validate` and `binding` (go-playground/validator, through Gin, Fiber and Echo) point to a rule method on the field's type or to the Input's `Validate`; `path`, `query`, `header`, `cookie`, `form`, `uri`, `param`, `params` and `reqHeader` (where a value comes from, in Huma, Gin, Echo and Fiber) point to the Section and the naming policy; `minLength`, `maxLength`, `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `multipleOf`, `minItems`, `maxItems`, `uniqueItems`, `minProperties`, `maxProperties`, `pattern`, `format` and `enum` (Huma's and swag's schema tags) point to `Length`, `Range`, `ExclusiveMin`, `ExclusiveMax`, `MultipleOf`, `Items`, `Unique`, `Members`, `Pattern`, `Format` and `Values`; `required` points to a plain field and `Opt[T]`; `default` points to `Defaults` and `Opt[T]` with `Or`. The test is what the tag would change: each of these states what a request may carry or where it is read, and nothing would keep it. A tag that changes nothing a request may carry (`json`, `db`, `gorm`, `doc`, `example`) is left alone, because a type shared with a database layer or another reader carries them for that reader. Two exceptions keep a correct program registering: a `validate` or `binding` tag is let through when the Input has a `Validate`, the one place an application's own validator can read it, and a type that decodes itself (`UnmarshalJSON`, `UnmarshalText`) is not walked, because its fields are its own. A `json` tag on a text Section's field is the naming policy's question, and [ADR 0011](0011-one-naming-policy-for-wire-names.md) refuses one that renames it. It spends none of the four axes: the walk runs once at Registration and a request is unchanged.

**Refused at Registration:** a `Range` that is the whole of its type, and a `Length` of `(0, math.MaxInt)` (both bound nothing); a `Validate` whose type is not `func() error`; a `Validate` with a pointer receiver (an Input is taken by value, so it would never be found); a `Validate` on a section; a `Length` that is not a length (`min` below 0, `max` below `min` or below 1); a `Range` whose `max` is below its `min`, or on an integer type other than `int` and `int64` (the text decoder writes one of those two); an `Items` whose bounds are not a count (`min` below 0, `max` below `min` or below 1), an `Items` with the signature `func() (min, max int)` on a type that is not a slice, or on a slice that decodes itself (`[]byte`, a `TextUnmarshaler`); a `Pattern` that returns an empty string (every value would match), that does not compile (the `regexp` error is quoted), or that is outside the common subset, naming the construct: an inline flag group `(?i)` `(?s)` `(?m)` `(?U)` or scoped `(?i:...)`, a `(?P<name>...)` group, a lookaround or an invalid group name, `\A \z \Q \E \a \C` and any other escape the subset does not list (including `\_`, `\-` outside a class, `\ ` and `\x{...}`), a backreference `\1`, `\s` and `\S` (RE2's set of spaces is narrower than ECMA-262's, so a value with a no-break space would pass in the client and fail on the server), `.` (RE2's dot matches `\r`, U+2028 and U+2029, ECMA-262's does not; write `[^\n\r]`), a POSIX class `[[:alpha:]]`, `\p` without braces or naming a script, a `]` first in a class or a lone `]`, `}` or `{` (RE2 reads them as literals, ECMA-262 refuses), a quantified `^`, `$` or `\b`, a class escape as the end of a range, and `\b` in a class; a `Pattern` on a type that is not a string with the signature `func() string`, on an enum (`Values`), or on a type that decodes itself (`TextUnmarshaler`, `UnmarshalJSON`, `[]byte`), because nothing would check it; a `Pattern` with another signature on a string type; a `Format` that returns an empty string; a `Format` of the signature `func() string` on an integer or float type, where the document already states a format of its own (`int32`, `int64`, `float`, `double`), refused rather than allowed to override it; a `Format` that names a checked format (the table above) on a type that is not a string, on an enum, or on a type that decodes itself, because a value of it could not be checked; the float `Range` refusals above; a `Check` with a pointer receiver (below); a method named `Length`, `Range`, `Items`, `Pattern`, `Format` or `Check` that is not that rule (`Items` on a type that is not a slice, `Pattern` on a type that is not a string, and `Format` on a type that is not a string, integer or float, are left alone unless they have exactly the rule's signature and name a checked format, because a struct with an `Items() []Item` or `time.Time`'s `Format(layout)` is the domain's own); a constraint type as a JSON map key, which is not checked; a field tagged with a key another framework reads for a rule or a place (the list above), unless it is `validate` or `binding` on an Input that has a `Validate`. Each is a row of the refusal table ([ADR 0007](0007-mistakes-are-refused-at-registration.md)).

**What this fails at.** A bound still costs a declared type per distinct bound: a one-off length is a type and a method where a tag would be a word. A pattern is limited to a subset of RE2 that ECMA-262 reads alike, so no lookahead, backreference or case-insensitive flag, and a pattern that needs one is a `Check` (with `regexp`) that the document cannot state; `\s` and `.` are refused until written as classes, which costs a sentence of surprise. A pattern is one declaration per distinct expression, as a length is. A pattern's failure does not say which part of the value was wrong, and carries no pattern member, so a client translating the message reads the document. The client's engine is not run at Registration: the subset is held by the probe and by a test that runs node when it is on the path, and a different ECMA-262 engine or Unicode version could still read a category differently. A list's length is an `Items` on its type, one type per distinct bound, as for `Length`. A domain type that already has a method named `Length`, `Range`, `Check`, or `Items` or `Format` with the rule's signature on the kinds above, meaning something else, cannot be a field type until it is renamed or wrapped. A `Format` outside the table is trusted: nothing checks that the value is what it names. A checked format is the framework's idea of it, not the application's: `email` refuses a quoted local part and an address with no dot in its domain, which RFC 5322 allows and almost no application's mail uses, and `uri` refuses an IRI with non-ASCII characters, so an application that needs another definition names another format and writes a `Check`. A float `Range` compares the stored `float64`, so a decimal amount such as `0.1 + 0.2` is a float's amount and not a decimal's. A `Check`'s message can echo the client's value if the application writes it so. Constraints are not carried into a response schema and are not enforced on output; a `Format` is carried, because it is an annotation on output, and its refusals hold on output too (an empty `Format`, another signature, one on an integer or float type, are refused at the route that returns the type). A `Validate` location is a string nothing checks. `Validate` reads the whole Input, so a check that needs a database is the handler's job, not `Validate`'s; it has no context and must not block.

**Allocation.** A typed JSON request whose fields carry an `ExclusiveMin`, a float `MultipleOf` and an integer `MultipleOf` allocates 2 (`budget_test.go`), and one that also carries a `Unique` list of at most 16 items, a `Unique` string list and a `Members` map costs what the same request with plain fields costs, 12 with its lists and map (equal in `budget_test.go`), so the new checks allocate nothing when they pass; a `Unique` list longer than 16 allocates its set. A typed JSON request whose Input has constraint types and a `Validate` that returns nil allocates 2, as without them (`budget_test.go`), and so does one whose fields carry `Length`, `Range` and a `Check` that returns nil, on the fast path and through the tokenizer. The `Check` is reached through a pointer to the decoded value, `reflect.NewAt(t, p).Interface().(Checker)`, which boxes nothing, and the pointer is hidden from escape analysis as the decoder already does for `reflect`; that is true only because a value receiver gets a copy and cannot keep the pointer, which is why a pointer receiver is refused. A `Check` costs 12.6 to 13.1 ns a value on the fast path, its own work included ([`docs/research/type-rules/`](../research/type-rules/report.md), a laptop, so a ratio and not a number for ADR 0003). A string that matches its `Pattern` costs what a plain string costs, 2 allocations a typed JSON request, equal in `budget_test.go` (`regexp.MatchString` on a string takes its machine from a pool and allocates nothing once warm). Its CPU cost is a claim and not a measurement: RE2 runs in time linear in the value and the pattern, a hostile value is bounded by the body limit, and a pattern is slower than a `Length` by a regular expression's constant, which this ADR has not measured on the reference workload. A request that passes with a float `Range` field and one field of each checked format (`email`, `uri`, `hostname`, `ipv4`, `ipv6`, `date`, `date-time`, `uuid`) costs 2, as the same request with plain fields does (`budget_test.go`), and the decoder allocates nothing on the fast path or through the tokenizer. A request that passes with an `Items` list, a `Format` string and a `uuid.UUID` costs what the same request with a plain list, string and `uuid.UUID` costs: 3 (2 and the list's backing array), equal in `budget_test.go`. A failed `Check` costs what a wrong type in the field costs (4). A `Validate` that fails with one `Invalid` allocates 3 (the error itself); a failed constraint type costs what any decoding error costs (4 for one error in the body, from its location string and the path it is built on).

**What a refused tag fails at.** A body type shared with a codebase that documents it with swag (`minLength:"3"`) or validates it with Huma's schema tags cannot be a Body until those tags are taken off or the type is wrapped, though nothing in that other codebase is wrong; the refusal costs that edit, where an ignored tag cost a rule that silently did not hold. The list is closed: a tag of a framework not on it (a new one, or a key spelled `Validate`) is still ignored without a word, and is added here when it is met. The `Validate` exception trusts that the method runs the validator; a `Validate` that checks something else lets a `validate` tag through that nothing reads.

**Considered:** `validate:"min=1,max=100"` tags with go-playground/validator, as Gin and Fuego use. Rejected because it is a language inside a string that no compiler checks, its errors name Go fields (`Key: 'FIn.Name' Error:…`, [`docs/research/`](../research/README.md)), and it is the dependency ADR 0006 refuses.

**What was rejected: the rest of what a type can state, in other spellings** (considered 2026-11-05). A third and fourth result on `Range` for the exclusivity of each side (`Range() (min, max float64, exclusiveMin, exclusiveMax bool)`): one name with two signatures on two kinds, and a row of booleans nobody reads. `Gt()`, `Gte()`, `Lt()` and `Lte()` as go-playground/validator names them, or `Above()` and `Below()`: four names for what `Range` and the document's own `exclusiveMinimum` already say, and the document's name is the one an agent has read. An exclusive bound on an integer: it would be a second spelling of `Range(n+1, ...)`. `Unique() bool` that may return false: a second way to say nothing. `Unique` as a marker method with no result: an agent reaches for the value-returning shape and is refused, where the bool shape is read right the first time; the marker has nothing to get wrong, and that was weighed against it. `Unique` on a struct or list by deep equality: a client cannot be told what two structs being equal means, and the cost grows with what the item holds. `Unique` that refuses a list with no `Items` maximum, so the pairwise cost is bounded by a declared number: it would make an agent write a bound it did not need, when a set is linear in the bytes the client sent anyway. A set for every list, which allocates for the commonest three-item list: pairwise for 16 or fewer costs nothing and is at most 120 comparisons. `MultipleOf` by exact `math.Mod` on a float: it refuses 0.3 for a step of 0.1, which a client sends. `MultipleOf` on an integer of 1 as allowed: a rule no value could break. `Members` named `Properties`, `Entries` or `Len`: the document says properties and JSON says members of an object, and `Items`' sibling for a map reads as the thing it counts; `Members` is the word of RFC 8259 for what an object holds and the glossary now has it.

**What was rejected: a tag bites does not read is ignored** (the position until 2026-11-03). Tags were rejected as the way to state a rule, but one written anyway was left alone, as `encoding/json` leaves a tag it does not know. A probe at 062ddaa registered an Input whose body fields carried `validate:"required,min=3,max=40"`, `binding:"required,min=3"` and `validate:"required,email"`, and a path field `path:"id" validate:"min=1"`: Registration accepted it and `POST /users/0` with `{"name":"a","email":"not-an-email"}` was answered 201 with the body echoed ([`docs/research/foreign-tags/`](../research/foreign-tags/report.md)). The rules the author wrote did not hold and nothing said so, which is the mistake ADR 0007 exists to refuse, and the one a developer coming from the frameworks most Go services use is likeliest to make. Moved by that.

**What was rejected: a bound at the type's limit is a bound** (the position until 2026-11-03). `Range() (0, math.MaxInt64)` was a range of two numbers, so the document stated `maximum: 9223372036854775807` and the 400 said `expected an integer between 0 and 9223372036854775807`, a sentence that reads as a limit the author chose when the author meant "not negative". A user's port of a Commitment context found both and worked around them with a `Check`. Moved by that evidence and by the cost of the alternative, two more method names; reading the type's own limit as absent adds no name and no case a correct program can tell apart.

**What was rejected: a `Format` does nothing at request time** (the position until 2026-11-03). It said a format is an annotation: the document names it, a `Check` beside it enforces it, and the framework ships no email rule because what counts as one is the application's. The cost: a client reads `format: email` in the document and the server keeps no such promise, which is a false one, and every field of the kind needed a `Check` that repeated what the `Format` already named. Huma checks these formats, and a user moving from it expects the same. Moved by that: the eight formats of the table are checked by definitions written here, small enough to read, and a name outside the table remains an annotation. A decimal is still not covered, and `Check` remains for any rule the table does not say.

**What was rejected: `Bounded[R]`** (the decision from 2026-11-01 to 2026-11-02). A string whose length lay within the `Range() (min, max int)` of a zero-size type argument (`Name bites.Bounded[NameRange]`, with `type NameRange struct{}` and its method). It worked and cost nothing a request, but every bound was two declarations a reader had to connect, the field's type was the framework's and not one the rest of the application could take, and it covered string lengths only. A named type with a `Length` method is one declaration, is the domain type, and the same device gave `Range` and `Check`; measured equal (2 allocations, [`docs/research/type-rules/`](../research/type-rules/report.md)). Removed before 1.0 ([ADR 0034](0034-versioning-before-1-0.md)): a field of type `Bounded[R]` becomes a named string type whose `Length` returns what `R`'s `Range` did.

**What was rejected: a pattern is a `Check`** (the position until 2026-11-02). It said a pattern has no form the API description can state, so the author wrote `regexp.MustCompile` in a package variable and a `Check` around it, and a `Format` could name what it checked. A client then learned the rule from a sentence the author wrote and the document stated nothing. Moved by the dialect probe ([`docs/research/pattern-dialect/`](../research/pattern-dialect/report.md)): the document can state a pattern if Registration refuses the constructs the two engines read differently, which is a short list and can be walked from the source; `Pattern` is that, and a `Check` remains for what the subset cannot say. Stating the author's RE2 expression unchecked was rejected: `(?i)`, `\z`, `(?P<n>)`, `\s`, `.` and `\pL` all compile in Go and differ or fail in a client that follows the document.

**Also rejected on 2026-11-02.** Leaving a method of a rule's name with another signature alone, as the first build did: a `Range` written on a string type in the habit of `Bounded` would then have checked nothing and said nothing. Calling `Check` through a function value without hiding the pointer: the decoded value escaped, one allocation a request for a caller that decodes onto its stack (the jsoncodec tests went from 1 to 2 and from 0 to 1). A `Check` with a pointer receiver: it could keep a pointer to a value on the stack. Struct tags for the rules (`maxLength:"40"`, as Huma has): the language inside a string this ADR refuses above.

**What was rejected while building it.** `Min[N]`-style types with the number in the type argument: Go type arguments are types, not values. A generic `Positive[T]` over the integer kinds: a type declaration cannot have a type parameter as its underlying type, so it would be a struct with an accessor and every use a method call; two named integer types cover `int` and `int64`. A `Validate` that returns plain errors as 400 with no location: it makes `Invalid` optional and the location absent, which is the Go field name problem again in another place. Running `Validate` on a pointer receiver through a pointer to the Input: it makes the Input escape to the heap, one allocation a request.

**What it costs** (measured 2026-11-01, [`docs/research/m2-request-path/`](../research/m2-request-path/report.md)): constraint types in every field and a `Validate` that returns nil keep 2 allocations; GET +0.4% and POST -2.1% req/s, inside the budget of ADR 0003. The POST p99 rose 19% in that run with 120 ns more CPU, a cause not found; measured again on 2026-11-05 ([`docs/research/middleware-p99/`](../research/middleware-p99/report.md), three rounds interleaved), GET -0.3% and POST -0.6% req/s, p99 unchanged on both (817 against 821 us, 950 against 949), 15 and 33 ns of CPU, so the 19% is not reproduced.
