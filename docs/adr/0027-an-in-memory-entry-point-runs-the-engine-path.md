# The whole application can be tested over in-memory connections, on the same path the engine takes

The engine takes its listener as an interface. A test package provides a listener whose connections live in memory: they honour deadlines, carry a remote address the test sets, and can be closed from the client's side at any moment. The app takes a `Clock` (the real one by default), and the test package has one that moves only when told to. On top of these sit a client for plain requests, a JSON helper and a WebSocket client (built 2026-11-01, [ADR 0074](0074-the-bitetest-websocket-client-reads-on-its-own-goroutine-and-times-out-in-real-time.md)): it dials a WebSocket route, sends text, binary and JSON, reads messages and pings, answers pings, closes with a status and reads the server's close, with real-time timeouts so a test never hangs.

So everything the reference workload does is testable with no port: a request and its 400, a client leaving mid-handler ([ADR 0016](0016-the-handler-context-is-cancelled-on-disconnect.md)), a timeout or a missed heartbeat by advancing the clock ([ADR 0024](0024-limits-are-on-by-default.md), [ADR 0039](0039-heartbeats-run-on-one-timer-wheel.md)), a trusted proxy by setting the remote address ([ADR 0025](0025-no-proxy-is-trusted-by-default.md)), TLS over the in-memory pipe, and a chat room with several WebSocket clients. The framework's own tests use it for almost every behaviour.

**Waiting for an Observer's End.** `Server.WaitEnded` returns once every request the server received whole has ended, so a test that reads what an Observer recorded does not poll ([ADR 0051](0051-a-request-is-observed-when-it-starts-and-when-it-has-really-ended.md)). It is built on the memory connection, not on a hook in the app: the engine's connection reads its next request only after End has run, so a server end of the listener is settled when it is closed or blocked in a `Read` with nothing to read and its peer still there, and `WaitEnded` waits, on a notification and not a sleep, for all of them. A request being handled, a stream still sending and a client that left mid-handler are therefore waited for; a WebSocket is settled once its upgrade is answered, because End runs at the 101. A request the client has only partly sent is not waited for, since its connection is blocked in `Read` like an idle one. A handler held on the fake `Clock` is never settled, and the call fails the test after five real seconds. It costs the request path nothing, since the only code added is in `memconn`, which no real listener uses (the engine's allocation rows are unchanged), and no exported name of the root package. It waits for the whole server, not for one request: a `Do` is one request, so a test that wants a single request's End makes it alone.

**Reading JSON back** (revised 2026-11-05). `Response.JSON`, `Message.JSON`, `WS.ReadJSON` and `bitetest.JSON[T](tb, resp)`, which fails the test with the status and the body, read as a client of the app reads: with the app's own codec, naming policy, formats and `WithJSONSchema` registrations, through an internal door (`internal/testcodec`, set by `bites` as `Start` replaces the logger, the way `SendJSON` writes, [ADR 0074](0074-the-bitetest-websocket-client-reads-on-its-own-goroutine-and-times-out-in-real-time.md)). A `Response` and a `Message` carry the `*bites.App` that produced them, so no call changes. An `Opt`, a `Null`, a `Date` and a tagged union ([ADR 0083](0083-a-json-value-of-several-kinds-is-a-tagged-union-of-opt-variants.md)) therefore fill as the app's clients see them, and a handler's own untagged type reads back under the naming policy it was written with ([ADR 0011](0011-one-naming-policy-for-wire-names.md)). **An answer is not a request, so the read is lenient.** It is the plan the Topics' payloads use ([ADR 0081](0081-a-topic-reaches-other-instances-through-a-broker-and-postgres-is-a-module.md)): a member the type has no field for is skipped, and a member the answer left out leaves its field zero, even one a request would require, so a test's own reduced type (a few fields of a large answer) reads without a copy of every member, and a test that checks a value checks it by comparing it. A member of the wrong type, or a body that is not JSON, is still an error. **A type the codec has no plan for** (`map[string]any`, `any`, a type with a channel field) and a `Response` or `Message` a test built by hand, with no app behind it, are read with `encoding/json/v2` as before, matching a member to a field ignoring case, underscores and dashes through the unmarshalers of `internal/wire`. **What was rejected.** Always `encoding/json` with case-insensitive matching (the first form, 2026-11-02): it filled an untagged type under either policy but could not fill an `Opt` held in a union or a union at all, so every application that returned a union declared a second, pointer-based copy of its types in its tests and a test holding the two equal (an application's report, 2026-11-05). A second method (`ReadAs`) beside the existing ones: two spellings of one read, and a method cannot be generic in Go. A strict read, with the request's refusals of unknown and missing members: a test of a reduced type failed on members it did not ask about, and a missing required member in an answer is caught by comparing the value read, not by the reading. The cost that remains is that a read by the app's codec does not tell a test the exact wire names: a test of those compares the text. It costs nothing on the request path (test code only); the plans are kept per type on the `App`, so a test that reads many messages compiles each type once.

**Starting and stopping.** `bitetest.Start` builds the app's server before it returns and serves it on a goroutine, so a Registration mistake panics in the test and a `Shutdown` right after `Start` stops a server that is serving; when it served the app with `go app.Serve(ln)`, a `Shutdown` that ran first found no server, returned nil and stopped nothing, which the testing guide's shutdown example met on 2026-11-04. A request sent once the app has stopped accepting (`Shutdown` with no `WithShutdownDelay`, or `Close`) fails the test with a message that says so and names `WithShutdownDelay`, rather than a bare `EOF` or a closed-connection error, which the fourth agent usability run met with nothing to go on.

**What `Start` does with the app's log.** An App that was not given a logger with `WithLogger` writes into `tb.Log` while the server runs, through a text handler without the time stamp; an App given one keeps it. Before, an App with no logger used `slog.Default()`, so every `Start` printed the start-up settings (fourteen Info lines) to the test binary's stderr, passing or not, and a test of a handler's error drowned the one line that mattered. `tb.Log` shows on failure and with `-v`, which is when a test log is wanted. The one risk of `tb.Log` is a call after the test has finished, which panics, and a connection's goroutine can log after its handler returned; so `Close`, which runs as a cleanup before the test ends, turns the handler into one that drops lines, under the lock a write holds (`TestALineLoggedAfterTheServerIsClosedIsDroppedAndNeverReachesTheTest`). The replacement is made through an internal hook (`internal/testlog`) that only `bitetest` calls, so no application can swap an App's logger after `New`; it costs nothing outside tests. Rejected: discarding the log by default, which hides the one line that explains a failure (a 500's cause is logged, never sent); and a `bitetest.Quiet` option, which is the flag one forgets, with the noise as the default.

**A request is written as the client would, and its answer read while it is written** (decided 2026-11-04). `Request.Header` and `WSRequest.Header` are `map[string][]string`, the shape `Response.Header` and `bites.Header` have, so a header with several values is a test like any other; they were `map[string]string`, one value each, and an agent in the usability test wrote the `[]string` form first, as every other header around it suggested ([`docs/research/agent-usability/`](../research/agent-usability/report.md), row 1). `Do` reads the answer on its own goroutine while it writes, so an app that answers before reading the whole body (a 413 for a body over `MaxBody`) gives the test that answer; before, the write into a connection the app had closed failed the test with `io: read/write on closed pipe` (row 4).

**What it cannot simulate:** the kernel. A reset connection, a partial write, a full socket buffer and real epoll readiness are covered by a smaller set of tests over loopback.

**What was rejected:** the first version of this ADR, an entry point taking a request's bytes and returning the response's bytes. It could not express a WebSocket, a stream, a disconnect or a timeout, so half the reference workload would have been untestable without a port. Huma's `humatest` is the precedent for testing without a server; the difference here is that nothing is skipped between the bytes and the handler.

**Services** (decided 2026-11-04, [ADR 0079](0079-services-start-after-the-app-binds-and-stop-in-reverse-around-shutdown.md)). `bitetest.Start` runs the app's `Service` `Start` functions before it returns and fails the test with their error; `app.Shutdown` and the end-of-test `Close` run `BeforeShutdown` and `Stop`, with real-time deadlines.
