# A type that writes its own JSON is described by a registration or refused

**A field whose type encodes or decodes itself through its own JSON methods, and whose shape the app has not declared, is refused at Registration, because the API document would otherwise describe it as `{}` and nothing would fail anywhere.** The codec hands such a type to `encoding/json/v2` for that value ([ADR 0015](0015-json-is-our-own-codec-on-jsontext.md)), which is correct on the wire, but the document is built from types and a method body cannot be read. Before this decision a `pgtype.Timestamptz` field registered, was written by its own `MarshalJSON`, and was described as `{}`, so the client generated from the document said `unknown` for a timestamp.

- **`WithJSONSchema[T](JSONSchema{Type, Format, Nullable})` declares the shape.** `Type` is one of `string`, `number`, `integer`, `boolean`, `object` and `array`, or `any` for a value that really is free-form JSON, described as `{}`. `Format` is the OpenAPI format of a string, number or integer. `Nullable` says the type's own method can write `null` (pgx's `Timestamptz` with `Valid` false does), so a response is described as `type: [string, null]`. The registration applies wherever `T` appears: a Body field, an Output field, a slice or array element, a map value, inside `Opt` and `Null`, and in an `Events` or Socket message.
- **The refusal is in the compiled plan, not the document.** The decoder refuses a type with a JSON unmarshal method (`UnmarshalJSON` or `UnmarshalJSONFrom`, alone or beside a text one) and the encoder one with a JSON marshal method, at any depth, unless it is registered. The message is the route, the Go path of the field, the type, which direction it travels and the option that fixes it. The test is made for the direction the type travels: a type with only `UnmarshalJSON` in an Output is written by the fields it has and is not this case.
- **A type with text methods and no JSON method is not this case.** It is a string, described as one already, and `WithTextFormat` ([ADR 0042](0042-text-values-are-decoded-by-type.md)) adds its format. `time.Time`, `uuid.UUID` and `Date` are known to the core. A type with both a JSON and a text method is written by the JSON one, so it is refused until registered, with `WithJSONSchema` and not `WithTextFormat`; the two options on one type are a panic from `New`, because a type is described one way.
- **`json.RawMessage` and `jsontext.Value` are free-form by name and need no registration.** They are the standard library's own spelling of "any JSON", so describing them as `{}` states what the author wrote and hides nothing; refusing them would make every pass-through payload field carry a line that says nothing. Any other type that is free-form says so in the open with `JSONSchema{Type: "any"}`, which is the way the refusal is answered when the honest description is `{}`. An `any` field is unchanged: it is an explicit statement that the shape is open, and in an Input it is refused as before. They also take `null` as the bytes `null`, and a member whose shape is known is a `RawJSON[T]` ([ADR 0087](0087-a-json-value-the-app-owns-is-raw-json-bytes-documented-as-a-type.md)).
- **`Nullable` is stated for a response only.** The decoder refuses `null` for a field that is not a `Null` before the type's own method is asked, so a request document that allowed it would promise what is answered with a 400. A request that may carry `null` is a `Null[T]`, which is described as nullable in both directions; a type that is already nullable is not wrapped twice.
- **`WithJSONSchema` refuses**, naming the line that registered it: an interface or pointer type, `time.Time`, `uuid.UUID` and `Date`, `json.RawMessage` and `jsontext.Value`, a type with no JSON method (it is described by its fields and the registration would hide them), a `Type` that is not a JSON type, a `Format` on an object, array, boolean or free-form type, `Nullable` on a free-form type (it already admits null), the type registered twice with two schemas, and a type also registered with `WithTextFormat`.
- **The registration states and does not enforce.** The type's own methods still decide what is valid, as before; a value they refuse is the same 400, `expected a valid value of type <type>` ([ADR 0042](0042-text-values-are-decoded-by-type.md)).

**Cost.** The axes of [ADR 0003](0003-the-trade-budget.md) do not move. The check is a pair of method-set lookups at Registration, the schema is a map lookup when the document is built, and nothing is added to a request: the delegated value is handled exactly as before, so the allocations of a typed JSON request and the memory of an idle connection are unchanged.

**What was rejected.**

- **`WithJSONFormat[T](type, format)`, a pair of strings like `WithTextFormat`.** It cannot say that a type may be null, and `Timestamptz` is the type that asked, nor that a type is free-form; both need a third field or a second option. One struct with three fields is one option to find.
- **Describing every self-encoding type as `{}` and warning.** A warning at start is read once. The failure is silent downstream, in a generated client, so it is the one this framework exists to turn into a Registration panic.
- **Refusing `json.RawMessage` too.** It would be consistent and noisy: the type says "any JSON" in its name, and the registration would repeat it for every field.
- **Reading the schema from a `JSONSchema()` method on the type.** The types that ask are another module's, which cannot gain a method, and the core cannot import their package: the same argument as `WithTextFormat`.
- **Treating `Type` left empty as free-form.** A forgotten field would then be `{}` with no panic, which is the failure this decision removes; free-form is spelled `any`.
