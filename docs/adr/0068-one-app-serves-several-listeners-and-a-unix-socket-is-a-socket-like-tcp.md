# One app serves several listeners at once, and a Unix socket is served, parked and watched like TCP

An `App` serves on as many listeners as the application gives it, each with its own `Serve`, `ServeTLS`, `Listen`, `ListenTLS` or `ListenUnix` call on its own goroutine, plain and TLS, TCP and Unix together, all into the one engine: one route table, one `MaxConns`, one `Shutdown` and one `Close` that reach every listener and every connection. `App.ListenUnix(path, perm)` is new. Built 2026-11-01, milestone 3, track C.

**Several listeners.** The engine already kept a set of listeners and closed them all when it stopped accepting; what this decision adds is the promise and the log. Each serving call logs one start-up line before it accepts, `bites: listening network=tcp addr=127.0.0.1:8443 tls=true`, so an app on three listeners says what each is. `MaxConns` ([ADR 0024](0024-limits-are-on-by-default.md)) is the app's, shared by every listener: it is a bound on the process's file descriptors and memory, which do not care which listener a connection came from. A listener that fails to bind returns its error to its own caller and the others go on serving; deciding whether that is fatal is the application's.

```go
go func() { errs <- app.Listen(":8080") }()                       // plain, for the health checks
go func() { errs <- app.ListenTLS(":8443", cfg) }()              // TLS
go func() { errs <- app.ListenUnix("/run/app/app.sock", 0o660) }() // the local proxy
```

**A Unix socket.** `ListenUnix` makes the socket file, sets its permission bits to `perm` (connecting needs write permission, so `0o660` lets the process's group connect: the proxy's user in that group), and the listener removes the file when it closes, at `Shutdown` or `Close`. A socket file left by a process that died without closing (one on which a connection is refused) is removed first; a socket another process answers on is an error, and anything that is not a socket (a regular file, a directory) is left alone and `net.Listen` reports it. TLS on a Unix socket is `ServeTLS` with a `net.Listen("unix", path)` listener; there is no `ListenUnixTLS`, since a local socket rarely needs it.

**Parking on a Unix socket: yes.** A Unix stream socket reports readiness, the peer's half-close (`EPOLLRDHUP`) and a hangup through epoll exactly as a TCP socket does, so the engine parks an idle Unix connection on its poller ([ADR 0005](0005-our-own-http1-engine-with-a-goroutine-per-connection.md)) and watches a running request's Unix connection with the epoll disconnect watcher ([ADR 0016](0016-the-handler-context-is-cancelled-on-disconnect.md)), not with a reader goroutine. `socketOf` in `park.go` is the one place that says which connections have such a socket: a `*net.TCPConn` or a `*net.UnixConn`. A refused head is answered, then the Unix socket is half-closed and drained for a moment as a TCP one is (`lingerClose`), because closing a Unix socket with unread bytes resets its peer too. Tests over a real socket: an idle Unix connection parks and its next requests are served, Shutdown closes a parked one, a client that leaves mid-handler cancels the context with `ErrClientGone` through the epoll watcher (`internal/engine/unix_test.go`).

**The peer address of a Unix connection is the zero `netip.AddrPort`.** A Unix socket's peer has no IP and usually no name at all, so `Request.RemoteAddr()` is the zero value, which `IsValid` reports as false; `Exchange.RemoteAddrPort` returns it without parsing the empty name. Behind a proxy on a Unix socket the client's address can only come from the proxy's headers or a PROXY header. Whether a Unix socket's peer may send them was left here to the trusted-proxy list, with the proposal that it be named explicitly and never trusted by default; wave 2 decided exactly that ([ADR 0058](0058-the-proxy-protocol-is-turned-on-per-listener-and-accepted-only-from-a-trusted-proxy.md), [ADR 0025](0025-no-proxy-is-trusted-by-default.md)): `TrustedProxies.UnixSockets` trusts the peer of every Unix socket the app listens on, the socket's permission bits being the list, and `ListenUnix(path, perm, ProxyProtocol())` reads a PROXY header whose client becomes the peer. Every serving call now takes `ListenOption`s after its other arguments.

**What it costs.** No field was added to a connection or to the server, so memory per idle connection is what ADR 0003 records for TCP (a parked Unix connection holds the same `parkState` a parked TCP one does; not measured separately, a claim). The request path is unchanged: the type switch in `socketOf` runs only when a connection parks or a context is armed, and `RemoteAddrPort` gained a case that is not reached for TCP. One more log line per listener at start. Throughput over a Unix socket is not measured yet (wave 2).

**Refusals** (rows of `refusal_test.go`): `ListenUnix` with a permission of zero, or with bits beyond `0o777` (such as `os.ModeSocket|0o660`), panics before anything is made. A path that cannot be listened on is an error returned, not a refusal: it is I/O, found only by trying.

**Scenarios it was put against.**

- _The reference workload_ ([ADR 0002](0002-the-reference-workload.md)) with nginx on the same host speaking to the app over `/run/app/app.sock` and Kubernetes probing a plain TCP port: one app, two listeners, one `Shutdown` that drains both and removes the socket file (`TestOneAppServesTCPTLSAndAUnixSocketAtOnceAndShutdownEndsThemAll`, with a TLS listener as the third).
- _A crash and a restart_: the old socket file is found stale and replaced (`TestListenUnixRemovesASocketNobodyAnswersOnAndNothingElse`).
- _Two instances started on one path by mistake_: the second gets an error and the first keeps its socket.
- _A hostile local user_: the permission bits decide who may connect; the default umask is not relied on.
- _20,000 idle keep-alive connections from a local proxy over the Unix socket_: parked, no goroutine each, as over TCP.

**What it fails at.** There is a window between `net.Listen` making the socket and `chmod` setting its bits, during which the umask's bits apply (usually stricter). A stale-socket check and the removal that follows are two steps, so two processes starting on one path at the same instant can both see it stale. A Unix connection's peer credentials (`SO_PEERCRED`: the peer's uid and pid) are not offered to the request. On a platform without epoll a Unix connection, like a TCP one, moves its wait to a fresh goroutine instead of parking.

**What was rejected.** One option to list the listeners up front (`WithListeners`): the serving calls already are that list, and a separate list would need its own TLS settings per entry. A `Serve` that takes several listeners and returns when the first one fails: it decides for the application that one failed listener ends the others. Leaving a stale socket file for the operator to remove: every restart after a crash would fail. Removing whatever is at the path: a typo in the path would delete a file. Treating a Unix connection as one the engine cannot park (the position before this decision, where only a `*net.TCPConn` parked): an idle Unix connection would hold a goroutine and its stack for no reason.
