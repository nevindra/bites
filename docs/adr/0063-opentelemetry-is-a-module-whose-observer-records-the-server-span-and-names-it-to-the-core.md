# OpenTelemetry is a module whose Observer records the server span and names it to the core

`modules/otel` ([ADR 0070](0070-optional-features-are-modules-under-modules-each-with-its-own-go-mod.md)) has one function, `otel.Tracing(otel.Config{TracerProvider})`, that returns an Observer ([ADR 0051](0051-a-request-is-observed-when-it-starts-and-when-it-has-really-ended.md)) recording one OpenTelemetry server span for each request, built on the W3C trace context the core carries ([ADR 0059](0059-the-core-carries-w3c-trace-context-and-records-no-span.md)). It depends on `go.opentelemetry.io/otel` and `go.opentelemetry.io/otel/trace` at **v1.47.0** (released 2026-10-02), pinned in the module's `go.mod`; the SDK that samples and exports is the application's, given as `TracerProvider` (the global one when nil). Decided and built on 2026-11-01, milestone 3 wave 2 (`modules/otel/otel.go`, `otel_test.go`).

```go
app := bites.New(bites.WithObserver(otel.Tracing(otel.Config{TracerProvider: tp}), bites.AccessLog()))
```

**The rule.**

- _Start finds the parent._ `bites.TraceFrom(ctx)` when the app has `WithTraceContext`, so the module reads the header the way the core already did; otherwise `bites.ParseTraceparent` of the request's `traceparent` and its `tracestate`, so the module works without the option. A valid trace with a parent span becomes the remote parent (`trace.ContextWithRemoteSpanContext`, with the caller's flags and tracestate); none, or a trace the core began with `Begin` (no parent), makes the span a root of a new trace, and the SDK's sampler decides.
- _Start starts the server span_ (`SpanKindServer`) named for the method, with the attributes of the stable HTTP semantic conventions a sampler may want: `http.request.method` (a method outside the nine the conventions name is `_OTHER`, with `http.request.method_original`, so a client cannot grow the set), `url.path`, `url.scheme` (from `Request.Scheme`, [ADR 0025](0025-no-proxy-is-trusted-by-default.md)), `client.address` (`Request.ClientAddr`), `server.address` and `user_agent.original`. The query is not recorded, since it may carry what should not be exported. The context Start returns holds the span, so the handler's own spans (a pgx query's) are its children.
- _Start names the span to the core._ `Request.SetTrace` gives the request the span's trace id, span id and flags, the caller's span as `Parent` and the tracestate, so `TraceFrom`, `Trace.Child().Traceparent()` for an outgoing call, and the `trace_id` and `span_id` of `AccessLog` all name the span the module records ([ADR 0059](0059-the-core-carries-w3c-trace-context-and-records-no-span.md) foresaw exactly this). A no-op provider has no span of its own (it hands back the parent's context), so the request keeps the trace the core read; a sampler that drops the span still gives it a new span id with the sampled flag clear, which is what the next service should see.
- _End finishes it_, with the context its own Start returned ([ADR 0051](0051-a-request-is-observed-when-it-starts-and-when-it-has-really-ended.md)): the name becomes `METHOD /route` from `Outcome.Route` (a 404 keeps the bare method, so a scanner cannot grow the set of span names), with `http.route`, `http.response.status_code`, `http.request.body.size` and `http.response.body.size`. A 5xx sets the span's status to Error with `error.type` the status code; a panic sets it with `error.type` `panic`; a 4xx is not a server error, as the conventions say. The span carries the failure itself (added 2026-11-03, from `Outcome.Err`, `Panic` and `Stack` of [ADR 0051](0051-a-request-is-observed-when-it-starts-and-when-it-has-really-ended.md)): a 5xx with an application error records it with `RecordError` and sets the status description to its text; a panic adds the conventions' `exception` event with `exception.type`, `exception.message` and `exception.stacktrace` from the goroutine that panicked, which `RecordError` cannot give, since it would take the stack of End; a stream cut by its function's error after a 2xx head gets `error.type` `stream` and the error recorded. A 4xx error is not recorded on the span. An abandoned request ([ADR 0049](0049-errors-are-found-with-errors-as-and-timeouts-wait.md)) gets the attribute `bites.abandoned` and an event `abandoned`, and its status is left to the answer the chain chose, because a client leaving is not the server failing. A stream and an upgrade get `bites.streamed` and `bites.upgraded`. Because End runs after the last byte was written, a stream's span covers the stream and its size is what was sent.
- _Order._ Give it before `AccessLog`, so it wraps the access log; the record names the module's span in either order, since `SetTrace` runs at Start.

**The attribute keys are written out**, not taken from the `semconv` package, whose import path changes with every version of the conventions; the HTTP keys used have been stable since conventions v1.23.0.

**What it costs.** The module's, not the core's; the core's axes are unchanged. Measured by `TestTheAllocationsTheObserverAddsToARequestAreMeasured`: a GET with a `traceparent` through the in-memory server, `testing.AllocsPerRun(500)`, client side included, minus the same app without the Observer (60 allocations), on the Ryzen 7 9700X at the working tree of milestone 3 wave 2 over commit 4291b54, the same in three runs: **7 more with the no-op provider, 11 with the SDK sampling nothing, 16 with the SDK sampling and recording** to an in-memory span recorder. With the no-op provider they are the attribute slice, the client address's string and the contexts holding the remote parent and the span, and `SetTrace` is not called; the SDK adds the span itself, its attributes and `SetTrace`'s encoding. An exporter's batching is the SDK's cost on top. Memory per idle connection: none. Throughput and p99 are not measured yet; they wait for the serial run of wave 2.

**Refusals.** None at Registration: a nil `TracerProvider` is the global one, and there is no other option to get wrong. **What cannot be caught before the first request:** a global provider never set (the no-op one records nothing, which is OpenTelemetry's own default), an exporter that cannot reach its collector (the SDK's to report).

**Scenarios it was put against.**

- _The reference workload_ ([ADR 0002](0002-the-reference-workload.md)) behind an ingress that sends `traceparent`: the server span is the ingress span's child, the pgx span is the server span's child (`TestTheHandlersSpansAreChildrenOfTheServerSpanAndTraceFromNamesIt`, with and without `WithTraceContext`), the access record carries the server span's ids (`TestTheAccessLogNamesTheSpanTheModuleRecorded`), and a call to another service sends a `traceparent` whose parent is the server span.
- _An SSE feed of ten minutes_: one span from the head to the last event, with the bytes sent.
- _A hostile client_ that sends a malformed `traceparent`: a new root trace, the header ignored, as the specification says. One that sends `PURGE` to every path: `_OTHER`, and a 404's span is named `GET` or `HTTP`, never the path, so neither the method attribute nor the span names grow. One that sets the sampled flag on every request: a parent-based sampler records what it asked for, which is the specification's behaviour and the reason an edge service uses a sampler that is not parent-based.
- _A client that leaves mid-handler_: the span ends with `bites.abandoned` and no error status (`TestAClientThatLeavesMidHandlerIsRecordedAsAbandonedAndNotAsAServerError`).
- _A panic_: the span ends with the 500, status Error and `error.type` `panic`.

**What it fails at.** The error value a handler returned is not on the span: an Observer sees the status, not the error ([ADR 0051](0051-a-request-is-observed-when-it-starts-and-when-it-has-really-ended.md)), so the span says `500` and not "the database is down"; the access log and the 500's log line have it. The span starts when the head is parsed, so the time the head took to arrive is not in it. Start cannot see the route, so a sampler deciding at Start does not have `http.route`. The span's timestamps are the SDK's real clock, not the app's (a test with `bitetest`'s fake clock sees real durations on the span). There is no metric of OpenTelemetry's kind (`http.server.request.duration`): metrics are the core's Prometheus Observer ([ADR 0060](0060-metrics-are-an-observer-in-the-prometheus-text-format-labelled-by-what-the-app-bounds.md)) until an application asks for OTLP metrics. A WebSocket's messages are not spans: the span ends at the 101. The query string and headers other than the user agent are not recorded, which a deployment that wants them adds in its own Observer.

**WebSockets are not recorded by this module (decided 2026-11-04).** The module records a span per request, and a socket's span would have to stay open for hours or be cut at the 101, where the request span already ends (`Upgraded`). Counting sockets is a metric, and this module has no `metric` API in it: the OpenTelemetry metrics API is a second dependency and a second provider to configure, which is its own decision (a metrics Observer for OpenTelemetry, with the HTTP families, on the roadmap of this module), not a corner of this one. `Metrics` of the core records the socket families ([ADR 0051](0051-a-request-is-observed-when-it-starts-and-when-it-has-really-ended.md), [ADR 0060](0060-metrics-are-an-observer-in-the-prometheus-text-format-labelled-by-what-the-app-bounds.md)); a `SocketObserver` of an application can emit them to OpenTelemetry meanwhile.

**What was rejected.** The OpenTelemetry API in the core: a third-party dependency for every application ([ADR 0006](0006-no-third-party-dependency-in-the-core.md)). A middleware instead of an Observer: it would end the span before a stream's function runs and would not see a panic ([ADR 0051](0051-a-request-is-observed-when-it-starts-and-when-it-has-really-ended.md)). OpenTelemetry's own propagator to read the header: the core already parsed it ([ADR 0059](0059-the-core-carries-w3c-trace-context-and-records-no-span.md)), and two parsers could disagree about a malformed one; without `WithTraceContext` the core's exported `ParseTraceparent` is the same parser. Wrapping `otelhttp`: it needs `net/http`'s request and writer, which the core never has. Setting the span's status to Error for a 4xx or an abandoned request: the conventions say a server's 4xx is the client's, and counting client disconnects as errors would page an operator for a client's network. Naming the span with the path when no route matched: unbounded names.
