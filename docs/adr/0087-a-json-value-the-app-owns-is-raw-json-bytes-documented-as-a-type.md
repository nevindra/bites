# A JSON value the application owns is a RawJSON: bytes on the wire and in the handler, a type in the document

**A `json.RawMessage` accepts `null`, and a member whose JSON the application owns but does not decode is a `bites.RawJSON[T]`: read and written as bytes, described in the API document as `T`.** Athena typed a Suggested Cell's patch of Style fields as a `json.RawMessage`, because the editor owns its keys. When a Cell proposed no style the natural answer was `"style": null`, and the decoder refused it with `must not be null`; and the document said `{}`, so the generated frontend type was `unknown` and the shape lived in prose. Two defects, one decision.

**Decision.**

- **`json.RawMessage` and `jsontext.Value` accept `null` like any raw value.** They mean "any JSON", and `null` is JSON. The member then holds the four bytes `null`, which is what `encoding/json` does for a `RawMessage` (its `UnmarshalJSON` is called with `null`), and the encoder writes the same bytes back, so a request and its echo are identical. A member that is absent, or a nil one in an Output, is `nil`, and the encoder writes `null` for it (as `encoding/json` does). The document needs no change: `{}` already admits `null`. Every other type keeps `must not be null` ([ADR 0041](0041-presence-is-a-type.md)); only a type that means "any JSON" is the exception, and the exception is a flag of the plan's node for exactly these types.
- **`bites.RawJSON[T]` is a struct with one field, `JSON json.RawMessage`.** It reads and writes through its own `UnmarshalJSON` and `MarshalJSON`, so the codec's delegate path handles it with no new decoding machinery: `JSON` holds a copy of the bytes exactly as they arrived (nothing pooled reaches the handler, [ADR 0008](0008-no-pooled-object-reaches-the-user.md)), `null` included, and an empty `JSON` is written as `null`. `T` is only a type argument: it decides the schema and is never checked against the bytes. The wire name of the member and the rules of presence are the field's, so `Opt[RawJSON[T]]` is a member that may be left out and `Null[RawJSON[T]]` one where `null` is the Null's (and `IsNull` is true) and not bytes.
- **The document describes it as `T`, nullable, in a request and a response.** A struct `T` is a component and the member is `anyOf: [$ref, {type: null}]`; a list or scalar `T` is `type: [array, null]`. It is nullable in both directions because the decoder takes `null` for it in both, unlike the `Nullable` of [ADR 0076](0076-a-type-that-writes-its-own-json-is-described-by-a-registration-or-refused.md), which a request cannot use. The request schema of `T` is the request one (`additionalProperties: false`, its constraints) although the server does not check the bytes: the document states what a client should send and the server stays as lenient as the bytes, the same way a registered `WithJSONSchema` states and does not enforce. A handler that wants the check decodes `JSON` into `T` itself.
- **`T` is refused at Registration when it cannot be a shape**: an interface (`RawJSON[any]` has no shape, `json.RawMessage` is the spelling of "any JSON"), a pointer (null is already accepted, so name the type itself), `json.RawMessage`, `jsontext.Value` or another `RawJSON` (free-form, so the document would say nothing more), and any type the codec would refuse as a field in that direction (a channel, a type with its own JSON methods and no registration). The refusal names the route, the field and what to write instead; its rows are in the refusal table.
- **It works wherever a JSON member does**: in an Input Body, an Output, a list, a map, an `Opt`, a `Null`, a Topic payload and a WebSocket message. A whole body or message that is a `RawJSON` is not the use it is for: a body that should be bytes is `Raw[T]` or `[]byte` ([ADR 0044](0044-the-body-type-decides-how-a-body-is-read.md)).

**The name.** `Raw[T]` already exists and means a request Body that keeps the exact bytes beside the decoded `T` for a webhook signature ([ADR 0044](0044-the-body-type-decides-how-a-body-is-read.md)); reusing it for a member would give one name two meanings, so the new type is `RawJSON`: raw JSON, as `json.RawMessage` is, with a type. They do different jobs and are not two spellings of one: `Raw[T]` decodes `T` and keeps the bytes beside it, a body only; `RawJSON[T]` never decodes `T` and is a member.

**Cost.** The axes of [ADR 0003](0003-the-trade-budget.md) do not move: `RawJSON` takes the delegate path a `json.RawMessage` already takes (one copy of the member's bytes, as before), the `null` exception is a boolean read when the member is `null`, and the compile-time check of `T` runs at Registration. The allocations of a typed JSON request and the memory of an idle connection are unchanged.

**What was rejected.**

- **Reusing `Raw[T]` for a member.** It decodes `T` and is refused outside a body or a message; making it also a lazy member would give the name two meanings, and an agent that read `Raw[T]` in a body would assume the member keeps and decodes.
- **A `bites.Schema` hint on the field, or a struct tag (`bites:"schema=..."`).** A tag is a string the compiler does not check and the codec reads only `json`; a hint would be a second way of declaring a shape beside the types. `RawJSON[T]` is the type the document is built from, so a rename of `T` follows into the document, and `go vet` and the compiler check it.
- **`WithJSONSchema[json.RawMessage]` per type.** The shape belongs to a member, not to the type: one application has a style patch and a batch of operations, both `json.RawMessage`. It is also refused by [ADR 0076](0076-a-type-that-writes-its-own-json-is-described-by-a-registration-or-refused.md).
- **Telling an application to use `Null[json.RawMessage]` or `Opt`.** It is the workaround Athena used: it changes the Go type for a value that already is "any JSON", and `Null` documents `unknown`.
- **Holding no bytes for `null` (a nil `RawMessage`).** A member sent as `null` could not be told from a member absent from a request, and `encoding/json` stores the bytes; the bytes also write back unchanged.
- **Decoding `T` and failing on a mismatch.** That is `T` as a field, and it needs the keys to be the application's. A member the application cannot decode is the reason for `RawJSON`.
